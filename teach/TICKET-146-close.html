Cierre UPONE-1769: cableado de tributación (3 agregados de schema)

TL;DR. Se dejaron cableados 3 agregados de schema aditivos y nullable en curriculum-mapping (mod-only): contributionPercentage (string) e índice de grupo en CompetencyAlignment, e isRepresentative (boolean) en CompetencyNodeDevelopmentLevel. Migración limpia (2 ADD COLUMN + 1 CREATE INDEX), suite verde, PR #31 abierto contra develop. Sin lógica que consuma los campos (eso es follow-up UPONE-1770).

Qué se hizo

  • contributionPercentage en CompetencyAlignment: string, nullable. String a propósito (decisión D-imp-1 del mod) para no truncar decimales.
  • Índice de grupo (planId, competencyNodeId, developmentLevelId): no único, aditivo; conserva el índice individual de planId.
  • isRepresentative en CompetencyNodeDevelopmentLevel: boolean, nullable. Objeto reusado.
  • i18n en es/en/pt, test nuevo con casos concretos, y doc de referencia del objeto actualizada.

Cómo se verificó

Suite del mod: 2303 tests verdes (+10 nuevos que prueban nullable, decimal preservado en string, true/false sin colapsar a null, y tripleta duplicada permitida por índice no único). Typecheck y build de storybook OK. Migración generada y aplicada sin drift: exactamente 2 ADD COLUMN nullable + 1 CREATE INDEX, sin drops ni renames; el CRUD de tributación de UPONE-1756 siguió verde. Review de kn-dredd: aprobable; su única observación (doc de referencia contradecía el campo) se corrigió en el commit 4c6b815.

Decisiones

  • Tipo string (no number) para contributionPercentage, por D-imp-1, para preservar decimales.
  • Punto de partida: develop con UPONE-1756 ya mergeado (PR #29), rama propia UPONE-1769.
  • Naming del FK de Matrix: quedó developmentLevelId apuntando al Scheme; coexiste con el de CompetencyAlignment que apunta a un Level. No se usó developmentLevelSchemeId.
  • Queda abierta (PO/lead): plegar estos agregados dentro de 1756 vs mantener 1769 como ticket propio.

Aprendizajes

  • Follow-up UPONE-1770: la escritura gobernada (*Validated) todavía no incluye contributionPercentage en WRITABLE_FIELDS; hoy es solo schema y se descarta en silencio si un cliente lo manda. Cablearlo al reparto de pesos allí.
  • Reset de la DB dev: requiere reseed de UPU + UP1_SEED_RESEED=true npm run sync:layouts para restaurar el acceso de Admin/Consultor a cd/cm (el profileRoleMapping tiene gate de una sola corrida).
