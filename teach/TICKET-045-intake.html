HU-11 — Pestaña "Versiones" en el RecordDetail de Activity

Una entidad Activity (el "Programa de asignatura" del modulo curriculum-design) puede tener varias versiones a lo largo del tiempo. Hoy, estando parado en la ficha de una version, no hay forma de ver las demas ni saltar entre ellas. Este caso agrega una pestaña "Versiones" a esa ficha (el RecordDetail, la vista de detalle de un registro) que lista las versiones del Activity y permite abrir la ficha de cualquiera de ellas. El ticket nacio como explore porque no se sabia si la UI requeria construir un componente nuevo en la libreria de layout o si bastaba con configuracion; la Fase 0 (discovery) ya resolvio esa duda y aqui empieza la implementacion.

TL;DR — Que hay: el RecordDetail de Activity ya renderiza sub-listas config-driven via el primitivo record-list (la seccion "Historial" lo usa hoy). Que se hara: agregar una pestaña "Versiones" en default_Activity_view.json que lista las otras versiones del mismo Activity y deja abrir cada una; mas las traducciones es/en/pt. Por que: el consultor necesita navegar el historial de versiones desde el detalle, y el primitivo existente lo permite con solo JSON (~0.5 SP), sin tocar el core de layout.

Conceptos clave (las bases)

Antes de tocar el JSON conviene entender cuatro piezas del dominio. Las dos primeras son del motor de layout (como se construye una ficha), las dos ultimas son del versionamiento de Activity (de donde salen los datos de la lista). Sin estas, el shape del JSON parece arbitrario.

RecordDetail (tabs)

La vista de detalle de un registro, renderizada por layout/src/layouts/RecordDetail.vue. Su contenido se declara en un JSON de layout; en Activity ese JSON organiza el detalle en tabs (General, Modalidades, …, Historial). La nueva "Versiones" sera una tab mas, no una seccion colapsable suelta.

record-list (primitivo)

Tipo de elemento del RecordDetail (type: "record-list") que renderiza una sub-tabla de registros relacionados, 100% config-driven: declaras objectName + columnas + filtro y el motor arma la lista. La tab "Historial" ya lo usa sobre ChangeLog — es el precedente directo.

Cadena de versiones

Cada version de un Activity es un registro Activity independiente con su propio id. Todas las versiones de un mismo programa comparten un campo de enlace (linkageField) que las agrupa. Filtrar Activity por ese campo da exactamente "las hermanas" de la version actual.

getVersionChain (HU-5)

Query de API (TICKET-040) que devuelve la cadena de versiones de un objeto. Era la fuente prevista para esta lista, pero el discovery mostro que record-list consume objectName+filtro, no un query custom. Conclusion: HU-5 ya no bloquea esta UI; sigue valiendo para consumidores de API.

Que pasa al clickear una version

El comportamiento exacto del click es el corazon del alcance acordado, asi que conviene verlo antes de escribir el JSON. En A-lite el unico elemento clickeable es el nombre de la version (la columna nameField). Al clickearlo, TableCell emite openRecordDetail y RecordList.handleOpenRecordDetail (layout/src/layouts/RecordList.vue:3943) navega — en route-mode — a la ficha de esa version. No es un panel maestro-detalle que intercambie datos sin salir de la pantalla; es una navegacion a la ficha completa de la version elegida.

Q&A de estudio

¿Por que "Versiones" es una pestaña y no una seccion colapsable, si la Jira dice "colapsable"?
Porque el default_Activity_view.json de Activity organiza el detalle en tabs (ver linea 17 del JSON). Todo elemento del detalle vive dentro de una tab. La forma natural y consistente con el resto del view es agregar una tab "Versiones", no una seccion suelta.
¿De donde sale la lista de versiones si no usamos getVersionChain?
De un record-list sobre el propio objeto Activity, filtrado por el campo de enlace (linkageField) que comparten todas las versiones de un mismo programa. El motor de layout resuelve la lista con objectName+filtro; no necesita un query custom.
Si clickeo una version, ¿cambian los datos de la pestaña actual o me muevo de ficha?
Te mueves de ficha: navegas al RecordDetail completo de la version elegida (su propio id), con todas sus pestañas. El intercambio de datos "in-place" sin salir de la pantalla es el panel maestro-detalle, que esta diferido a SP4 (Backlog B-2).
¿Por que el estado va como texto y no como badge de color?
Porque record-list no soporta hoy una columna type: "badge" de forma declarativa (los badges existen en cards, no en tablas). Agregarlo implica tocar el core de layout, asi que se difirio a SP4 como mejora cosmetica no bloqueante.
