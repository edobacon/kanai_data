La historia del caso

Las primeras 6 fluyeron y se verificaron contra UPU real. Lessons learned

L8 — Backticks en comentarios `.schema.graphql` crashean el server. El SDL se envuelve en gql`...` al generar `mods.js`; un backtick en un comentario GraphQL termina el template literal → SyntaxError → object-manager no levanta. `sync:logic` genera el archivo pero no lo ejecuta; solo el server lo cachea. Convención: schemas del mod sin backticks en comentarios.
L6 — El codegen lowercasea las relaciones singulares de FK. `currentStatusId` → relación `currentstatus` (no `currentStatus`). `version-from-source.js` (UPONE-1209) usaba el casing camelCase → crear-v2 nunca funcionó contra DB real. Impacto acotado (único offender; getVersionChain usa el FK escalar). Al hacer `include`/acceso a una relación, verificá el nombre real en el schema generado, no asumas camelCase.
L7 — El `cloneMap` es `oldId → {newId, type}`, no `oldId → newId`. El unit test mockeó el shape equivocado (string) y pasó; el E2E vivo expuso el objeto real. Los mocks deben replicar el shape exacto del productor (`buildRemapAPI.toObject`), o el test da falso verde.
Patrón limpio reusable — exponer `_cloneMap` en el payload del evento `:create` (mismo patrón `_`-prefijo transient que `_createdVia`) es genérico: cualquier mod que versione un objeto con hijos polimórficos lo consume vía su flow, sin código core por-mod. Es la base del derived genérico de SP4.

Q&A de cierre

¿Por qué el E2E vivo encontró bugs que los unit tests no?
Los unit tests mockean Prisma: no validan nombres de relación en `include` (L6), no ejecutan el typedef generado (L8), y pueden mockear el shape equivocado del cloneMap (L7). El runtime real (Prisma client generado + server + evento) es el único que ejerce esas superficies. Para features runtime-dependent, el E2E vivo es obligatorio.
¿Qué queda fuera de scope (SP4)?
El derived genérico en el codegen — remap declarativo de FKs internas entre hijos clonados sin hook por-mod. El hook de HU-8b es el path acotado de SP3; SP4 lo generaliza. Ticket agendado en el backlog.
¿El auto-trigger n8n del remap quedó validado?
El handler (`remapVersionedCurricularLinks`) está validado vivo (2 links remapeados en DB real) y el flow `versioning-remap` deployado. El auto-trigger Redis→n8n→mutation es el mismo patrón router que audit-capture (DEC-LOCAL-02); su activación es ops de n8n. El handler que invoca ya está probado.
