La decisión que importó

Contexto

Cómo clonar un objeto con un campo único (code) sin dejar registros a medias ni códigos colisionados.

Decisión (DEC-LOCAL-01)

Reusar prefilledModal + uniqueFields:["code"] — el modal abre con el code vacío y crea solo al guardar; la DB valida.

Resultado

Cero código nuevo. Cancelar no deja nada; un code repetido se rechaza con error limpio. Descartado: resolver server-side (innecesario sin hijos).

Lección reusable (L2)

✓ Hay DOS mecanismos de clone en una rowAction — el correcto depende de si el objeto tiene campo único.
  • prefillFromCurrent: true (sin cloneStrategy) → crea inmediato y redirige. Válido SOLO si el objeto NO tiene campo único (ej. BibliographyReference).
  • cloneStrategy: "prefilledModal" + uniqueFields → modal prellenado salvo los únicos (vacíos), crea al guardar. Requerido cuando hay campo único (ej. academicProgram, modality).
⚠ Copiar el analog correcto. Tomar BibliographyReference como molde (porque "también es plano") habría dado el mecanismo equivocado. El analog correcto fue modality (también con campo único). Fuente de verdad: el tipo RowAction en layout/src/types/recordlist.ts:224-239, que documenta cuándo usar cada uno.

¿Por qué se verificó el @@unique en la DB si ya estaba declarado en el JSON?
Por el gotcha TICKET-054: en up1 el enforcement declarativo (uniqueScopedBy) falla en silencio si el sync no creó la @@unique real. "Declarado" ≠ "aplicado". Se inspeccionó pg_indexes y luego TC-3 lo cerró end-to-end (P2002 sobre target ["institutionId","code"]).
El sync salió con exit 1 (drift). ¿Por qué no bloqueó el ticket?
Los 21 errores de drift son ajenos: 14 de uengagement-up1 (drift real de otro dueño) y 7 de curriculum-design/Modality (falso positivo del detector, ticket-048 B-1). El drift-check es una fase diagnóstica que sale 1 pero no revierte los upserts — se verificó en DB que capability + rowAction quedaron aplicados.
¿Por qué no se hizo mutation testing?
El diff es config pura (JSON), sin lógica ejecutable que mutar → daría score 100 trivial. La dimensión testing se cubrió con TC-2/TC-3 (enforcement real) + 93/93 tests declarativos. Mutation sí aplica a TICKET-065 (resolver de unicidad por linaje) — anotado en su Triage.
