TICKET-077 · curriculum-design · cierre · 2026-06-22

El override de tenant que sobrevivió a la migración al mod

Editar / clonar / versionar un Curriculum tipo Plan fallaba. La premisa del ticket (casteo FK mod-only + revert coordinado) era un mis-diagnóstico heredado. La causa real era de ubicación de fuente, no de código.

La lección central

Cuando un objeto pasa de tenant-specific a definido en un mod, puede quedar un override viejo en object-manager/objects/tenants/<T>/Base/<obj>.json. El codegen lo lee con last-wins (tenant > business) y registra el objeto contra el modelo VIEJO. El mod queda sombreado.
Un reset-tenant NO lo arregla: regenera el registry desde el mismo source committeado stale. Y el sync no regenera los tenant Base (son artefactos de migración congelados). Por eso el reset del dev no movía la aguja.

El fix (opción aprobada por el dev)

git rm object-manager/objects/tenants/UPU/Base/curriculum.json
→ Curriculum cae al business/Base mod-derived (modelo reducido + versioning), igual que AcademicProgram (que nunca tuvo override). El resolver de TICKET-074 (thin adapter) no se tocó: era correcto, solo dependía de un registry correcto.
Verificado: registry correcto (totalCredits isBaseField=false, totalPeriods/periodType presentes, versioningConfig poblado) + los 3 flujos OK en la suite. S3: revertido 98590c0 (fix mal ubicado en core, hoy dead code — 0 objetos at-risk, 542/542).

Qué llevarse

  • Capturá el error CRUDO, no el friendly. El friendly ("Valor inválido") es client-side; el Prisma real (Unknown argument vs Invalid value) distingue mis-bucketing de coerción — y desarmó dos mis-diagnósticos previos (074/076 culparon a casteo FK / coerción).
  • El output de un sub-agente es self-report. El agente infirió "clone funciona"; el repro empírico mostró que clone también fallaba. Verificar (DET-33).
  • Verificá contra el git/source, no contra el artefacto generado. El registry (DB) lagea; la verdad está en los objects/ committeados. Y ojo con objectToFileMap: getObjectToFileMap('<T>')['<Obj>'] te dice qué archivo gana.
  • Cuestioná la premisa del ticket. "mod-only + revert coordinado" era arrastre de un mis-diagnóstico; el diagnóstico real lo reescribió.
