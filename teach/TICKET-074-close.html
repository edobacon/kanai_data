Lecciones

¿Por qué el versionado de curriculum crasheaba y cómo se generalizó?
prepareVersionData incluía currentstatus/workflow incondicionalmente. Curriculum no las modela. Se gateó todo a needsWorkflow = !!initialStateField: presente (activity) → path workflow idéntico; ausente (curriculum/academicProgram) → se salta y el estado lo da el static_default. Generaliza la plataforma sin parchear caso por caso.
¿Por qué el fix de versionado NO cerró "versionar curriculum end-to-end"?
Destrabó el crash, pero la v2 nace sin su extensión rt__Plan__curriculum (frente #2 / B1): el path de versión usa objectType=Curriculum base; con el alias rt__ el guard L40 lo rechaza (path RT no-atómico, TICKET-056). Es trabajo de core aparte.
¿Cuál fue el error de proceso y cómo lo corrigió el dev?
Para arreglar la navegación toqué RecordDetail.vue (layout-engine core). El dev lo atajó: debe ser mod-only. Se revirtió y se intentó la vía mod (returnsScalar:true + retorno escalar). Lección: la navegación post-submit de un customEndpoint full-page la gobierna la app suite, NO se arregla tocando core layout desde este ticket — y cuando no alcanza mod-only, se difiere (B2) en vez de invadir core.
¿Qué quedó realmente entregado y verificado?
Versionado sin workflow (E2E vivo), fix institutionId (E2E + unit + 542 resolvers sin regresión), split RT en update (guardado verificado por el dev). Diferido: B1 (RT atómico en versión) y B2 (navegación suite-side). El push de los commits quedó pendiente de aprobación humana (super autopilot).
