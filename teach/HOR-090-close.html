Lessons learned

Tailwind v3 + var-colors: la opacidad no se genera
bg-accent/5, border-accent/60, ring-accent/30 NO generan CSS en v3 cuando el color es var(--x) hex. Usar flat o -bg. Apareció 2 veces (la 2da: el perl olvidó surface). Para habilitar opacidad de verdad: tokens como canales RGB + rgb(var(--x) / <alpha-value>) → B4.
El config de Tailwind no hace HMR — el "se ve mal" era eso
El dev vio el board sin colores: tokens.css HMR'eó (fondo navy) pero las utilities nuevas del tailwind.config.ts necesitaban restart del dev server. El build de producción SÍ las tenía. Los componentes con style="var(--color-*)" inline (la tabla de sessions) renderizaban bien sin restart — patrón robusto.
"Build verde" no es validación visual
El build pasaba con utilities ausentes (Tailwind ignora clases desconocidas; tokens inexistentes se pierden silenciosos). El gate real de un ticket de diseño es el ojo del dev (S2.T4) — el dev atrapó lo que el build no. Y el reviewer aislado atrapó el commit faltante + los surface omitidos.
Header: scroll vs compactar
Primera respuesta al overflow fue scroll horizontal; el dev pidió compactar. Solución: nav ícono+count, label solo en el activo + tooltip. Más angosto y más "plataforma".
