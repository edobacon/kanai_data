Crear bloque electivo desde edición (paridad add↔edit) + fix doble "+"

Follow-up de MC-06 (UPONE-1349). Dos detalles del componente CurriculumMesh: (1) al editar una asignatura electiva, el selector de bloque solo dejaba elegir existentes — no crear uno nuevo, cosa que el modal de alta sí permite; (2) el botón "+ Asignatura" muestra dos signos "+". Este documento orienta sobre las bases (cómo se crea un bloque hoy), el entorno (dónde vive la asimetría) y el plan.

TL;DR — Fix de reuso: la capacidad "crear bloque" ya está extraída en blockSelect.logic (resolveBlockSelection + BLOCK_NEW_SENTINEL) y la mutación CREATE_REQUIREMENT (rt__Group__requirement) ya existe — solo el modal de edición no las consumía. El doble "+" es porque el Button trae icon="bi bi-plus-lg" y la etiqueta i18n además empieza con "+".
glosario cómo se crea un bloque la asimetría plan

Glosario

bloque electivo

Un requirement de recordType Group (rt__Group__requirement) dueño del plan. Agrupa asignaturas electivas; el planEntry electivo apunta a él por blockId.

blockSelect.logic

Módulo puro: resolveBlockSelection(selectValue, newName, options) → interpreta '' / __new__ / id existente. Ya usado por el alta; reusable.

CREATE_REQUIREMENT

Mutación createInstance con objectType rt__Group__requirement + buildBlockPayload. Crea el bloque; devuelve su id.

seam modal ↔ Element

El modal es presentacional (emite eventos, no muta); el Element ejecuta las mutaciones. El alta lo hace en createElectivaEntries.

Cómo crea un bloque el ALTA (lo que la edición no hacía)

flowchart TD
  S[select bloque] -->|__new__ + nombre| R[resolveBlockSelection\nisNew:true]
  S -->|id existente| E[isNew:false]
  R --> C[Element createElectivaEntries\nCREATE_REQUIREMENT rt__Group__requirement]
  C --> ID[nuevo blockId]
  ID --> P[planEntry con blockId]
  E --> P

El modal de edición tenía un <select> plano (solo existentes) atado a form.blockId, sin la opción __new__ ni el input — nunca importaba blockSelect.logic.
