Flujo por session — el camino recorrido

S1 · Input + Switch

Se instalaron las deps Radix (react-switch, react-label) y se construyeron los dos átomos más simples como calibración del patrón. Input nació con un footgun (`error={false}` + `variant="error"` dejaba aria/CSS inconsistentes) que el reviewer aislado detectó y se corrigió a `error === true || variant === 'error'`. Switch dejó el primer learn: Radix no togglea con `.click()` nativo en jsdom → la interacción va en la story `play()`.

S2 · Card + Dialog

Tasks paralelas (archivos disjuntos). Card es HTML puro con subcomponentes; Dialog reusó la misma primitiva Radix que el Sheet ya entregado, centrado y con focus-trap. El reviewer corrigió el tipo del ref de CardTitle (renderiza `

`, era `HTMLDivElement`).

S3 · Select + extensión Badge

Select (single) sobre react-select con estado error en el trigger. Badge se extendió con las 5 variantes semánticas; lo crítico fue el test de regresión que verifica byte-a-byte que las variantes previas siguen intactas — el reviewer confirmó la extensión como no-breaking.

S4 · FormField + FormSection

El corazón: FormField conecta RHF + zodResolver, renderiza label/error con a11y y expone mapApiErrorToField para el contrato del backend. Aquí el review adversarial pidió un test de borde (error + description simultáneos) que destapó un bug a11y real: un aria-describedby huérfano. Se fixeó la condición y se cerró con 9 tests de integración.

S5 · Cierre WP

Suite completa verde (131 jsdom + 31 storybook browser). Mutation testing (warn-first) reveló gaps de lógica en FormField que se cerraron con hardening (FormField pasó de 6→10 tests); el residual (clases Tailwind de átomos presentacionales) quedó como backlog `should`. Conocimiento generado

Decisiones (DEC-LOCAL en spec) — DEC-LOCAL-01: extender Badge (additivo, mitigado con regresión). DEC-LOCAL-02: addon-a11y en test:'todo' global (flip a 'error' rompería stories existentes — fuera de alcance). DEC-LOCAL-03: Select simple, sin Combobox/MultiSelect (sin consumidor inmediato).

Lecciones aprendidas

¿Cuál fue el mayor retorno de la inversión de proceso?
La reconciliación del intake (investigar el repo real antes de diseñar) evitó reconstruir Button/Badge/Tooltip — habría sido trabajo redundante que además violaría RULE-global-003. El alcance efectivo se recortó de 8 a 5 átomos + extensión + forms.
¿Qué aportó el reviewer aislado que la auto-revisión no habría dado?
Dos fixes reales: el footgun de Input (`error`/`variant` inconsistente) y —el más valioso— el bug a11y de FormField (aria-describedby huérfano), que surgió de un test de borde que el reviewer sugirió y que los 4 escenarios core NO cubrían. La independencia del revisor encontró lo que el ejecutor daba por bueno.
¿Cómo se interpretó el score de mutation 56.2?
Warn-first (no bloqueante). La mayoría de survivors son mutaciones de clases Tailwind en componentes presentacionales — bajo valor (aseverar cada clase es frágil, contra el espíritu de RULE-frontend-002). Los survivors de LÓGICA (FormField describedBy/mapApiErrorToField) sí se cerraron con hardening. El residual quedó como backlog `should`, no `must`.
¿Qué gotcha operativo hereda el dev?
jormat-front hornea node_modules en la imagen Docker. Las 3 deps Radix nuevas (react-select/switch/label) están en package.json y verdes en host, pero el dev debe correr ./run.sh build para que su contenedor las vea — si no, dará "Module not found" en runtime.
