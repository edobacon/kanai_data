Conceptos clave (las bases)

Step split / lazy-load

Partir un step grande en un indice liviano + sub-archivos por fase. El LLM carga solo la fase activa via dkc_get_step_phase, no el monolitico. Patron introducido en HOR-059 para request-execute/request-close.

v1 legacy en teach

Los steps teach-intake.md/teach-close.md tienen bloques <details>v1 LEGACY</details> (formato markdown viejo) que solo aplican a tickets pre-2026-05-29. Para tickets nuevos son dead code que igual se inyecta.

Scoping de rules

Un step puede declarar reads: rules/{module}/ (solo el modulo del ticket) o rules/ (el directorio entero). En up1 eso es la diferencia entre ~5 archivos y 115 (272KB).

dkc_get_step_phase

Tool MCP que retorna solo la fase pedida de un step split; si el step no esta split, retorna el monolitico sin error (auto-detect). Es lo que hace el split transparente para el resto del flujo.

Como carga hoy vs el patron a aplicar

Hoy — monolitico

El step entero (ej. teach-intake.md, 525 lineas) se inyecta de una al leerlo.

+ Simple, todo en un archivo

− Carga fases que no se usan en este turno + dead code v1

Split lazy-load (HOR-059)

Indice liviano + sub-archivos por fase; se carga solo la fase activa via dkc_get_step_phase.

+ Menos tokens/turno; el resto se carga on-demand

− Mas archivos; toca el workflow engine (requiere verificar el auto-detect)
