## Criterios de aceptación
- [ ] Dado un clon limpio con el Node de `.nvmrc`, cuando se ejecutan `corepack enable` y
  `pnpm install --frozen-lockfile` en la raíz, entonces terminan con código 0 y `git status` queda
  limpio.
- [ ] Dado `server/` copiado solo a otra ubicación, cuando se ejecuta
  `pnpm install --frozen-lockfile` dentro de esa copia, entonces instala con su propio lockfile sin
  leer nada fuera de `server/` (DEC-205).
- [ ] Dado `pnpm-workspace.yaml`, cuando se inspecciona, entonces no incluye `server/`, y
  `pnpm install` en la raíz no crea ni modifica `server/pnpm-lock.yaml` (DEC-230).
- [ ] Dado un PR que modifica `server/contract/openapi.yaml`, `server/prisma/migrations/**` o
  `.github/workflows/**`, cuando se abre, entonces GitHub solicita la revisión del owner declarado
  en `CODEOWNERS`.
- [ ] Dado el repositorio en GitHub, cuando se crea un issue, entonces se ofrecen los seis
  formularios con los campos del doc 48 (secciones 2 a 7), incluido el handoff a Kanai.
- [ ] Dado un PR nuevo, cuando se abre, entonces la descripción precarga la plantilla con
  `docs-impact` (`required`, `generated-only` o `none`) y la sección de QA humana.
- [ ] Dado un archivo `.env` o `.env.local` en cualquier carpeta, cuando se ejecuta
  `git add -A --dry-run`, entonces el archivo no aparece.
- [ ] Dado el contenido documental previo, cuando se integra la historia, entonces
  `check_citas.py`, `check_cobertura.py`, los `build_*.py --check`, `unittest` y `check_backlog.py`
  siguen pasando localmente.

## Adendas al request

### Adenda 1 - 2026-09-26 - dev

Adaptar el flujo de colaboración a un proyecto mantenido por una sola persona: conservar pull request obligatorio y CODEOWNERS informativo con @edobacon para las áreas críticas; no exigir aprobación humana ni revisión distinta del autor; permitir el merge únicamente con checks obligatorios verdes, conversaciones resueltas y acción manual de squash merge. No habilitar auto-merge. Sustituir los criterios que esperaban una solicitud de revisión al propio autor por validaciones de sintaxis y cobertura de rutas de CODEOWNERS. Reflejar esta regla en CONTRIBUTING.md y en la documentación canónica de estrategia CI/CD; la configuración efectiva de protección de main sigue perteneciendo a HU-00-09.

**Motivo**: GitHub no puede solicitar al autor que revise su propio PR y una aprobación distinta bloquearía permanentemente el flujo de un repositorio con un solo desarrollador.
