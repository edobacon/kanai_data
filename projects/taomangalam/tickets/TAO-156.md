> **ID estable:** `HU-00-08` · **Estado:** `Ready` · **Orden recomendado:** `6` · **Puntos publicados:** `5`

## Objetivo
Resultado: `server/contract/openapi.yaml` gobierna servidor y app mediante lint Spectral,
comparación con `openapi-diff` contra `main`, tipos TypeScript y cliente Dart `dart-dio`
generados, validación de peticiones en tiempo de ejecución y gate de codegen sin diff. Consumidor:
HU-00-09 (job `contract`), HU-00-13 (`pnpm generate`) y toda épica que implementa operaciones.

## Alcance
**Incluye**
- `server/contract/.spectral.yaml` versionado con el ruleset base de OpenAPI y reglas del proyecto
  tomadas de las convenciones del contrato: `operationId` presente y único, `x-capacidad` y
  `x-requiere-cuenta` en cada operación y errores `application/problem+json` (DEC-227).
- `openapi-diff` con `--fail-on-incompatible` contra la versión de `main` (tecnologia/17 §5).
- `openapi-generator` con generador `dart-dio` hacia `server/contract/generated/`, consumido por
  `app/` como único cliente generado (tecnologia/06).
- Tipos TypeScript generados con `openapi-typescript` en `server/contract/generated/` y usados por
  los handlers de salud (DEC-230).
- `express-openapi-validator` sobre las peticiones (DEC-162, tecnologia/06): una petición que
  incumple el contrato responde 400 `validacion_fallida` en `problem+json`.
- `pnpm generate` regenera todo; el gate ejecuta `git diff --exit-code` tras regenerar.
- Versiones de generadores fijadas en lockfiles o configuración (tecnologia/17 §3).
- Prueba de contrato mínima: las respuestas de salud validan contra `Salud` y el modelo Dart
  generado deserializa una respuesta real de `GET /health/live`.

**No incluye**
- Contrato de eventos Socket.IO: fuera de EP-00.
- Render Redocly del contrato: HU-00-16.
- Implementación de operaciones de negocio: épicas funcionales.

## Criterios de aceptación
- [ ] Dado el contrato vigente, cuando se ejecuta Spectral con el ruleset, entonces termina sin
  errores; si hay hallazgos, se corrigen en el contrato en el mismo PR o se documenta la excepción
  en el ruleset con su motivo.
- [ ] Dada una operación sin `x-capacidad`, cuando corre el lint, entonces falla.
- [ ] Dado un PR que elimina una propiedad requerida de una respuesta, cuando corre `openapi-diff`,
  entonces informa un cambio incompatible y el paso falla; un campo opcional nuevo pasa.
- [ ] Dado un clon limpio, cuando se ejecuta `pnpm generate`, entonces `git diff --exit-code`
  termina con código 0.
- [ ] Dado un archivo de `server/contract/generated/` editado a mano, cuando corre el gate, entonces
  falla.
- [ ] Dado un campo nuevo en el esquema `Salud`, cuando se ejecuta `pnpm generate`, entonces
  `openapi-typescript` actualiza los tipos TypeScript y un handler que omite el campo requerido no
  compila con `tsc --noEmit`.
- [ ] Dada `GET /v1/version?plataforma=windows` (operación documentada, aún sin handler), cuando
  llega al servidor, entonces responde 400 `problem+json` con `codigo: validacion_fallida` y
  `requestId`.
- [ ] Dado el paquete Dart generado, cuando se ejecuta `dart analyze` sobre él, entonces compila sin
  errores (puede excluir reglas de estilo, tecnologia/17 §4).
