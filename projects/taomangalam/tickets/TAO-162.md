## Objetivo
Resultado: `app/widgetbook/` es una app Flutter separada que muestra componentes y estados con
fixtures compartidas con las pruebas, y su build web estático se publica como artifact en cada PR
con UI. Consumidor: EP-01 y las épicas funcionales que agregan componentes y vistas, y los
revisores de PR (DEC-193).

## Alcance
**Incluye**
- App `app/widgetbook/` con su `pubspec.yaml`, dependiente del paquete de la app, con `widgetbook`
  y su generador de anotaciones (tecnologia/06).
- Controles de dispositivo teléfono y tablet, orientaciones admitidas, escala de texto normal y
  aumentada, tema claro con el selector técnico oscuro oculto (DEC-196) y movimiento normal y
  reducido.
- Fixtures en una única ubicación importable por widget tests, golden tests y el catálogo.
- Un caso de uso de ejemplo sobre el `design_system` de HU-00-02 para validar la tubería.
- `pnpm dev:catalog` (tecnologia/18) y `pnpm docs:catalog` (tecnologia/19) abren el mismo catálogo
  con hot reload.
- Build web estático del catálogo en los PR que cambian `app/`, publicado como artifact, sin
  secretos y sin Widgetbook Cloud.

**No incluye**
- Componentes, vistas y golden tests reales: EP-01 y épicas funcionales.
- Hosting de previews efímeras por PR: sin decidir (tecnologia/18 §14).

## Criterios de aceptación
- [ ] Dado `pnpm dev:catalog`, cuando se abre, entonces muestra el caso de uso de ejemplo y un
  cambio en el widget se refleja con hot reload.
- [ ] Dado el caso de uso, cuando se cambian dispositivo, escala de texto y movimiento, entonces se
  ve en teléfono y tablet, con texto aumentado y con movimiento reducido.
- [ ] Dado el catálogo, cuando se revisan sus controles, entonces no hay selector de tema oscuro
  visible.
- [ ] Dado un PR que cambia `app/lib/`, cuando termina el workflow, entonces existe un artifact con
  el build web del catálogo que se abre servido localmente.
- [ ] Dado el build web, cuando se inspecciona, entonces no contiene archivos `.env`, tokens ni
  endpoints de ambientes.
- [ ] Dado el build de la app, cuando se ejecuta `flutter pub deps` en `app/`, entonces
  `widgetbook` no figura como dependencia de producción.
- [ ] Dada una fixture modificada, cuando se ejecutan los widget tests y se abre el catálogo,
  entonces ambos reflejan el mismo cambio.
