> **ID estable:** `HU-00-09` · **Estado:** `Ready` · **Orden recomendado:** `10` · **Puntos publicados:** `5` · **Referencia externa:** GH-11

## Objetivo
Resultado: `.github/workflows/ci-pr.yml` ejecuta en cada PR los jobs de tecnologia/17 §8 en paralelo, con PostgreSQL 18 de servicio, publica cobertura y termina en `quality-gate`, check obligatorio de `main`. Consumidor: HU-00-10 a HU-00-16 y todo PR del proyecto.

## Alcance
**Incluye**
- Jobs `metadata` (rutas, títulos, archivos prohibidos como `.env` y certificados, coherencia de lockfiles), `contract` (HU-00-08), `flutter-static`, `flutter-test` con LCOV, `backend-static` (Prettier, ESLint, `tsc --noEmit`, `dependency-cruiser`, `prisma format` y `prisma validate`), `backend-test` (Vitest con cobertura), `integration`, `build-smoke`, `security` (Trivy) y `docs`.
- `integration` con service container `postgres:18` fijado por digest, creación de los cuatro roles con `infra/postgres/init/001_roles.sql`, migraciones desde cero con el rol migrador, Supertest de salud y `pg-boss` real (DEC-198, DEC-200).
- `docs` con los gates documentales existentes: `build_fichas.py --check`, `build_manual_y_personalidad.py --check`, `build_signos.py --check`, `build_result_catalog.py --check`, `check_citas.py`, `check_cobertura.py`, `unittest discover -s tests` y `check_backlog.py` (HU-00-16 lo amplía).
- `quality-gate` que corre siempre y falla si un job requerido falló, fue cancelado o no terminó correctamente; filtros por ruta solo en jobs pesados.
- `concurrency` que cancela ejecuciones obsoletas del mismo PR, summary único y artifacts de pruebas y cobertura.
- Actions fijadas por SHA completo, `permissions` mínimos por job y PR de forks sin secretos.
- Toolchain desde los archivos versionados (FVM, `.nvmrc`, Java 17), `pnpm install --frozen-lockfile`, `flutter pub get` con lockfile y caché de pub, pnpm y Gradle por lockfile.
- Ruleset de `main`: PR obligatorio, una aprobación distinta del último autor, `CODEOWNERS`, invalidación de aprobaciones, conversaciones resueltas, `quality-gate` requerido, historia lineal con squash y sin force-push ni borrado (tecnologia/17 §2).
- Umbral de cobertura de líneas del backend en Vitest no inferior al 80 %.
- Cobertura Flutter desde el LCOV de `flutter test --coverage`, procesado con `lcov` y `diff-cover` (≥ 80 % de líneas nuevas o modificadas; DEC-230).
- Python 3.12 fijado en CI para los gates documentales (DEC-230); artifacts retenidos 30 días.
- Medición de los presupuestos de tecnologia/18 §11 informada en el summary.

**No incluye**
- `main.yml`, `nightly.yml`, CodeQL y Dependabot: HU-00-10.
- APK como artifact instalable y build iOS: HU-00-11. Widgetbook: HU-00-12.
- MkDocs y gates documentales nuevos: HU-00-16. `release.yml`: EP-17.

## Criterios de aceptación
- [ ] Dado un PR de prueba sin fallas, cuando corre `ci-pr.yml`, entonces todos los jobs aplicables y `quality-gate` quedan verdes.
- [ ] Dado un PR que rompe el formato Dart, el tipado TypeScript, la compatibilidad del contrato o una migración desde cero, cuando corre el workflow, entonces el job correspondiente y `quality-gate` quedan rojos.
- [ ] Dado un PR que solo cambia `docs/`, cuando corre el workflow, entonces los jobs pesados se omiten por filtro de ruta y `quality-gate` termina verde, no pendiente.
- [ ] Dado un segundo push al mismo PR, cuando empieza la nueva ejecución, entonces la anterior se cancela.
- [ ] Dado un PR que agrega un archivo `.env`, cuando corre `metadata`, entonces falla.
- [ ] Dado un PR que rompe una cita documental, cuando corre `docs`, entonces `check_citas.py` falla y `quality-gate` queda rojo.
- [ ] Dado el ruleset activo, cuando se intenta un push directo a `main` o fusionar un PR con `quality-gate` rojo, entonces GitHub lo rechaza.
- [ ] Dada una ejecución completa, cuando se abre el summary, entonces muestra el porcentaje de cobertura de Flutter y backend, enlaces a los LCOV y la duración de los jobs.
- [ ] Dado un PR que agrega código Dart con menos de 80 % de líneas nuevas cubiertas, cuando corre `flutter-test`, entonces `diff-cover` falla y `quality-gate` queda rojo.
- [ ] Dado el job `docs`, cuando se inspecciona su configuración, entonces usa Python 3.12 fijado y los artifacts del workflow declaran retención de 30 días.
