## Objetivo
Resultado: `app/` contiene un proyecto Flutter 3.47.2 con los sabores `development`, `staging` y
`production` aislados, configuración tipada por entorno, estructura Atomic Design más capas,
Riverpod y analyzer estricto. Consumidor: HU-00-03, HU-00-08 (cliente Dart), HU-00-12
(Widgetbook), EP-01 y EP-06.

## Alcance
**Incluye**
- Flutter 3.47.2 stable fijado con FVM y su archivo de versión versionado; Dart del propio SDK
  (tecnologia/24).
- Mínimos iOS/iPadOS 15 y Android `minSdk` 24, `compileSdk` y `targetSdk` 36; Java 17 (DEC-198).
- Sabores en Android (flavors) y en iOS (schemes y configuraciones) con identificador de
  aplicación, nombre visible e ícono secundario propios (tecnologia/18 §3).
- Configuración tipada por sabor generada desde archivos no secretos versionados, validada al
  arrancar con fallo temprano y mensaje accionable; el sabor `production` no puede apuntar a
  servicios locales.
- Estructura `app/lib/core`, `data`, `design_system/{atoms,molecules,organisms,templates}` y
  `features/<feature>/{application,presentation}` (tecnologia/05), con una pantalla inicial
  provisional sin contenido de producto.
- `flutter_riverpod` y `riverpod_generator` (DEC-158) con `riverpod_lint` y `custom_lint`.
- `analysis_options.yaml` sobre `flutter_lints` con `strict-casts`, `strict-inference`,
  `strict-raw-types` y las reglas mínimas de tecnologia/17 §4.
- Una prueba unitaria y una de widget mínimas para que `flutter test --coverage` produzca LCOV.

**No incluye**
- Tema, componentes, shell, navegación e i18n: EP-01.
- Drift, dominio y persistencia: EP-06.
- Cliente Dart generado: HU-00-08.
- Instalación conjunta de plugins nativos: HU-00-03.
- Panel DevTools interno de `development` (tecnologia/18 §9): HU-00-19.

## Criterios de aceptación
- [ ] Dado FVM instalado, cuando se ejecuta `fvm flutter --version` en `app/`, entonces informa
  Flutter 3.47.2 stable.
- [ ] Dado cada sabor, cuando se compila un APK debug con `--flavor <sabor>`, entonces se obtienen
  tres APK con identificadores distintos que se instalan a la vez en el mismo emulador y muestran
  nombres visibles distintos.
- [ ] Dado macOS con Xcode, cuando se ejecuta `flutter build ios --simulator --flavor development`,
  entonces compila sin errores.
- [ ] Dado un valor obligatorio ausente o inválido en la configuración de un sabor, cuando se
  valida la configuración al arrancar, entonces falla con un mensaje que nombra la clave, sin
  mostrar valores.
- [ ] Dado el sabor `production` con un endpoint `localhost`, `127.0.0.1`, `10.0.2.2` o IP de red
  privada, cuando se valida la configuración, entonces la validación falla.
- [ ] Dado el código base, cuando se ejecutan `dart format --output=none --set-exit-if-changed .`,
  `flutter analyze --fatal-infos --fatal-warnings` y `dart run custom_lint`, entonces terminan con
  código 0.
- [ ] Dado un `print` o una llamada dinámica agregados en `lib/`, cuando se ejecuta el analyzer,
  entonces falla.
