## Objetivo
Resultado: la validación documental de HU-00-16 se completa con el verificador de frontmatter con Ajv, el render reproducible de diagramas Mermaid a SVG, la documentación de API de Dart y TypeScript y la detección nocturna de documentos huérfanos (tecnologia/19 §7 y §10). Consumidor: todo PR con impacto documental (DEC-193) y el sitio de documentación del monorepo.

## Alcance
**Incluye**
- JSON Schema versionado del frontmatter (campos mínimos, enums de `type` y `status` por familia, fechas e IDs únicos, tecnologia/19 §4) y verificador propio con Ajv que además comprueba referencias a DEC y a vistas V-xx.
- Baseline explícita de documentos heredados: reglas completas en archivos nuevos o modificados; los heredados sin tocar no bloquean (tecnologia/19 §4 y §13).
- `@mermaid-js/mermaid-cli` con versión fijada que genera SVG desde los `.mmd`, incluido en MkDocs, con gate de diff limpio tras regenerar; los HTML de Mermaid con CDN se reemplazan por el SVG generado (tecnologia/19 §13, punto 6).
- `dart doc --dry-run` con los lints `public_member_api_docs` y `comment_references` sobre la API pública de `app/`.
- TypeDoc sobre los exports de `server/` con validación y warnings como error.
- `pnpm docs:generate`, `pnpm docs:api` (Redoc, DartDoc y TypeDoc) y `pnpm docs:diagrams` (tecnologia/19 §11), incorporados a `docs/development/commands.md`.
- Pasos nuevos en el job `docs` de `ci-pr.yml` (frontmatter, DartDoc, TypeDoc, Mermaid y regeneración sin diff) y detección de documentos huérfanos y metadata atrasada en `nightly.yml`.

**No incluye**
- MkDocs, markdownlint, Vale, cspell, Lychee y render Redocly: HU-00-16.
- Snippets ejecutables y cobertura documental de nightly: sin historia en EP-00.
- Hosting o publicación del portal: sin decisión; el sitio se entrega como artifact.
- Migración masiva de documentos heredados al schema: se migran al tocarlos (tecnologia/19 §4).

## Criterios de aceptación
- [ ] Dado un documento nuevo con `status` fuera del enum de su familia o sin `id`, cuando corre el verificador de frontmatter, entonces falla nombrando el archivo y el campo.
- [ ] Dados dos documentos con el mismo `id`, cuando corre el verificador, entonces falla listando ambos archivos.
- [ ] Dado un documento modificado que cita una DEC o una vista inexistente, cuando corre el verificador, entonces falla; un heredado en la baseline que no se modifica no bloquea.
- [ ] Dado un `.mmd` modificado sin regenerar su SVG, cuando corre `docs`, entonces el gate de regeneración falla mostrando el diff.
- [ ] Dado un miembro público de Dart sin comentario `///`, cuando corre `dart doc --dry-run` con los lints, entonces el job falla.
- [ ] Dado un export de `server/` con un enlace TSDoc inválido, cuando corre TypeDoc, entonces el job falla por warning tratado como error.
- [ ] Dado un documento de `docs/` que ningún otro documento ni la navegación enlaza, cuando corre `nightly.yml`, entonces el summary lo informa como huérfano.
- [ ] Dado un clon limpio, cuando se ejecuta `pnpm docs:generate`, entonces `git diff --exit-code` termina con código 0.
