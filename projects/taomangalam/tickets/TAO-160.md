> **ID estable:** `HU-00-13` · **Estado:** `Ready` · **Orden recomendado:** `12` · **Puntos publicados:** `3` · **Referencia externa:** GH-13

## Objetivo
Resultado: desde la raíz, `pnpm run doctor`, `pnpm run bootstrap`, `dev:services`, `dev`, `generate`, `check` y `test` dejan el entorno listo y en marcha, con configuración de editor versionada, `.env.example` documentado y acceso móvil al backend local resuelto por el comando. Consumidor: toda persona que clona el repositorio y el criterio de cierre de EP-00 (clon limpio funcionando).

## Alcance
**Incluye**
- Scripts raíz de tecnologia/18 §4, ejecutables desde cualquier subdirectorio, que muestran el comando que falla y enlazan su sección de troubleshooting.
- Los scripts de arranque se llaman `bootstrap` y `doctor` y se invocan con `pnpm run`, porque `pnpm setup` y `pnpm doctor` son comandos propios de pnpm con precedencia sobre los del `package.json` (DEC-230).
- `pnpm run doctor`: comprueba Flutter (versión de FVM), Dart, Node (`.nvmrc`), pnpm (`packageManager`), Docker, Java 17, Xcode o Android SDK y puertos (`54329`, backend y Mailpit).
- `pnpm run bootstrap`: instala dependencias, valida configuración, ejecuta `generate` y prepara hooks opcionales.
- `pnpm dev:services` (Compose de HU-00-05) y `pnpm dev`: backend en `tsx watch` y app `development`, mostrando URLs y dispositivo; configura `10.0.2.2` en emulador Android, loopback en Simulator, `adb reverse` en Android físico o IP de red en otro dispositivo, sin direcciones fijas en la lógica de producto.
- `pnpm check` (formato, lint, tipado y unitarias afectadas) y `pnpm test` (suite local no nativa).
- `.editorconfig` y `.vscode/` con `extensions.json`, `settings.json`, `launch.json` (depuración compuesta) y `tasks.json`, sin tokens, IDs de equipos Apple ni rutas absolutas; generados excluidos de búsqueda.
- `.env.example` raíz y `server/.env.example` con nombre y explicación de cada variable, sin credenciales.
- `docs/development/setup.md`, `commands.md`, `configuration.md` y `debugging.md`.
- Comprobación en CI de que los comandos documentados existen y de que el ayuda de `doctor` responde (tecnologia/18 §12).

**No incluye**
- `dev:catalog`: HU-00-12. `qa:bundle`: HU-00-11. Comandos `db:*`: HU-00-06. Comandos `docs:*`: HU-00-16.
- Dev Container: HU-00-19. Configuraciones de Android Studio o IntelliJ: opcionales (tecnologia/18 §4).

## Criterios de aceptación
- [ ] Dado un clon limpio en macOS con los requisitos de `setup.md`, cuando se ejecutan `pnpm run doctor`, `pnpm run bootstrap` y `pnpm dev`, entonces la app `development` corre en un emulador, el backend responde `GET /health/live` y el tiempo total medido queda registrado frente al presupuesto de 30 min.
- [ ] Dado Docker detenido, cuando se ejecuta `pnpm run doctor`, entonces marca Docker como fallido con el enlace de solución y termina con código distinto de 0.
- [ ] Dado el puerto `54329` ocupado, cuando se ejecuta `pnpm run doctor`, entonces lo informa.
- [ ] Dado el `package.json` raíz, cuando se inspeccionan sus scripts, entonces existen `bootstrap` y `doctor`, no existe un script `setup`, y `docs/development/commands.md` documenta la invocación con `pnpm run` (DEC-230).
- [ ] Dado `pnpm check` ejecutado desde `app/lib/`, cuando corre, entonces ejecuta los mismos controles que desde la raíz.
- [ ] Dado un emulador Android, cuando se ejecuta `pnpm dev`, entonces la app llega al backend local sin editar código ni configuración a mano.
- [ ] Dado el schema `zod` de configuración del backend, cuando corre la prueba de configuración, entonces cada variable del schema figura en `server/.env.example` y viceversa.
- [ ] Dado `.vscode/`, cuando corre la comprobación de CI, entonces no hay rutas absolutas ni tokens.
