# Modelo de datos — TAO-156 (HU-00-08): Contrato como fuente única

## 1. Naturaleza del modelo

Esta historia **no introduce un modelo de datos relacional ni persistente**. No hay tablas, colecciones, migraciones de esquema ni entidades con FK contra una base de datos.

El "modelo de datos" afectado es la **capa de contrato (OpenAPI 3.x)** y sus **artefactos derivados** (tipos y cliente generados). Por lo tanto, las "entidades" son esquemas del contrato, operaciones, parámetros, extensiones y archivos de configuración; las "relaciones" son las referencias entre esos objetos y sus derivados.

Base de verificación: pedido de la HU, REQ-01..REQ-08, criterios de aceptación, casos `QA-00-08-*` y decisiones DEC-155, DEC-160, DEC-162, DEC-170, DEC-227, DEC-230, DEC-236. Los campos concretos de `Salud`/`SaludListo` y el catálogo de valores de `plataforma` **no se redefinen en esta HU**; se modelan como referencias a confirmar contra `server/contract/openapi.yaml` vigente.

Legenda: `[EXISTENTE]` ya en el repo · `[NUEVO]` lo agrega esta HU · `[DERIVADO]` generado por codegen.

## 9. Notas de migración y compatibilidad

- **Sin migración de datos.** No hay cambios de esquema persistente ni backfill.
- **Compatibilidad del contrato:** un cambio incompatible (p. ej. eliminar/renombrar propiedad **requerida**) exige **nueva versión mayor o convivencia explícita**; **no** se fuerza dentro de `/v1` (tecnologia/17 §5, REQ-02, criterio 3, QA-00-08-02).
- **Cambios aditivos:** un campo **opcional** nuevo pasa el gate de `openapi-diff` (criterio 3).
- **Seguridad de entrada:** toda petición HTTP se valida contra el contrato **antes** de la lógica; incumplir ⇒ `400 problem+json` con `codigo: validacion_fallida` y `requestId` (DEC-162, REQ-05, criterio 7, QA-00-08-03). El log registra `errorCode`.
- **Rollback (atómico):** revertir contrato, codegen, validadores y versión **como una unidad**; **nunca** dejar código generado apuntando a otra versión del contrato.
- **Orden de publicación:** el contrato y sus derivados preceden a cualquier consumidor (bloquea HU-00-09, HU-00-13, HU-00-18).
- **Dependencias de entrada:** HU-00-02 y HU-00-04 deben estar resueltas antes de aplicar este modelo.
