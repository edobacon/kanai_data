### Context found

- **Rules**: `RULE-global-001` (DoD C1–C6), `RULE-global-003` (modal de sesión usa `acquireTokenSilent`/`logoutRedirect` del MSAL entregado — sin reescribir el flujo), `DET-18` (draft), `DET-30` (rama de ticket).

- **Warnings**:
  - `<Can>` / `useCan`: en este ticket se construye la primitiva con el **vector de capabilities del store** (`auth.store`). El store recibe las capabilities del usuario desde `GET /api/capabilities/me` (endpoint que entrega JOR-010/A6 backend). En este ticket: primitiva funcional con vector mock/store; se conecta al endpoint real en JOR-011.
  - Route guard en dos niveles: (1) ocultar del nav (`<Can>` en `NavItem`); (2) bloquear acceso directo por URL (middleware o componente guard que resuelve capability requerida contra vector del usuario). Si falta la capability → renderiza página 403, NO el contenido.
  - La nota de seguridad del WP-A4.6 aplica: las páginas 403/404 son **UX**, no la frontera de seguridad — el backend siempre revalida (`@RequireCapability`).
  - Sin maqueta para 403/404 → se derivan del design system (JOR-003 tokens + JOR-006 átomos).

  - `<Breadcrumb>`: `Módulo › Subsección › Acción`, basado en la ruta activa.

  - Route guard en dos niveles: oculta `NavItem`/`NavGroup`/tile del Home si falta cap de acceso; bloquea acceso directo por URL → página 403.
  - Página 403 "Acceso denegado": icono + mensaje + CTA "Volver al inicio"; claro/oscuro.
  - Página 404 (`app/not-found.tsx`): estilo nuevo con design system, reemplaza el default de Next.
