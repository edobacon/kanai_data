# El guard de cambios sin guardar avisa "se van a perder los cambios" sin haber editado nada

## Request

Al salir de un formulario, el guard (JOR-056) siempre notifica que se van a perder los cambios,
aun cuando no se ha editado nada. La detección de cambios está fallando.

Reportado por el dev sobre: crear/editar item, crear factura (ventas), factura proveedor (compras).
El síntoma aparece al **abrir el formulario y salir de inmediato, sin tocar ningún campo**.

Causa raíz **confirmada** (no es hipótesis) contra la fuente de Radix y la semántica de RHF.

### Hipotesis

| # | Hipotesis | Status | Evidencia |
|---|-----------|--------|-----------|
| H1 | El `Select` de Radix dispara un `change` sintético al montar → `field.onChange` → RHF marca el campo dirty | ✓ confirmada | `node_modules/@radix-ui/react-select/dist/index.mjs:1094-1110` (SelectBubbleInput): `prevValue` (undefined en 1er render) `!==` `selectValue` → `dispatchEvent(change)` → `onValueChange(value)` |
| H2 | El mismatch `undefined` (default RHF) vs `''` (valor emitido) hace que RHF lo trate como cambio real | ✓ confirmada | RHF compara por deep-equal; `undefined !== ''` → dirtyFields poblado → `formState.isDirty=true` al montar |
| H3 | El `MultiSelect` corrompe el array al montar | ✓ confirmada | Select interno con `value=""` → `onValueChange('')` → `handleSelect('')` → `onChange([...[], ''])` → agrega `''` a categorias/aplicaciones/proveedores |
| H4 | Los tests jsdom no lo atrapan | ✓ confirmada | Las suites de guard mockean el `Select` de Radix; jsdom no ejercita `SelectBubbleInput`. Tests diagnósticos propios: los 4 forms dan `isDirty=false` en jsdom (por eso el bug solo aparece en navegador) |

**Detalle por form afectado:**

| Form | Control al montar | Default RHF | Emite al montar | ¿Dirty? |
|------|-------------------|-------------|-----------------|---------|
| Ventas (`TransactionBuilder`) | Select `origen`, `tipoDTE` (`value={field.value ?? ''}`) | `undefined` (no en `DEFAULT_VALUES`) | `''` | Sí (`undefined !== ''`) |
| Compras (`PurchaseInvoiceBuilder`) | Select `tipo`, `origen` (`value={field.value ?? ''}`) | `undefined` | `''` | Sí |
| Item (`ItemCreateForm`) | MultiSelect `categorias`/`aplicaciones`/`proveedores` | `[]` | `onChange([''])` | Sí + corrupción |
| Pago (`EfectuarPagoForm`) | Select `formaPago` (`value={field.value ?? ''}`) | `undefined` | `''` | Sí (probable — mismo patrón; no reportado por el dev) |

**Nota**: `ItemCreateForm.tipo` NO falla porque su default es `''` (emite `''` → `'' === ''` → no dirty). Esa asimetría fue la pista.

### Solución acordada con el dev — alcance B + C

- **B (necesaria)** — `MultiSelect.handleSelect`: ignorar selección vacía/duplicada
  `if (!selected || value.includes(selected)) return;`. Corrige item y evita la corrupción del array.
- **C (sistémica)** — wrapper/componente `SelectField` para Selects controlados por RHF que ignore el
  emit espurio de montaje: `onValueChange={(v) => { if (v !== (field.value ?? '')) field.onChange(v); }}`.
  Ataca la clase entera del bug (ventas/compras/pago) sin depender de recordar defaults `''` en cada form.

Descartadas: A (alinear defaults a `''` por-form) — frágil ante Selects nuevos y no cubre el MultiSelect.

## Summary

### What was requested
Corregir el falso aviso de "se van a perder los cambios" al salir de un formulario sin editar.

- **Causa raíz real (corregida en S2)**: RHF nace `isDirty=true` al montar por mismatch de baseline (`_formValues != _defaultValues` en deepEqual) — inputs de texto `register` que rinden '' vs default undefined, y Controllers/Selects que registran claves ausentes de defaults. El emit de Radix era solo un factor.
- **Fix**: hook `useFormMountBaseline` (`reset(getValues())` al montar) aplicado a los 4 forms con guard (item/ventas/compras/pago). Rebaselina los defaults a los valores reales → `isDirty` parte en false; una edición real sí marca dirty (protección conservada).
- Guard en `MultiSelect.handleSelect` para ignorar selección vacía/duplicada (bug de corrupción del array, aparte).
- Descartado el enfoque S1 (SelectField + defaults per-campo): frágil y no era la causa; revertido.
- Regression completa (1333 tests, branches 92.77%) + diagnóstico/verificación en navegador real del dev.
