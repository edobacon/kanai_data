# Activación/desactivación de cuentas de usuario: permiso, no auto-acción, modal de confirmación y bloqueo de login

## Request

Manejar la activación y desactivación de una cuenta de usuario con estas reglas:
1. Un usuario NO debe poder activar/desactivar su propia cuenta; solo puede hacerlo quien tenga el permiso.
2. El ícono debe ser uno solo, no debe cambiar según el estado (ya existe el badge que muestra el estado).
3. El botón de cambio de estado debe levantar un modal que advierta de la acción y pida confirmación antes de realizar el cambio, tanto para activación como para desactivación.
4. Validar que un usuario con cuenta desactivada no puede ingresar al sistema, sin importar su rol.

### Context found

**Capabilities (catálogo en [03_rbac.ts:24-51](../../../../q/jormat_monorepo/jormat-evolution-mono/backend/jormat-api/seeds/03_rbac.ts)):** `config.users:view/edit/delete/assign-roles`. El disable usa `config.users:delete` (nombre confuso: la descripción dice "Deshabilitar"). El enable reusaría la misma capability.

**Frontend permisos:** `useCan(cap)` + `<Can cap>` leyendo `useAuthStore().capabilities` (deny-by-default). La vista ya está bajo `<RouteGuard cap="config.users:view">`.

### Decisiones de diseño (resueltas con el dev 2026-06-24)

- **D-A (user-cache de 5 min) → Aceptar ventana ≤5 min.** El check de `disabled_at` se hace sobre la fila fresca (login y cache-miss) → un login de cuenta desactivada se bloquea de inmediato; un usuario ya logueado+cacheado que se desactiva queda cortado al expirar el cache (≤5 min). No se invalida cache ni se agrega query por-request.
- **D-B (capability) → Nueva capability de estado.** Se introduce `config.users:change-status` en el catálogo (03_rbac) para enable+disable (reemplaza el uso de `config.users:delete` en disable). Migra catálogo + seeds + asignaciones RBAC. Se otorga a `internal-admin` (09 grant-all) y a los roles que hoy tienen `config.users:delete` (preservar capacidad actual).
- **D-C (UX self-action) → Ocultar la acción en la fila propia.** Backend igual bloquea (403) por defensa en profundidad.
- **D-D (login bloqueado) → 401 + mensaje + logout MSAL.** El front muestra "cuenta desactivada, contacta a soporte" y cierra la sesión.
