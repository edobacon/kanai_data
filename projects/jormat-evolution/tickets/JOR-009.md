# JOR-009 · A5 · Fundaciones backend

## Request

Construir la estructura de modulos NestJS base + los utilitarios de backend que todos los modulos de negocio reutilizaran: repos por dominio, paginacion/filtros estandar (DTO de query reutilizable), `ExceptionFilter` global con contrato `{code,message}`, `CapabilitiesGuard` + `@RequireCapability` (guard de strings sin CASL), y en el front el cliente API tipado (axios + `ApiError`) con hooks base React Query. ## Triage

Las fundaciones backend son el prerequisito inmediato de JOR-010 (RBAC) y de toda la Capa B/C: sin el patron de modulo, el contrato de error y el guard base no se puede construir ningun endpoint de dominio con calidad uniforme. Este ticket NO crea el modelo de datos de negocio (eso es Capa C); crea la infraestructura de plomeria que cada modulo posterior reutiliza.

### Context found

- **Rules**: `RULE-global-001` (DoD: tipado estricto, unit del service con repo mockeado, test del builder, test del guard — C1–C6 + testing); `RULE-global-002` (S2: el guard que se crea aqui es la frontera de authZ — el test de `CapabilitiesGuard` debe incluir caso 403 sin capability; S3: contrato de error no expone stack trace; S4: el DTO de pagination valida sus params); `RULE-global-003` (no tocar `auth.guard.ts` entregado ni `/auth/me` — el `CapabilitiesGuard` es nuevo y aditivo, resuelve caps por su cuenta usando el `req.user` que el `AuthGuard` entregado ya deja).
- **Decisions**: `DEC-006` (guard de strings propio + `@RequireCapability`, sin CASL — aqui se implementa el `can()` puro y el guard); `DEC-001` (tenant: en este ticket no hay queries de dominio, pero el patron de repos que se define aqui debe dejar el slot para `workspace_id` en cada query futura); `DEC-004` (validacion: `class-validator` + `ValidationPipe` ya global — el DTO de pagination usa este patron); `DEC-002` (contrato tipado: A5.5 arranca la Fase 0, Zod en front).
- **Docs**: `implementation-tasks.md` WP-A5 (A5.1–A5.5 — fuente granular); `implementation-conventions.md §B` (patron modulo Nest: module/controller/service/dto/repo, DI por constructor, sin logica en controllers); `permissions-model.md §5` (implementacion del guard y `can()`); `frontend-api-layer.md` (capa tipada front: cliente axios + `ApiError` + hooks RQ).
- **Warnings**: el `CapabilitiesGuard` (A5.4) resuelve las caps efectivas consultando la DB al vuelo — en este ticket el modelo de permisos (tablas) aun no existe (lo crea JOR-010). Por lo tanto A5.4 se implementa como el guard + `can()` + decorador, con la interfaz de resolucion de caps; la conexion real a DB (`effectiveCaps`) se completa en JOR-010 cuando existan las tablas. Documentar este contrato en el spec para que JOR-010 lo cierre.

### Scope (anti-drift)

- **Dentro**: estructura de modulos Nest por dominio (patron module/controller/service/dto/repo) documentada y con un modulo ejemplo; DTO de paginacion/filtros/orden reutilizable (con validacion class-validator); `ExceptionFilter` global con contrato `{code,message}` + status; `CapabilitiesGuard` + decorador `@RequireCapability` + funcion pura `can()` (con wildcards); cliente API tipado en el front (axios + `ApiError`, modulos por dominio) + hooks base React Query.
