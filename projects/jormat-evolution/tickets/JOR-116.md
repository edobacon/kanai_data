# JOR-116 · Estabilizar el proyecto storybook/browser de vitest (flaky bajo carga)

## Request (follow-up, backlog — NO Jira)

El proyecto `storybook` de vitest (stories corridas como tests en chromium headless, `@storybook/addon-vitest`)
es **flaky bajo carga paralela**: en corridas con ambos proyectos algunas stories/tests fallan por timeout
(5s) o errores de provider (`useTheme`/`NavigationGuardProvider`), pero **pasan en aislamiento**. Hoy esta
excluido de CI/coverage a proposito (`--project '!storybook'`) y JOR-115 alineo `npm test` para no correrlo
por defecto. Este ticket es para **estabilizarlo** y poder recuperarlo como red de seguridad de interaccion.

## Evidencia (2026-08-08)

- Proyecto jsdom (CI real): 1784/1784 verde, estable.
- Proyecto storybook/browser: pasa aislado (ej. `EfectuarPagoForm.stories`, `ItemSearchPanel` 6/6); flaky
  solo en corrida full paralela. Sintomas: `Test timed out in 5000ms`, `Unable to find role="dialog"`,
  `useTheme debe usarse dentro de <ThemeProvider>`, `useUnsavedChangesGuard ... <NavigationGuardProvider>`,
  `NEXT_NOT_FOUND`.

## Hipotesis / enfoques a evaluar (no decididos)

1. **Timeouts/concurrencia**: subir `testTimeout` del proyecto storybook y/o bajar la concurrencia del
   browser (instancias/pool) para eliminar los timeouts por contencion de CPU.
2. **Providers**: los errores `useTheme`/`NavigationGuardProvider` sugieren que algunas stories no reciben
   los decorators globales bajo cierta orden/carga; revisar `.storybook/preview.tsx` (decorators) y que
   toda story que use esos hooks quede envuelta. Ver si es un race del addon en browser-mode.
3. **Aislar el flaky set**: identificar las stories concretas que flaquean y darles play-functions/espera
   robusta (findBy con timeout explicito, waitFor).

## Criterio de terminado

`npm run test:stories` (proyecto storybook completo) verde de forma **repetible** (3 corridas seguidas sin
fallos), para reincorporarlo a la señal de CI si se desea. No urgente; no bloquea la ola front-fidelity.

## Notas

- Es un problema **preexistente** del harness (no introducido por la ola). Registrado como backlog local
  (no Jira) por indicacion del dev.
