# JOR-145 · Unificar soft-delete a is_active (dominio/datos): inventario, users, customers y tablas sin estado

## Request (backlog local — NO Jira)

Migrar el borrado logico de todas las tablas de **negocio/datos** a la convencion unica `is_active smallint NOT NULL DEFAULT 1` (1 = activo, 0 = eliminado) ([[RULE-database-001]]). El bloque de RBAC/control de acceso se aparta en [[JOR-146]] por su riesgo de fuga de permisos.

Hoy conviven varias convenciones (mapeo verificado 2026-08-12): `in_status` smallint 1/0 (inventario), `disabled_at` timestamp (users, customers), `is_active`+`status` integers muertos (trucks, **fuera de alcance**: lo rehace [[JOR-147]] app-native, ver Encadenamiento), y varias tablas sin ninguna columna de estado.

**Decision de nombre/tipo (dev, 2026-08-13, verificada contra legacy):** el patron es `is_active smallint` con valores `1`/`0`, NO boolean (el codigo real ya usa un smallint 1/0). En inventario **NO se renombra `in_status`**: esa columna queda **reservada** para el estado de falla del item (legacy `status-fail`: `{value, observation}`, feature aun no migrado), asi que se **agrega** `is_active` nuevo y `in_status` se deja intacto. El legacy no lee `in_status` por ese nombre en ninguna parte (0 usos), por eso agregar `is_active` al lado es seguro.

## Alcance (17 tablas)

- **Inventario: agregar `is_active`, conservar `in_status` (11)**: providers, categories, applications, items, locations, item_references, item_providers, item_categories, application_items, item_warehouses, item_warehouse_locations. Agregar `is_active smallint NOT NULL DEFAULT 1`, backfill `is_active = in_status` (hoy `in_status` ya es 1/0). **`in_status` NO se dropea**: queda reservado para el estado de falla del item. Recrear el indice `idx_item_providers_item_id_in_status` con su equivalente sobre `is_active` para las lecturas de vivos.
- **`disabled_at` → `is_active` (2)**: users, customers. Agregar `is_active smallint NOT NULL DEFAULT 1`, backfill `is_active = (disabled_at IS NULL ? 1 : 0)`, luego **dropear `disabled_at`**. Se **pierde** el timestamp dedicado de baja; la marca temporal queda en `updated_at` (decision dev 2026-08-13; caveat: `updated_at` se sobrescribe en cualquier edicion posterior, no es fecha de baja fiable). El indice unico parcial de customers (`WHERE disabled_at IS NULL`, `migrations/20260723000000_customers.ts:29-31`) pasa a `WHERE is_active = 1`.
- **trucks: FUERA DE ALCANCE**. [[JOR-147]] rehace trucks app-native (uuid PK + `is_active smallint 1/0` propio en su migracion); este ticket NO lo toca. Se saca de las 18 originales → 17.
- **Sin estado hoy → agregar `is_active` (4)**: warehouses, attachments, catalogos_repuestos, usage_metrics. Nacen con `smallint NOT NULL DEFAULT 1`. `catalogos_repuestos` ademas pasa de hard-delete a soft (`catalogos-repuestos.repository.ts:107-109`).

Fuera de alcance: `workspaces` (mantiene `status` de ciclo de vida y hard-delete). RBAC/memberships en [[JOR-146]].

## Enfoque: expand-contract (2 migraciones)

1. **Expand (aditiva, reversible)**: migracion que agrega `is_active smallint NOT NULL DEFAULT 1` + backfill en las 17 tablas (inventario desde `in_status`, users/customers desde `disabled_at`). Conserva las columnas viejas. `down()` dropea `is_active`.
2. **Switch de codigo**: reemplazar los filtros/deletes por columna vieja (`= 1` para vivos, `= 0` para baja):
   - Inventario: ~20 sitios en `src/items/items.repository.ts` + ~10 en `src/catalogos/catalogos.repository.ts` (`.where('in_status', 1)` → `.where('is_active', 1)`, `update({ in_status: 0 })` → `update({ is_active: 0 })`). `in_status` deja de leerse para activeness (queda reservado).
   - **Preservar marcadores de deuda de [[JOR-144]]**: al reescribir `src/items/items.repository.ts` y `front/.../ItemCreateForm/itemDetailToFormValues.ts` NO borrar los marcadores `DEUDA_TECNICA` de DT-18 (`bloqueoDescuento`) ni DT-19 (`canales.catalogo`) que JOR-144 dejo vivos a proposito en esos bloques. Solo se toca el filtro/columna de activeness.
   - users/customers: `src/users/users-admin.service.ts:125,141`, `src/customers/customers.repository.ts:177,183`, `src/auth/auth.guard.ts:55-56` (`assertAccountActive`).
   - Reemplazar indice parcial de customers (`WHERE is_active = 1`).
3. **Contrato de lectura (front)**: los reads que alimentan al front NO devuelven filas `is_active = 0`; a efectos del usuario estan eliminadas.
4. **Seeds**: auditar `seeds/01_initial_data.ts` y confirmar que users/customers/inventory preservan comportamiento con `DEFAULT 1` (hoy no setean columna de estado; dependen del default).
5. **Tests**: actualizar suites que asertan sobre `in_status`/`disabled_at`; agregar regresion de soft-delete (borrar → no aparece en reads; reactivar donde aplique).
6. **Contract (destructiva)**: migracion que dropea **`disabled_at` (2)**. **NO se dropea** `in_status` (reservado para el estado de falla). Solo tras 2-5 verdes. DET-40: antes del drop, verificar 1:1 que ningun consumidor lee `disabled_at`.
