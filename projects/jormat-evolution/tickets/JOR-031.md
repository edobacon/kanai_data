# TopBar: mostrar nombre de empresa (no id) + ocultar badge de notificaciones en 0

## Request

En el TopBar:
1. La empresa activa muestra el **id** (UUID) del workspace; debería verse un **nombre**.
2. El badge de notificaciones debería ser **0**, y cuando es 0 **no debería verse** el badge.

> Nota de alcance (acordada con el dev): aunque el pedido se etiquetó "tactic", mostrar el nombre exige traer el workspace (el front solo tiene `workspace_id`). El dev optó por "un solo tactic para ambos" asumiendo que crece (servicio + hook nuevos). El badge es trivial.

## Discoveries / decisions

- D1: el badge ya oculta cuando `unreadCount === 0` (`{unreadCount > 0 && <Badge/>}` en `TopBar.tsx:70`). El único cambio real es el valor hardcodeado `3 → 0`. El "ocultar en 0" ya estaba bien.
- D2: `/auth/me` devuelve `{id, email, name, role, workspace_id}` sin nombre de workspace; no existe servicio de workspaces en el front. La tabla `workspaces` tiene `name`/`slug` y existe `GET /api/workspaces/current` (controller `workspaces.controller.ts:21`). → el nombre se obtiene con un fetch a ese endpoint.
- M1 (micro-decision): agregar `services/api/workspaces.ts` (`getCurrentWorkspace`) + `hooks/useWorkspace.ts` (`useCurrentWorkspace`, React Query vía `useApiQuery`), y mostrar `workspace.name` en `EmpresaSwitcher` con **fallback al id** mientras carga / si falta. La selección sigue usando el `id` (header `X-Admin-Workspace`); solo cambia la etiqueta visible.
- M2 (micro-decision): unit test de `EmpresaSwitcher` mockea `useCurrentWorkspace` (como ya mockea los stores) → sin QueryClient/MSW en jsdom. Ahí vive la cobertura nombre-vs-id.
- D3 (dato, verificado en DB `jormat-evolution-postgres-1`): el workspace del dev (`0da5e238…`) tenía `name = "Eduardo Bacon"` — **el nombre del usuario**, no de la empresa. Causa raíz backend: [auth.guard.ts:179](../../../../q/jormat_monorepo/jormat-evolution-mono/backend/jormat-api/src/auth/auth.guard.ts) `const workspaceName = name || email.split('@')[0]` → el auto-provision nombra el workspace con el nombre de la persona en el primer login. **No es bug de frontend** (el display de `workspace.name` es correcto). Fix de dato aplicado: `UPDATE workspaces SET name='Jormat SpA' WHERE id='0da5e238…'` (decisión del dev). El workspace seedeado (`Jormat Demo`) sí tenía nombre real.
- D4 (descubierto en S1): el proyecto storybook **no tiene MSW configurado** (`.storybook/preview.tsx` solo tiene `QueryClientProvider`, sin `initialize()`/`mswLoader`). Por eso `parameters.msw.handlers` se ignora en stories y no se pueden testear stories que dependen de un fetch de datos. La story `WithName` se descartó; la cobertura nombre-vs-id queda en el unit test (mock del hook). Agregar MSW a storybook = follow-up de infra, fuera de scope.
- D5 (out-of-scope, observación → follow-up backend): la conducta del auto-provision (D3) debería corregirse para que un workspace nuevo no se llame como la persona. El dev optó por NO crear el ticket backend ahora; queda anotado.
