# Imágenes docker prod/dev con nombre propio para que convivan

## Request

Las imágenes de prod y dev del front (y api) comparten el tag (`jormat-evolution-front`): el `run.sh build` (prod) pisa la imagen dev y el modo dev cae con `next: not found` (la imagen prod standalone no tiene el binario `next`). Hay que hacer que sean distintos para que puedan convivir. Detectado al levantar jormat post-JOR-061 (el front no arrancaba).

Ver M1.
- **Bugs**: n/a

## Discoveries / decisions

- D1: `docker compose up` NO reconstruye si el tag ya existe — por eso el modo dev arrancó la imagen prod (built hace 7 días por `run.sh build`) con `command: npm run dev` → exit 127. La imagen prod es Next standalone (`server.js`, sin `next` en `.bin`).
- D2: los servicios `api` y `front` no declaran `image:` en ningún compose → ambos modos derivan el mismo nombre `{project}-{service}` = colisión estructural, no accidente puntual.
- M1 (micro-decision): excepción a RULE-global-003 autorizada por el dev (AskUserQuestion 2026-07-01) — agregar `image:` SOLO en `docker-compose.dev.yml` (aditivo); el compose prod y `run.sh` no se tocan, preservando el flujo de build/tag ACR.
