# Detalles UX del modal de detalle de item (cierre, dismiss configurable, select custom)

## Request

En la vista de detalle de item (`ItemDetailModal`):
1. El botón de cerrar no muestra la X bien y "se pierde con cualquier click en el modal".
2. El modal debería persistir si se presiona afuera; eso debería ser **configurable** y en este caso NO debería hacer dismiss.
3. Hay un selector en la esquina inferior izquierda del modal que no dice qué es y usa un `<select>` nativo; debería ser un selector custom de React.

## Discoveries / decisions

- D1: `DialogContent` es primitivo compartido (`components/ui/dialog/dialog.tsx`), consumido por 5 modales (CreateRole, UserRoles, UserForm, ItemDetail, SessionTimeout). El prop `dismissable` se agrega **aditivo con default `true`** → cero regresión para los otros 4.
- M1 (micro-decision): "configurable" se implementa como prop `dismissable?: boolean` en `DialogContent` (no por handler suelto en cada call-site) — API reusable y legible; los otros modales pueden adoptarla luego (p.ej. SessionTimeoutDialog).
- M2 (micro-decision): `dismissable={false}` desactiva solo el dismiss por **interacción exterior** (overlay/pointer-outside). Escape se mantiene como cierre intencional del usuario (no es un click accidental afuera). El botón X y el "Cerrar" del footer siguen siendo los cierres explícitos.
- M3 (micro-decision): el `<select>` nativo se reemplaza por el `Select` custom (Radix, `@/components/ui/select`) controlado con estado React + label visible "Bodega".
- D2 (out-of-scope, observación): `SessionTimeoutDialog` probablemente debería usar `dismissable={false}` también (un timeout no debe cerrarse por click afuera) — no se toca en este tactic.
