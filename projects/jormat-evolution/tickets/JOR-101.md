# Actualizar matriz e2e de roles tras JOR-077 (cost-view)

## Request

`test/e2e/roles-config.e2e-spec.ts` tiene 4 tests en rojo porque la matriz `EXPECTED` (count + must por rol) quedó desactualizada. JOR-077 (cerrado 22-jul, commit `86c7ce7`) agregó `items.parts:cost-view` y otras capabilities a los seeds (`04_items_capabilities.ts` +7, `10_demo_roles_users.ts` +4) pero **no** actualizó la matriz del e2e. Resultado: los roles resuelven más capabilities de las que la matriz espera.

Detectado durante la regression de S2 de **JOR-081** (backlog B1). Es preexistente, ajeno al módulo items (por eso ticket aparte).

## Diagnóstico (ya hecho)

- Falla en 4 roles: `bodega` (espera 11), `jefe-local` (espera 25), `jefe-venta` (espera 25), `gerencia` (espera 26).
- Ejemplo runtime real: `gerencia` resuelve **31** capabilities (recibido) vs 26 (esperado). El array recibido incluye caps nuevas post-JOR-077.
- Causa raíz: JOR-077 tocó solo seeds, no el spec e2e. JOR-077 cerró probablemente corriendo unit (no `test:e2e`, que requiere Postgres), así que el drift pasó silencioso. No quedó registrado como deuda en JOR-077.

## Solución propuesta

1. Correr `npm run test:e2e -- roles-config` y capturar el vector real resuelto por cada rol (los 4 que fallan + verificar los 2 que pasan por si acaso).
2. Actualizar en `roles-config.e2e-spec.ts` la matriz `EXPECTED`: el `count` exacto de cada rol al valor real, y agregar a `must[]` las capabilities clave nuevas (al menos `items.parts:cost-view` donde aplique — gerencia + jefaturas según el seed `10_demo_roles_users.ts`).
3. **Confirmar los counts contra el seed** antes de fijarlos (no solo copiar el "recibido" — validar que el seed es correcto y la matriz refleja la intención de negocio de JOR-040).
4. `npm run test:e2e -- roles-config` verde (6/6 roles).

## Regression

- Los otros e2e (`items-read`, `items-write`) no se tocan y deben seguir verdes.
- No modificar seeds ni capabilities: el fix es SOLO alinear la matriz de test al estado real (salvo que la revisión revele que el seed asignó una capability incorrecta a un rol, en cuyo caso escalar).
