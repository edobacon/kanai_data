# Items sin placeholders: acciones del detalle + imagenes + CSV del listado

## Request

Hacer que el modulo de items (listado Y detalle) deje de trabajar con placeholders y accione de verdad, tomando como referencia el comportamiento del legacy (AngularJS). Hoy items muestra datos reales de DB (JOR-081/083) pero: (a) las acciones del modal de detalle son `toast.info('no implementado')` o hardcode (imprimir, duplicar, compartir, ver ficha, activar/desactivar falla), con botones DUPLICADOS entre el MediaCard y el footer (Editar e Imprimir aparecen dos veces; "IMPRESION RAPIDA" e "Imprimir" comparten el mismo handler); (b) el selector de bodega esta muerto (se setea pero nada lo consume); (c) el soporte de imagenes es stub (StorageService no escribe a disco ni persiste la asociacion en DB); (d) la carga masiva de items por CSV no existe en el new (el legacy tenia "CARGA MASIVA DE ITEMS" con plantilla) y la descarga CSV solo exporta la pagina visible (no el filtrado completo ni todos).

Alcance = items completo (listado + detalle). DENTRO: (1) Clonar/Duplicar -> crea un registro nuevo (reusa itemDetailToFormValues + alta que persiste); (2) Imagenes reales -> StorageService escribe a /app/uploads (carpeta uploads como VOLUMEN Docker) + servir estaticos + tabla GENERICA polimorfica de archivos (attachments: owner_type/owner_id, sirve tambien a factura-proveedor/staff a futuro; hoy owner_type='item'); (3) Activar/Desactivar falla -> endpoint chico (la columna items.failure ya existe) + reflejar color en el listado; (4) Ver ficha -> pagina completa /inventario/items/[id] (deep-link, la maqueta la pedia); (5) Compartir -> Web Share API nativa (navigator.share, fallback copiar link); (6) Impresion Rapida -> vista print client-side (imagen + detalles) + window.print, replica la del legacy; (7) Imprimir Etiqueta -> label por bodega client-side, alimentado por el selector de bodega (que SE MANTIENE, no se remueve); (8) Import CSV -> carga masiva con plantilla descargable + endpoint backend nuevo (parse/validar por fila/crear en lote) + reporte de errores; (9) Export CSV completo -> exportar el filtrado entero (no solo la pagina) + decidir columnas y gating de costo; + homologar los botones (un solo set, sin duplicados). FUERA (deuda, no este ticket): en transito (guias/importaciones), productos relacionados, facturar/cotizar/wishlist, historial/kardex, Precio Minimo (necesita decision RBAC), WooCommerce, y los exports CSV especializados (ofertas/prioridad/stock-proveedor/critico/kardex/ML -> son reportes, Banda 6).

Es un ticket GRANDE (~46-54 SP): ejecutar en varias sessions (ej. S1 acciones front del detalle, S2 imagenes fullstack, S3 import CSV fullstack, S4 export CSV + homologacion de botones).

Piezas fullstack: imagenes (storage+tabla+volumen) e import CSV (endpoint bulk-create). El resto es front sobre backend ya real (+ endpoint chico de falla).

Referencia detallada campo a campo y accion a accion, con evidencia legacy archivo:linea, comparacion modal vs pagina completa, y estado de deuda tecnica (cubrible/queda/desbloqueo), en: jormat_docs/legacy/front/migracion/ticket-items-acciones-detalle.md (proposed_id T-ITEMS-FE-4). Cierra deuda de T-ITEMS-FE-1 (JOR-083) y T-ITEMS-BK (JOR-081).

1. **Clonar/Duplicar** (front): reusa `itemDetailToFormValues` -> precarga el alta -> crea registro nuevo. Legacy: `cloneItem` (`itemsDetailController.js:220`).
