# Fix seed runner: knex carga el spec colocado en seeds/ y aborta la corrida

## Request

El comando `./run.sh seed` (knex `seed:run`) esta roto desde el commit `88ce463` (JOR-012-S2):
el knexfile configura `seeds: { directory: './seeds', extension: 'ts' }` y knex carga TODOS los
`.ts` de `seeds/` — incluido el test colocado `seeds/02_local_admin.spec.ts`. Al ejecutarlo como
seed falla con `ReferenceError: describe is not defined` y aborta toda la corrida de seeds. Por eso
las capabilities nuevas (ej. `purchases.*` de JOR-015) no se pueden seedear; la DB solo tiene las
sembradas antes de agregar ese spec. Fix elegido (Opcion A): mover el spec a `seeds/__tests__/`
(knex usa `recursive: false` → ignora el subdir; jest recursa desde el root `seeds/` que ya esta
en `jest.config.ts` roots → lo sigue corriendo) y ajustar el import del seed. No tocar `knexfile.ts`
ni `jest.config.ts`. Ticket/commit propio de infra, no mezclar con modulos de negocio.

## Discoveries / decisions

- D1: knex 3.2.10 — `seeder-configuration-merger.js:12` define `recursive: false` por default; `fs-seeds.js`
  filtra por extension (`filterByLoadExtensions`), por eso `.spec.ts` (termina en `.ts`) entra como seed.
  Con `recursive:false`, knex NO escanea subdirectorios de `seeds/` → `seeds/__tests__/` queda fuera del runner.
- D2: `jest.config.ts` ya incluye `roots: ['<rootDir>', '<rootDir>/../seeds']`. jest recursa desde el root
  `seeds/`, por lo que `seeds/__tests__/*.spec.ts` se descubre sin tocar config (cero edits en jest.config).
- M1 (micro-decision): Opcion A sobre C (seedSource custom en knexfile). A toca solo nuestro archivo y
  cero infra entregada (RULE-global-003); C agrega codigo acoplado a internals de knex sobre el knexfile.
- D3 (operativo): el compose dev (`docker-compose.dev.yml`) monta solo `./backend/jormat-api/src` y
  `./shared` — `seeds/` esta HORNEADO en la imagen (`Dockerfile.dev: COPY . .`). Verificar cualquier
  cambio de seed exige `./run.sh build` (o rebuild del servicio `api`) + recrear el contenedor ANTES de
  `./run.sh seed`; el contenedor en ejecucion no refleja edits de `seeds/` del host. (Mismo patron que
  jormat-front, memoria `reference_jormat_front_docker_bakes_node_modules`.)
- D4 (preexistente, no introducido): tras recrear, `seed` fallo en `03_rbac.ts` con
  `relation "capabilities" does not exist` — 2 migraciones pendientes en esta DB
  (`20260614000000_rbac_tables`, `20260614000001_users_disabled_at`). Prerrequisito documentado
  `migrate → seed`. Corrido `./run.sh migrate` (Batch 2, aditivo) y `seed` quedo limpio. Ajeno al fix del runner.
