# Mostrar la barra de paginación siempre (no ocultarla con una sola página)

## Request

Las tablas deben mostrar la barra de paginación **siempre** (el "Mostrando 1 a N de N"), incluso cuando hay una sola página. Hoy el `DataTable` la oculta con `pageCount <= 1` (comportamiento preexistente), y como los stubs tienen pocas filas la barra nunca aparece. Arreglar en todas las tablas con un ticket tactic fix.

## KB consulted

- **Rules**: [RULE-frontend-001](../rules/frontend/RULE-frontend-001.md), [RULE-frontend-002](../rules/frontend/RULE-frontend-002.md) — al tocar `DataTable` mantener tests/stories del componente compartido.
- **Bugs**: n/a (sin bugs abiertos del módulo).
- **Specs**: [SPEC-tables-server-side-pagination](../specs/SPEC-tables-server-side-pagination.md) (JOR-068, closed) — este cambio es un follow-up de UX sobre el mismo `DataTable`; NO contradice la spec (que cubría el cálculo server-side, no la visibilidad de la barra). Sin overlap conflictivo.

## Discoveries / decisions

- D1: el ocultamiento con 1 página es **preexistente** a JOR-068 (base `1c16620`: `... && table.getPageCount() > 1 ? <Pagination> : null`). JOR-068 lo preservó adaptándolo a modo server (`effPageCount <= 1 return null`).
- D2: el componente `Pagination` ya renderiza bien con `pageCount=1` (muestra "Mostrando 1–N de N" + prev/next deshabilitados via `isFirst`/`isLast`) → el fix no requiere tocar `Pagination`, solo quitar la guarda en `DataTable`.
- M1 (micro-decision): el cambio toca 4 archivos (1 fuente + 3 test flips de la aserción "barra oculta con 1 página"). Roza el umbral de escalamiento tactic (>3 archivos), pero es **un solo cambio semántico** en el componente compartido + propagación mecánica de tests; se mantiene tactic (escalar a full-path por un toggle de 1 línea sería overhead injustificado). La línea 301 (`rows.length === 0 → null`) ya evita mostrar la barra en tablas vacías.
