# Jerarquia de fuentes y confianza para datos de DrunAppGor

## Context and problem statement

DrunAppGor parte de muchas fuentes locales: PDFs extraidos/traducidos, reglas completas, puertas 1.5, docs curados y DrunaDoors. Si todas se tratan como iguales, el pipeline puede mezclar texto canonico, traducciones, datos derivados e intentos incompletos sin que el usuario o el desarrollador sepan que tan confiable es cada dato.

La app necesita una jerarquia explicita de fuentes y un vocabulario de confianza antes de modelar assets, UI, chat o voz.

## Decision drivers

- Evitar repetir el desorden inicial de DrunaDoors.
- Preservar trazabilidad para reglas, historia, puertas, interacciones y chat.
- Permitir que el pipeline combine fuentes sin ocultar incertidumbre.
- Hacer que los tests puedan bloquear datos sin `sourceRefs` o sin `confidence`.
- Separar fuente canonica de fuente auxiliar.

## Considered options

| # | Option | Description |
|---|--------|-------------|
| A | Todas las fuentes equivalentes | Consumir cualquier archivo local como verdad. |
| B | Solo PDFs/docs canonicos | Ignorar DrunaDoors y referencias estructuradas auxiliares. |
| C | Jerarquia con confianza explicita | Usar fuentes por prioridad y marcar origen/confianza por record. |

### Option A: Todas las fuentes equivalentes
- **Pro**: Menos friccion inicial.
- **Con**: Mezcla datos verificados, OCR sospechoso y fixes manuales.

### Option B: Solo PDFs/docs canonicos
- **Pro**: Maxima limpieza conceptual.
- **Con**: Pierde estructura ya extraida y trabajo util de DrunaDoors.

### Option C: Jerarquia con confianza explicita
- **Pro**: Recupera valor sin ocultar incertidumbre.
- **Pro**: Permite UI/chat honestos sobre gaps.
- **Con**: Requiere campos extra y validaciones.

## Decision outcome

**Chosen option**: C — Jerarquia con confianza explicita.

**Justification**: DrunAppGor necesita datos locales primero, pero no todas las fuentes locales tienen el mismo peso. La fuente de verdad debe ser auditable y cualquier dato derivado o incompleto debe marcarse.

## Source hierarchy

| Nivel | Fuente | Uso |
|-------|--------|-----|
| 1 | `fullrules_es/sections/**` | Reglas, keywords, estados, flujo de juego y mecanicas. |
| 1 | `pdfdata_es/**` | Narrativa, capitulos, setups, eventos, interacciones, recompensas. |
| 1 | `doors_es/**` | Puertas traducidas 1.5 para V1. |
| 2 | `docs/**` | Docs curados: guias de extraccion, glosarios, decisiones tecnicas y catalogos. |
| 3 | `drunadoors/src/data/**` | Fuente auxiliar/cantera: datos estructurados, traducciones, casos manuales, overrides. |
| 4 | `refs/**` | Referencias externas/locales para auditoria o reconstruccion. |
| 5 | online | Solo fallback autorizado para erratas/FAQs/dudas puntuales. |

## Confidence vocabulary

| Valor | Significado |
|-------|-------------|
| `exact` | Transcrito/verificado contra fuente canonica local. |
| `verified` | Estructurado y revisado contra fuente canonica. |
| `translated` | Traduccion local aceptada, con fuente original trazable. |
| `derived` | Derivado desde una fuente estructurada o regla de pipeline. |
| `inferred` | Inferido por heuristica o cruce de fuentes. |
| `partial` | Datos utiles pero incompletos. |
| `incomplete` | Marcado como incompleto por la fuente o por revision. |
| `ocr_suspect` | Texto con sospecha de OCR corrupto o mezcla de entradas. |
| `missing` | Dato esperado no disponible localmente. |

## Consequences

### Positive
- El pipeline puede priorizar fuentes sin descartar trabajo previo.
- Chat/voz/UI pueden mostrar incertidumbre de forma honesta.
- Tests pueden exigir `sourceRefs` y `confidence`.

### Negative
- Aumenta la complejidad inicial del modelo.
- Algunos tickets visuales dependen de cerrar gaps de completitud.

### Mitigations
- Definir IDs/sourceRefs en `RULE-project-002`.
- Mantener readiness actualizado antes de activar tickets de datos grandes.
- Usar DrunaDoors solo como cantera bajo `RULE-project-001`.

## Confirmation

- Todo asset generado incluye `sourceRefs` y `confidence`.
- Ningun dato proveniente de DrunaDoors se marca `exact` sin verificacion contra fuente nivel 1/2.
- Los tickets de pipeline consultan `docs/context-data-readiness.md` antes de diseñar tasks.
