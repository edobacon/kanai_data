### Adenda 1 - 2026-10-12

Aclaraciones consolidadas (hechos verificados en el repo):
1. Runners separados: las 119 fallas de unittest son de `python3 -m unittest discover -s tests` (raiz); las 8 de node tests son de `node --test scripts/dev/*.test.mjs` (paridad de .env.example, importa zod desde server/); Vitest corre solo en `server/`. El criterio de exit 0 aplica a Vitest sin fallas de codigo y a `pnpm run check` sin regresiones respecto del baseline medido en la sesion; las 119 y las 8 se clasifican como fallas de entorno preexistentes, sin corregirlas ni silenciarlas.

4. El baseline de Vitest se mide con `pnpm -C server exec vitest run` ademas de `pnpm run check`; el grep de secretos usa patrones con valor (por ejemplo `otp[=:] *[0-9]{4,}`, `password[=:] *\S+`, `token[=:] *\S{8,}`) y no la palabra suelta.

### Adenda 2 - 2026-10-12 - eduardo.bacon@uplanner.com

Decision de la persona (opcion A, acotar el criterio al baseline medido):
1. El criterio de verde de este ticket se evalua contra el baseline medido en la sesion, no contra un verde absoluto de `pnpm run check` ni de Vitest. Se exige: (a) que Vitest en `server/` ejecute al menos las 648 pruebas del baseline sin fallas de codigo nuevas; (b) que `pnpm run check` no tenga regresiones frente a ese baseline.
2. La inestabilidad de la suite medida en el baseline queda clasificada como falla de entorno preexistente, sin corregirla en este ticket: la carrera de limpieza de bases efimeras ("permission denied to terminate process" en `app-release.integration` y `configuracion.integration`) y el 405 intermitente de `verificacion-correo` (pasa 3 de 3 de forma aislada).
