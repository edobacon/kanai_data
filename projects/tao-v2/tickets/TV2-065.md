# B0-01b. Estabilizar la suite de integración

Tipo: improvement
Módulo: Backend

## Contexto
- Origen: baseline medido en TV2-003 (B0-01). Vitest en `server/` con Node 24 no es estable en verde y TV2-003 lo dejó clasificado como falla de entorno preexistente, sin corregirlo (adenda 2).
- Épica: EP-02 Base del servidor y registro. Debe ejecutarse antes de TV2-004 (B0-02), que de lo contrario hereda la inestabilidad.
- Repo único `tao-v2`, rutas `server/src/test/`, `server/vitest.config.ts`, `compose.yaml`.

## Alcance
Dentro:
- Carrera de limpieza de bases efímeras: `app-release.integration` y `configuracion.integration` fallan en el `afterAll` con "permission denied to terminate process". Corregir la causa (permiso del rol, o no terminar conexiones ajenas), con reintentos solo si el timeout del hook los cubre.
- 405 intermitente en `verificacion-correo` (pasa aislado, falla dentro de la suite completa): determinar la causa, por ejemplo interferencia entre archivos en paralelo, y corregirla.
- `pgboss.integration` ("migración idempotente") encuentra 1 job donde espera 0: confirmar si la causa es el estado compartido con la base del stack legacy (`taomangalam-postgres`, puerto 54329) y aislar la base de pruebas de `tao-v2`.
- Quitar de la config de calidad del proyecto los flakes conocidos que queden resueltos.

Fuera: parametrizar `compose.yaml` y los scripts `backend:*` (es de TV2-004), el modelo de datos (TV2-005), y las fallas de `unittest` y `node --test` clasificadas como entorno en TV2-003.

## Criterios de aceptación
`pnpm -C server exec vitest run` con Node 24 termina con 0 fallas y las 648 pruebas ejecutadas, en 3 corridas completas consecutivas. `pnpm run check` termina con exit 0. Ninguna prueba se omite ni se marca flaky para lograrlo. Las corridas quedan registradas con su salida, no solo con relato.

Ninguna aceptación se cierra con un doble que siempre devuelve éxito; una corrida que no se pudo hacer queda pendiente, no aprobada.

## Dependencias
Depende de TV2-003 (matriz de evidencia y baseline). Bloquea a TV2-004.

## Recursos y cuentas
- Recursos: PostgreSQL local de pruebas. Cuentas ficticias y locales; sin contraseñas ni tokens en documentos ni reportes.

## Verificación
Backend, Node 24 por `.nvmrc`: `pnpm -C server exec vitest run` tres veces seguidas y `pnpm run check`. Se registra SHA, comandos, totales ejecutados/pasados/fallidos y pendientes.

## Riesgos
- La colisión con la base del stack legacy puede requerir un puerto o una base propios, que se solapa con TV2-004: coordinar para no duplicar.
- Corregir la limpieza puede exigir permisos de rol de PostgreSQL que cambian el entorno local.
