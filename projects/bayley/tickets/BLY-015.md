# Flow Explorer — vista de flujo centrada en un layout + sidebar retractil

## Summary

Archivado `2026-04-21` sin acceptance review formal. Trabajo implementado y validado en browser durante 5 sessions (2026-04-17 a 2026-04-18). Tests 106/106 verde, type-check limpio.

**Que se hizo:** modo Flow autosuficiente en LayoutsView (vista de app con multi-root, clusters visuales por entry-point, hover/sticky highlight, click-no-cambia-flow, sidebar retractil con defaults por modo, pill "Filtros (N activos)").

**Learns relevantes capturados en sessions (no promovidos a rules formales):**
- Multi-root grafo: separar "cambio de foco" (highlight, muta en sitio) de "cambio de contexto" (rebuild). Watcher que rebuildea depende de la seleccion de contexto, no del highlight.
- Cada modo de una vista exploratoria debe permitir auto-entrada (empty state con selector propio) — no depender de otro modo como prerequisito.
- Diferenciar estados visuales por **color**, no por grosor, cuando hay >1 elemento con el mismo tipo de ring (root vs selected).
- Mutar `data` en sitio > rebuild para cambios puramente visuales (preserva posiciones dagre, evita flicker).
- Rol en flow + cluster de origen son obligatorios para legibilidad con 15+ nodos.

**Pendiente (no aborda en este ticket):**
- Errores preexistentes de type-check en main (4 archivos) — ver BLY-016 backlog B6.

- Aprendizaje: cuando dos estados (root vs selected) usan el mismo color, la vista con 6 roots simultaneos se vuelve ilegible. Diferenciar por **color** (no por grosor) es mas robusto.

### 2026-04-18 — Session 5 (cluster highlight hover+sticky)

Pedido: "hay forma de mostrar los que estan unidos en un mismo entry-point?"

Implementada opcion A (hover highlight) descartando B (filtro por chips) y C (re-root en modo app).

Cambios:

- **FlowExplorer**: refs `hoveredRoot` y `stickyRoot`, computed `activeCluster = sticky ?? hovered`. Handlers `@node-mouse-enter` / `@node-mouse-leave` actualizan hovered solo si el nodo es `isRoot`. `@node-click` toggle sticky solo si el nodo clickeado es root. `@pane-click` limpia ambos.
- **Watcher activeCluster**: muta en sitio `data.flowClusterDimmed` en los nodos y `style.opacity` / `labelStyle.opacity` en los edges — sin recompilar el layout dagre. El flow mantiene posiciones, solo cambia el pintado. Misma tecnica que el watcher de `selectedLayoutId`.
- **LayoutNode**: prop nueva `flowClusterDimmed`; cuando `true`, la opacidad baja a 0.18 (override de la degradacion por depth).
- **Edges dimmed**: opacity 0.12 cuando ni el source ni el target pertenecen al cluster activo. Mantiene visibles los edges que entran al cluster desde afuera.
- Validacion DOM: hover dispatch sobre `hw_factor_assessment_list` dejo 5 roots a 0.18 y el hovered a 1; click sobre `hw_intervention_list` hizo sticky (otros a 0.18 aun despues de mouseleave); click en `.vue-flow__pane` limpio y todos volvieron a 1.
- Aprendizaje: no reconstruir el grafo para cambios puramente visuales — mutar `data` en sitio preserva posiciones dagre y evita flicker. Es la misma razon por la que el watcher de `selectedLayoutId` tambien muta en sitio.

## Request

El DetailPanel muestra rowActions / tabs / schema-fields del layout seleccionado con enriquecimiento de object target (BLY-014), pero **solo 1 nivel de profundidad**. Para debugear flows reales donde un modal abre otro modal que abre otro (ej. `ca_matrix_list → Ver detalle → ca_matrix_view → [rowActions con sus propios targets]`), el usuario tiene que **navegar click por click**, perdiendo el panorama de la cadena.

Solucion: **tercer modo "Flow"** en LayoutsView que toma el layout seleccionado como raiz y renderiza un grafo dirigido con expansion recursiva por profundidad ajustable, detectando ciclos visualmente.

Bonus: replantear la **sidebar izquierda**. En Jerarquia y Flow es parcialmente redundante — retractil con default por modo.

## Artifacts

### Composable `useLayoutsFlow`

```typescript
import type { LayoutNode, NavigationEdge, NavigationEdgeType } from '@/types/layouts';

export interface FlowNode {
  layout: LayoutNode;
  depth: number; // 0 = raiz
  incomingEdge: NavigationEdge | null; // edge que lo trajo
  isExpandable: boolean; // tiene edges salientes no incluidos todavia
  isCycle: boolean; // true si este nodo aparece ya como otra referencia
}

export interface FlowGraph {
  rootId: string;
  nodes: FlowNode[];
  edges: NavigationEdge[]; // subset de model.edges
  edgeTypesInFlow: Set<NavigationEdgeType>; // para el filtro contextual
}

export interface FlowOptions {
  maxDepth: number; // 1-4
  includeEdgeTypes: Set<NavigationEdgeType>; // edges a seguir al expandir
}

export function buildFlow(
  allNodes: LayoutNode[],
  allEdges: NavigationEdge[],
  rootId: string,
  options: FlowOptions,
): FlowGraph;
```

BFS desde rootId. Mantiene `visitedIds` set. Si un edge.to ya esta visitado → marca el edge como ciclo y NO recursa. Incluye solo edges cuyos `type` estan en `options.includeEdgeTypes`.
