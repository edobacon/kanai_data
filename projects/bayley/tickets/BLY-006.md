# Deep-link de flujo completo — URL compartible que preserva un recorrido entre vistas

## Closure (archivado 2026-04-21)

**Razon**: target original era `/layouts?flow=id1>id2>id3` — LayoutsView esta **deprecada** por AppsView (ver [BLY-023](BLY-023.md) draft para eliminacion).

**Estado actual de deep-links en bayley**:
- Deep-links simples si existen: `/datamodel?entity=X`, `/apps?app=Y` via `useQuerySync`
- Flow-trace multi-paso (`id1>id2>id3` con path highlighted + panel de gaps) no se implemento

**No reabrir automaticamente**. Si mas adelante se necesita compartir "recorridos" entre layouts dentro de AppsView, crear ticket nuevo con target correcto (`/apps?app=X&path=...` o similar). El formato y la logica de "resolver + gap detection" pueden reutilizar conceptos de este ticket, pero el alcance inicial (Layouts/Eventos/Componentes) queda invalido por la deprecacion de LayoutsView y porque las vistas de Eventos (BLY-004) y Componentes (BLY-005) no existen.

Ticket archivado sin implementar.

## Request (original)

Permitir compartir una URL de Bayley que represente un "recorrido" completo entre layouts encadenados, para revisiones de PR o discusiones tecnicas. Ejemplo: `/layouts?flow=ca_matrix_list>ca_matrix_view>competencyTree>ca_competency_create` debe abrir la vista de Layouts con los 4 nodos resaltados, sus aristas marcadas, y el panel lateral mostrando el "camino".

## Scope

### IN

- Nueva query string `flow` en la vista `/layouts` con formato `id1>id2>id3>...` (separador `>`)
- Resaltado visual: nodos del path con anillo dorado; aristas del path con color intenso; resto atenuado
- Panel lateral "Flow trace" con:
  - Lista ordenada de layouts del recorrido
  - Tipo de arista entre cada par consecutivo (navigate, modal, record-list, ...)
  - Si el link entre dos pasos no existe como arista → marcar como "gap" con propuesta de correccion
- Boton "Copiar link" que genera la URL actual
- Boton "Construir flow" interactivo: click en nodos sucesivos va construyendo el path; al terminar, URL se actualiza
- Extension del formato para otras vistas:
  - `/eventos?flow=case:closed>on-case-closed-upu>Up1Notification` (evento + flow + nodo interno)
  - `/componentes?flow=CompetencyTreeElement>useCompetencyTree` (componente + composable)

### OUT

- Ejecucion real del flow (solo visualizacion)
- Persistencia de "flows favoritos" (podria ser BLY-007)

## Requirements funcionales

| REQ | Descripcion |
|-----|-------------|
| REQ-01 | Parsear query string `flow` en formato `id1>id2>id3` con tolerancia (espacios, url-encoded) |
| REQ-02 | Resolver cada id contra el modelo de la vista actual (Layouts, Eventos, Componentes segun ruta) |
| REQ-03 | Si un id no resuelve → panel muestra warning con "no se pudo resolver"; recorrido se corta en ese punto |
| REQ-04 | Entre cada par consecutivo, identificar la arista del tipo correspondiente; si no hay arista directa, marcar "gap" |
| REQ-05 | Resaltado visual: nodos path con ring + aristas del path con color especifico (ej. dorado #f59e0b); resto con opacity 30% |
| REQ-06 | Panel "Flow trace" abajo del grafo (o lateral) con lista ordenada, tipo de arista, cross-link a detalle de cada paso |
| REQ-07 | Boton "Copiar link" copia URL exacta incluyendo la query `flow` |
| REQ-08 | Modo "Build flow": click en nodo agrega al path; click en nodo ya incluido lo remueve hasta ahi; boton "Reset" limpia |
| REQ-09 | Formato `flow` compatible con las 3 vistas (Layouts, Eventos, Componentes) con misma sintaxis `>` |
| REQ-10 | Si el path tiene un gap, proponer el "siguiente paso mas probable" segun aristas existentes del ultimo nodo resuelto |

## Design tecnico

```typescript
// src/types/flowTrace.ts
export interface FlowStep {
  nodeId: string;
  resolved: boolean;
  kindHint: string | null;    // 'layout' | 'component' | 'event' | 'flow'
}

export interface FlowEdgeInPath {
  fromNodeId: string;
  toNodeId: string;
  edgeType: string | null;    // del catalogo de la vista; null = gap
  isGap: boolean;
}

export interface FlowTrace {
  steps: FlowStep[];
  edges: FlowEdgeInPath[];
  unresolvedAt: number | null;   // indice del primer step no resuelto
}
```

### Composable

```
src/composables/useFlowTrace.ts
```

Exports:

```typescript
export function useFlowTrace(model: Ref<NodesAndEdges>): {
  path: Ref<string[]>;
  parsed: ComputedRef<FlowTrace>;
  highlight: ComputedRef<{ nodes: Set<string>; edges: Set<string> }>;
  addStep: (id: string) => void;
  removeFrom: (id: string) => void;
  reset: () => void;
  asQuery: ComputedRef<string>;
  copyLink: () => Promise<void>;
};
```

El composable es generico respecto al modelo: funciona con `{ nodes, edges }` donde cada edge tiene `from`/`to`/`type`. Cada vista (Layouts, Eventos, Componentes) lo consume pasando su modelo.


### Formato URL

Forma estandar:

```
/{vista}?flow={id1}>{id2}>{id3}
```

Encoding: `>` se mantiene literal en la query (URLSearchParams lo acepta). IDs con caracteres especiales van url-encoded.

### Consideracion core + mods

El recorrido puede cruzar libremente:

- `core_layout > mod_layout > core_element`: valido, sin restriccion
- Resaltado aplica igual a ambos
- Si un id es un layoutType base (sin archivo), se resuelve desde `coreCatalog.ts` y se marca con badge "core"
