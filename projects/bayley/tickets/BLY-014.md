# Mostrar object/tipo target en rowActions, tabs y record-list embebidos

## Request

En el DetailPanel (BLY-009) las referencias a otros layouts (rowAction.targetLayoutId, tab.associatedLayoutId, schema record-list.layoutId) se muestran como el id del layout destino — pero no se ve **que object se abre** en el modal/vista. Ejemplo:

```
Crear Factor → hw_factor_create    🔒 mod/...
```

El usuario no sabe si eso abre un RecordDetail de HwFactor, HwAssessment u otro sin clickear.

Fix: al resolver la referencia contra el modelo, mostrar `objectName · layoutType` a la par del id.

```
Crear Factor → HwFactor · RecordDetail (hw_factor_create)    🔒 mod/...
```

## Scope

### IN

- Helper en `useLayoutsStore` o composable: `findLayoutById(id): LayoutNode | null`
- DetailPanel Estructura:
  - **Row actions**: si `targetLayoutId` resuelve, mostrar `objectName · layoutType` + id abajo
  - **Tabs (associated)**: idem para `associatedLayoutId`
  - **Schema fields (record-list)**: idem para `layoutId` del campo
- Mantener badge ⚠ para targets que no se encuentran (dangling)
- Incluir layouts runtime (ya en el modelo tras "Cargar runtime") en la resolucion

### OUT

- Vista agregada "Modales y navegacion" por object en HierarchyTree (queda para follow-up si sirve)
- Fetch automatico de targets que no estan cargados (el usuario carga runtime manualmente)
- Cross-link cascada (click → DetailPanel del target → resolver todo recursivo)

## Tasks

1. Agregar getter/method `findLayoutById` al layouts store
2. DetailPanel: helper local `resolveTarget(id)` que devuelve `{ node, label } | null`
3. Enriquecer filas de rowActions / tabs / schema-fields para mostrar object + type
4. Manejar caso layout runtime-db (badge DB tambien en el link)
5. Test e2e con Playwright
