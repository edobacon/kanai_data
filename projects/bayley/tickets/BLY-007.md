# Navegabilidad real de layouts via app.json

## Request

El parser de layouts actualmente usa el campo `applicationId` del layout JSON como heuristica para decidir si es navegable o auxiliar. **Esto es incorrecto**: en UP1 real, la mayoria de layouts no declaran `applicationId`, pero SON navegables porque aparecen en `mods/{mod}/config/app.json`. Consecuencia: en Bayley todos los layouts aparecen como "auxiliares" en el DetailPanel, y ninguno muestra URL abierta en UP1.

Fix: extender el parser para leer `app.json` de cada mod, cross-referenciar con los layouts, y marcar cada `LayoutNode` con `isNavigable` y `app` correctamente.

## Contexto real de UP1

Cada mod tiene `mods/{mod}/config/app.json`:

```json
{
  "name": "assessment-matrix",
  "label": "Assessment Matrix",
  "icon": "bi-mortarboard",
  "order": 50,
  "tenants": ["TEST", "UPU"],
  "roles": ["Admin", "Coordinador"],
  "version": "1.0.0",
  "defaultObjects": [
    { "objectName": "CaCompetencyMatrix", "layoutId": "ca_matrix_list" },
    { "objectName": "CaLevelScheme", "layoutId": "ca_levelscheme_list" }
  ]
}
```

`defaultObjects` declara cuales son los **layouts entry-point** de la app. Los sub-layouts con el mismo `objectName` (p.ej. `ca_matrix_drafts`, `ca_matrix_published`) se muestran como dropdowns del tab padre en la sidebar de UP1.

### Categorias de navegabilidad

| Tipo | Ejemplo | Criterio |
|------|---------|----------|
| **Entry-point** | `ca_matrix_list` | Aparece en `defaultObjects[].layoutId` de algun app.json |
| **Sub-listado** | `ca_matrix_drafts`, `ca_matrix_published` | Mismo `objectName` que un entry-point del mismo mod (dropdown) |
| **Auxiliar** | `ca_matrix_create`, `ca_matrix_view` | No matchea ninguno de los dos (se abre como modal desde rowActions) |
| **Core reportbuilder** | `report_list` | Siempre navegable (el workspace los expone) |
| **Core defaults** | `default_Category_view` | Auxiliares generados para objects sin layout custom |

```typescript
export async function parseLayouts(fs: FsAdapter): Promise<LayoutsModel> {
  const [scanResult, appsResult] = await Promise.all([
    scanLayoutFiles(fs),
    scanApps(fs),
  ]);

  const nodes = scanResult.files.map((f) => {
    const { node, anomalies } = extractLayout(f);
    return node;
  });

  // Nuevo paso: aplicar navegabilidad

  const { edges, anomalies: edgeAnomalies } = detectEdges(nodes);
  return assembleModel(nodes, edges, [...scanResult.anomalies, ..., ...appsResult.anomalies]);
}
```
