# Vista Apps: grafo de navegacion y acciones del usuario partiendo de una app

## Summary

### What was requested

Nueva vista **Apps** en bayley — exploracion visual read-only tipo Vue Flow que grafique el flujo de navegacion y acciones del usuario partiendo de una app, con POC contra `hello-world-mod` como referencia.

### What was done

Lo que el dev puede hacer ahora que antes no podia:

- Abrir `/#/apps` y seleccionar una app (hello-world, engagement, etc.) para ver un grafo con el AppNode raiz + todos sus LayoutNodes derivados del menu (RecordList con landing) + sub-layouts (view/edit/create) + TabNodes extraidos de los RecordDetail + ObjectNodes vinculados.
- Ver **row actions agrupadas** dentro de cada LayoutNode por seccion (Header / Row actions / Detail actions) y por objeto target. Las acciones implicit (Ver/Editar/Eliminar/Crear) se sintetizan a partir de `canView/canEdit/canDelete/canCreate` del layoutConfig — no requieren estar declaradas explicitamente.
- **Expandir on-demand** sub-modales clickeando el handle de un row action. Cycles se detectan y dibujan como edges rojos dashed con label `↻` en vez de recursar. Depth maxima 4.
- **Deep-link bidireccional**: `/#/apps?app=hello-world` carga la vista con esa app pre-seleccionada. La URL se actualiza al cambiar de app. Al volver desde DataModelView el grafo se reconstruye (via `watch immediate`).
- **Deep-link field → DataModel**: click en un field de un LayoutNode (via `FieldNavLink`) navega a `/#/datamodel?entity=X`. Field param (`?field=Y`) pendiente — backlog B1.
- **Sidebars retractiles**: derecho (DetailPanel con JSON raw del layoutConfig), izquierdo (filtros por tipo de layout / objeto).
- **Orchestrator IDs** visibles — cada layout real se asigna a un Orchestrator (`O-N`) que los tabs del mismo layout heredan. Util para entender "que monta que".
- **Colores semanticos** en edges: modal violet, navigate blue, create emerald, cycle red dashed, dangling red dotted.
- Integracion con sidecar runtime ya existente (BLY-011) — endpoints `/api/apps`, `/api/apps/:name`, `/api/runtime-layout/for-object/:objectName`.

## Request

Construir una nueva vista en bayley llamada **"Apps"** — herramienta de exploracion visual (read-only) tipo Vue Flow que grafique el flujo de navegacion y acciones del usuario partiendo de una app.

**Motivacion del dev:**

Las 3 vistas actuales de Layouts (Grafo, Jerarquia, Flow) no resuelven este caso de uso: no permiten responder a simple vista "¿si hago click aqui, que se carga?". El dev necesita graficar, desde la app como punto de partida, todas las opciones de navegacion y accion del usuario, para poder debuggear contra el codigo.

**Lo que debe mostrar (todo en el mismo grafo, interactivo):**

1. **App** → sus layouts y objetos asociados
2. **Menu/barra superior** → opciones y a donde navega cada una
3. **Row actions** de listados → si abren modal, que layout/objeto carga el modal
4. **Pestañas** de layouts → que cargan
5. **Campos** de objetos en cada layout → con link al datamodel para ver el objeto completo

**Alcance inicial**: POC con `hello-world-mod` como app de referencia.

**Modo**: solo lectura.

**Fuente de datos**: sidecar runtime (SPEC-runtime-sidecar) — layouts/objetos reales de la DB via object-manager. Es la fuente mas fidedigna segun el dev.

### Decision arquitectonica (confirmada)

**Opcion 4 — Hibrido ER + listas dentro de nodos (patron B de comunidad Vue Flow)** confirmada por el dev.

**Tipos de nodo:**

| Nodo | Estilo | Items internos | Handles |
|------|--------|----------------|---------|
| **AppNode** | Header + menu de navegacion | Items del menu superior. **Cada item con dropdown muestra las opciones del dropdown (submenu) agrupadas debajo del item padre** | Por item de menu → al layout/objeto target |
| **LayoutNode** | Header con tipo (RecordList/RecordDetail) + label | Items agrupados por seccion: `Tabs` (si tiene), `Row Actions` (agrupados por su propia tabla/contexto — **NO lista plana**), `Fields` (solo los navegables o con condicion). Cada grupo es colapsable | Por item → a layout/modal/objeto target |
| **ObjectNode** | ER-style (reutiliza `EntityNode` de DataModel) | Fields con tipo y badges (PK, FK, unique). Click en field → deep-link a DataModelView con entidad seleccionada | Solo en fields con FK visible |
| **ModalNode** | Variante visual de LayoutNode (color distinto, indicador "modal") | Igual que LayoutNode | Igual |

**Agrupaciones obligatorias dentro de nodos (clarificacion del dev):**

1. **En LayoutNode**, los row actions **deben mostrarse agrupados**, no como lista plana. Agrupacion por:
   - Su seccion de origen en el layout (header actions vs row actions de tabla vs actions de detail)
   - Su objeto target (si hay multiples actions que navegan al mismo modal/layout, se agrupan)
   
2. **En AppNode**, cada item de menu con dropdown debe renderizar las opciones del dropdown **visualmente agrupadas debajo del padre** (indentacion + separador), no como items hermanos planos.

3. **Edges salen del item especifico**, no del nodo contenedor — handles por item para que sea claro "este row action especifico lleva aqui".

**Referencias de implementacion:**
- Patron "listas dentro de custom node" recomendado en Vue Flow Discussion #1391 (evita el hack de `hidden: true` recursivo).
- NO usar `parentNode`/subflows Vue Flow nativos — limitaciones conocidas (DOM siblings, dagre mal, no collapse nativo).
- Reutilizar `EntityNode.vue` de DataModel para ObjectNode.
