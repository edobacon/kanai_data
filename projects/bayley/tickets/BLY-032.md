**Decision tecnica (DEC-LOCAL-05) — desviacion respecto a B3 confirmado:**

El handoff confirmo B3: "Split stores/app.ts en multiples Pinia stores" con propuesta `useWorkspaceStore + useSidecarStore + useOverlayStore + useSnapshotStore`.

**Implemento un middle-ground**: modules pattern dentro de un solo `defineStore`. Razones:
1. **Riesgo de migracion**: 12 consumers de `useAppStore` (App.vue, router.ts, useScan, useSidecarPolling, 5 shell components, SandboxView, 2 tests) requirien cambios coordinados para split puro. El blast radius es mayor que el ROI.
2. **Cohesion**: muchas funciones cruzan concerns (pickFolder llama initSidecarFromFolder, restore llama checkSnapshotAvailable + refreshOverlayMeta + initSidecarFromFolder). Stores Pinia separados forzarian inter-store calls, perdiendo la simplicidad del store unificado.
3. **Espiritu cumplido**: la guideline `max ~400 lineas` se respeta (380 final). Cada module tematico es testeable independientemente; si en el futuro se quiere migrar a Pinia separados, los modules son los building blocks naturales.

Si este middle-ground no satisface, follow-up ticket: convertir cada module en un `defineStore` separado y migrar consumers (trabajo bien delimitado por module).

**Discoveries / Learns:**
- **L13**: cuando un store Pinia tiene >12 consumers y funciones que cruzan concerns, el split puro multi-store es mucho mas invasivo que su ROI. El **modules pattern** (factories internas dentro de un solo `defineStore`) preserva la API publica del store y zero consumer changes, mientras moderniza la organizacion interna. Es un step intermedio valido.
- **L14**: las factories que toman `deps` como objeto explicito (`createOverlayState({ workspaces })`) son mas flexibles que las que importan refs globalmente — facilita testing y futura migracion a stores Pinia separados.
- **L15**: writable computeds (con get/set delegando al state per-workspace) son boilerplate repetido. Extraer a una factory `createActiveWorkspaceComputeds(deps)` reduce ~50 lineas duplicadas y centraliza la convencion "workspace activo = current".
