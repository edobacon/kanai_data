## Sessions

### Session 1 — 2026-05-09 — diagnostico + fix de los 22 errores

**Tipo:** auto
**Validation tier:** T1 (build + tests + type-check + lint + format:check OK).
**Session goal:** llegar a 0 errores en `npm run build` para que tickets siguientes (BLY-035 e2e, BLY-036 LLM-review, BLY-037 docs) arranquen desde un baseline limpio.

**Diagnostico:**

Tras instalar `@types/wicg-file-system-access` (BLY-040 hipotesis H1), el `npm run build` seguia fallando con los mismos 22 errores. Eso pareciait sugerir que el extends de `@vue/tsconfig/tsconfig.dom.json` no aplicaba lib correctamente en build mode.

Test diagnostico clave:
- `vue-tsc -p tsconfig.app.json --noEmit` → 0 errores (clean).
- `vue-tsc -p tsconfig.node.json --noEmit` → reproduce los 22 errores.

**Root cause real (rejecto H1+H3, confirmo H2 ampliado):** `tsconfig.node.json` incluye `tests/**/*.ts`, y los tests importan transitivamente archivos de `src/` (composables, parsers, utils) que usan `window`/`document`/`FileSystem*Handle`. TypeScript sigue las imports e incluye los archivos importados en el closure del compile. Como `tsconfig.node.json` tenia `lib: ["ES2023"]` sin DOM y `types: ["node"]` sin FSA, todos esos archivos fallaban — aunque sintacticamente "pertenecen" a tsconfig.app.json.

**Issue secundario detectado durante la ejecucion:** una vez corregidos los lib/types, `vue-tsc -b` (build mode) **ignoro `noEmit: true`** y empezo a emitir 165 archivos `.js`/`.vue.js` en `src/`, `tests/`, `sidecar/`, `vite.config.js`. El comportamiento original (sin emitir) se enmascaraba porque vue-tsc abortaba con errores antes de llegar a la fase de emit. Con type-check pasando, build mode emite por defecto. Solucion: cambiar el script `build` de `vue-tsc -b` a `vue-tsc --noEmit` (consistente con `type-check`).

**Discoveries / Learns:**
- **L1**: cuando un tsconfig de tests incluye `tests/**/*.ts`, el closure transitivo de imports puede arrastrar archivos `src/` aunque esos archivos pertenezcan logicamente a otro tsconfig. El lib/types del tsconfig que **inicia** la compilacion es el que se aplica — no el tsconfig que "incluye" el archivo en su `include`.
- **L2**: `vue-tsc -b` (build mode con project references) ignora `noEmit: true` y emite cuando el type-check pasa. El setup original se "salvaba" del emit por accidente (los errores TS abortaban antes). Para type-check + bundle Vite, `vue-tsc --noEmit && vite build` es la forma correcta.
- **L3**: el setup original era fragil: cualquier fix de tipos hubiese disparado el emit accidental. Que el repo no tuviera 165 .js commited fue suerte (probablemente el dev nunca dejo pasar el type-check + build sin errores).
- **L4**: WICG File System Access **no esta en DOM lib estandar** — requiere `@types/wicg-file-system-access` aparte. Util para apps que usan FSA para leer carpetas locales (caso de bayley).

**Tiempo invertido:** ~25 min efectivos (diagnostico fue lo mas largo, ejecucion del fix fue rapida).
