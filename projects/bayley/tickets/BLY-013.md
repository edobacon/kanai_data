# Sidecar FS adapter — leer UP1 local via endpoints para testing automatizado

## Request

File System Access API requiere user gesture, bloquea testing con Playwright (`Failed to execute 'showDirectoryPicker' on 'Window': Intercepted by Page.setInterceptFileChooserDialog()`). Para poder probar flujos completos de Bayley en modo automatizado, el sidecar (que corre en Node y tiene acceso al fs) expone endpoints de lectura limitados a una ruta UP1 configurada. Bayley detecta el modo via query param y usa un adapter HTTP en vez de FSA.

## Scope

### IN
- Sidecar: nuevo `UP1_ROOT_PATH` en `.env.local`
- Endpoints `/api/fs/exists`, `/api/fs/read`, `/api/fs/walk`
- Validacion de path: rechazar `..` y asegurar que todo queda dentro de `UP1_ROOT_PATH`
- `/health` expone `upRoot: string | null` para que el frontend sepa si esta disponible
- Bayley: `createSidecarFsAdapter()` implementando `FsAdapter`
- Landing page: boton "Usar UP1 local (sidecar)" si `upRoot` esta configurado
- Query param `?fs=sidecar` auto-activa el adapter

### OUT
- Write operations (solo read)
- Ruta configurable desde la UI (solo via `.env.local`)
- Multi-root simultaneo

## Tasks

1. Sidecar: agregar `UP1_ROOT_PATH` opcional a config + endpoints fs
2. Validacion de path traversal + resolve contra upRoot
3. `/health` devuelve `upRoot` si esta configurado
4. Bayley: adapter HTTP implementando `FsAdapter` (mismo interface que node/fsa)
5. Landing: boton condicional + URL param auto-activate
6. Test e2e con Playwright

## Acceptance

- [ ] Con `UP1_ROOT_PATH` seteado, `/health` reporta `upRoot: <path>`
- [ ] `GET /api/fs/read?path=../../../etc/passwd` → 400 rechazado
- [ ] Landing muestra boton "Usar UP1 local (sidecar)" si upRoot disponible
- [ ] `http://localhost:5173?fs=sidecar` arranca el scan sin abrir FSA
- [ ] Playwright puede navegar y ver la jerarquia/layouts cargados
