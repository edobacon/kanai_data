## Request (original)

Agregar a Bayley una vista `/componentes` que catalogue todos los componentes Vue custom: los de mods (`mods/*/modsComponents/`) y los base del core (`layout/src/components/`, `layout/src/modsComponents/`). Por cada componente muestra que composables usa, que queries/mutations GraphQL ejecuta, desde que layouts se invoca, y que props expone.

Responde: "¿si toco este composable, que componentes afecta?"; "¿este custom element se usa desde algun layout?"; "¿hay componentes huerfanos (declarados pero nunca invocados)?".

## Scope

### IN

- Parser `parsers/components/` que escanea archivos `.vue` de:
  - `mods/*/modsComponents/**/*Element.vue` — custom elements Vueform
  - `mods/*/modsComponents/**/*.vue` fuera del patron Element — componentes standalone
  - `layout/src/components/**/*.vue` — atoms / molecules / organisms del core (para catalogar "base")
  - `layout/src/modsComponents/**/*.vue` — copia post-sync de componentes de mods (marcar como "synced-copy" para no duplicar)
- Parser de composables: `mods/*/modsComposables/**/*.ts|*.js` y `layout/src/composables/**/*.ts|*.js` / `suite/composables/**/*.ts|*.js`
- Extraccion para cada `.vue`:
  - `defineElement({ name })` si aplica → tipo exportado (usado como `type: "..."` en layouts)
  - `defineComponent({ name })` o `<script setup>` → nombre
  - Imports de composables (cross-link)
  - Queries GraphQL detectadas: `gql\`...\``, `useQuery(...)`, `apolloClient.query(...)`, `apolloClient.mutate(...)`
  - Props declaradas (`defineProps`)
  - Emits declarados (`defineEmits`)
  - Uso de `useTenantApolloClient()` (indicador de interaccion con API)
- Cross-ref desde layouts: para cada componente con `defineElement({ name: "Foo" })` (→ type `foo`), buscar layouts que usen `type: "foo"` en su schema
- Vista `/componentes` con tabla + grafo lateral
- Filtros por mod/core, tipo (Element / standalone), con/sin queries, huerfanos
- Deep-link `/componentes?component=CompetencyTreeElement`

### OUT

- Parsing AST completo (Vue SFC complejo). Usar regex tolerante + lectura de bloques `<script>`
- Ejecutar componentes (solo catalogacion estatica)

## Design tecnico

```typescript
// src/types/components.ts
export type ComponentKind = 'vueform-element' | 'standalone' | 'atom' | 'molecule' | 'organism' | 'synced-copy';

export interface ComponentNode {
  name: string;                       // del defineElement o inferido
  kind: ComponentKind;
  filePath: string;
  mod: string | null;                 // null = core
  layoutType: string | null;          // tipo usado en layout JSON (kebab-case del name sin "Element")
  props: Array<{ name: string; typeHint: string | null; required: boolean; default: unknown }>;
  emits: string[];
  composables: string[];              // nombres de composables importados
  graphql: Array<{ kind: 'query' | 'mutation'; operationName: string | null; raw: string }>;
  usesApolloClient: boolean;
  syncedCopyOf: string | null;        // si es synced-copy, path original en mods/
}

export interface ComposableNode {
  name: string;
  filePath: string;
  mod: string | null;
  graphql: Array<{ kind: 'query' | 'mutation'; operationName: string | null; raw: string }>;
  usedByComponents: string[];         // resuelto en post-procesamiento
}

export interface ComponentsModel {
  components: ComponentNode[];
  composables: ComposableNode[];
  orphans: string[];                   // names de componentes sin invocacion
  duplicates: Array<{ name: string; paths: string[] }>;
  anomalies: Anomaly[];
}
```

### Parser

```
src/parsers/components/
├── index.ts
├── scanVue.ts             # walk de paths de componentes
├── extractVue.ts          # regex tolerante sobre .vue: defineElement, defineComponent, defineProps, defineEmits, imports, gql
├── scanComposables.ts     # walk de paths de composables
├── extractComposable.ts   # regex sobre .ts/.js: export function use*, gql
├── crossRef.ts            # matchea layouts → components (requiere LayoutsModel)
└── validate.ts
```

**Paths escaneados**:

1. `mods/*/modsComponents/**/*.vue`
2. `mods/*/modsComposables/**/*.ts|*.js`
3. `layout/src/components/**/*.vue` (si accesible) — atoms/molecules/organisms
4. `layout/src/modsComponents/**/*.vue` — detectar `synced-copy` matcheando nombre con el mod real
5. `suite/modsComponents/**/*.vue` (destino de sync adicional)
6. `layout/src/composables/**/*.ts`
7. `suite/composables/**/*.ts`

**Extract regex** (tolerante, no AST):

- `defineElement\(\s*\{\s*name:\s*['"]([A-Za-z0-9_]+)['"]`  → name
- `defineProps\s*<\s*\{([\s\S]*?)\}\s*>` o `defineProps\(\{[\s\S]*?\}\)` → props
- `defineEmits\s*\(\s*\[(.*?)\]` → emits
- `import\s+\{([^}]+)\}\s+from\s+['"](?:@/composables|..\/..\/modsComposables)\/([^'"]+)['"]` → composables
- `gql\s*\`\s*(query|mutation)\s+(\w+)?[\s\S]+?\`` → graphql operations
- `useTenantApolloClient\s*\(` → flag usesApolloClient

Si la extraccion falla, registrar anomaly `extract-incomplete` con filePath + detalle. No crashear.

### Consideracion core + mods

| Caso | Tratamiento |
|------|-------------|
| Componente base del core (ej. Button en `layout/src/components/atoms/`) | Kind = atom/molecule/organism segun path; `mod: null`; no tiene `layoutType` (no se invoca desde layout JSON) |
| Componente de mod (`CompetencyTreeElement.vue`) | Kind = vueform-element; `mod: assessment-matrix`; `layoutType: "competency-tree"` |
| Copia sincronizada en `layout/src/modsComponents/` | Kind = synced-copy; `syncedCopyOf: mods/.../CompetencyTreeElement.vue`; marcar como "no es source de verdad" |
| Composable core (`useTenantApolloClient`) | `mod: null`; usado tipicamente por muchos componentes de mods |
| Componente de mod que importa composable core | Link cross-ref con `mod: null` del composable |
