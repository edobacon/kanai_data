# Cero config — sidecar arranca sin creds y se autoconfigura desde `.env` de UP1 via FSA

## Request

> "correr bayley con sidecar sin pasar por engorrosas configuraciones"

Eliminar la friccion del onboarding: hoy el dev tiene que copiar `sidecar/.env.example` a `sidecar/.env.local` y completar manualmente `OBJECT_MANAGER_URL`/`TENANT_ID`/`AUTH_TOKEN` antes de arrancar Apps/Layouts. La feature unifica workspaces y delega la carga de creds al browser via File System Access API.

**Nota**: ticket retroactivo. La feature ya esta implementada en WIP no commiteado al momento de abrir este ticket (2026-05-08). Se formaliza para preservar el trabajo y desligarlo del ticket BLY-028 (auditoria) que comparte el numero `028` por colision en comentarios de codigo.

## Triage

Refactor de runtime config + onboarding UX. Cambio chico en LOC pero **transversal en flujo**: toca el ciclo de vida del sidecar (uninitialized → initialized via POST), el contrato browser↔sidecar (nuevo endpoint `/api/config/init`), y la simplificacion del modelo de workspaces (3 → 2: `up1`, `up1-cache`, `embedded`).
