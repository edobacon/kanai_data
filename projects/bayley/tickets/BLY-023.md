# Eliminar vista Layouts y dependencias huerfanas — preservando AppsView

## Request

Eliminar todo el codigo exclusivo de la vista **Layouts** (LayoutsView + componentes + stores/composables huerfanos + ruta + tests de hierarchy) manteniendo intacta la capa de datos compartida con AppsView (tipos, parsers, `useRuntimeLayouts`, `utils/layoutStyle`).

**Motivacion del dev**: la vista Layouts (3 modos: Grafo, Jerarquia, Flow) no entrego el valor esperado. El caso de uso que pretendia cubrir lo resuelve hoy la vista **Apps** (BLY-016). La tab ya se oculto en BLY-019 (commit `c318e57 chore: ocultar pestana Layouts en TabNav`), pero el codigo sigue en el repo — este ticket formaliza la limpieza.

**Fuera de alcance**:
- Eliminar `parsers/layouts/*`, `types/layouts.ts`, `useRuntimeLayouts`, `utils/layoutStyle.ts` — son consumidos por AppsView (`types/layouts`), `components/apps/*` (`layoutStyle`), `useAppsGraph/Expand` (tipos), y `useRuntimeLayouts` vive como cliente HTTP del sidecar para AppsView.
- Renombrar la capa B a "apps-only" (posible candidato para BLY posterior si queda evidente tras esta limpieza que la nomenclatura ya no refleja el uso real).
- Touchear AppsView/`components/apps/*`.

## Triage

Refactor **bajo riesgo** — 4-5 tasks. El analisis previo identifico con certeza los consumidores: la capa B (tipos + parsers) y parte de C (useRuntimeLayouts, layoutStyle) las usa AppsView; el resto es huerfano una vez que LayoutsView desaparece.

Complejidad: la remocion es mecanica (Grep + delete + type-check). El riesgo esta en:
- `ScanSnapshot` actualmente contiene `layouts: LayoutsModel` — si AppsView o algun otro consumer lee `snapshot.layouts`, hay que preservarlo o eliminarlo coherentemente.
- Fixtures en `tests/fixtures/sample-up1/` son compartidas entre `tests/parsers/layouts.test.ts` (que se mantiene) y `tests/composables/useLayoutsHierarchy.test.ts` (que se elimina). Borrar solo las fixtures exclusivas de hierarchy.
- `ensureLayoutsStateLoaded` u otros side-effects en routers/guards que pudieran esperar el store layouts.
