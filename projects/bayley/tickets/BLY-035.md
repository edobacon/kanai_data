**Discoveries / Learns:**
- **L1**: `<RouterLink>` envolviendo `<button>` (patron de Vue Router) hace que Playwright matchee tanto el rol `link` como `button` en strict mode. Usar `.first()` o limitar al `nav` parent es el patron correcto para localizar tabs.
- **L2**: `getByText('SCOPES')` con texto que aparece en multiples lugares (sidebar filters titles + stats) requiere `.first()` para no fallar strict mode. Alternativa: usar locator parent + getByText interno.
- **L3**: el `webServer.reuseExistingServer: true` evita doble spawn cuando el dev ya tiene `npm run dev` corriendo. En CI con `CI=1` lo desactiva — comportamiento deseado.
- **L4**: el embedded workspace cubre el flujo "Pick → DataModel render" sin necesidad de FSA mock — los assets bundleados (43 objects + 424 fields) son suficientes para validar el grafo. El path FSA real (con `showDirectoryPicker` mock) queda como follow-up si se quiere.
- **L5**: `page.route()` para mockear sidecar es minimo intrusivo y mas rapido que spawnear el server real. Util para tests que validan feature-gate (capabilities.hasSidecarRuntime) sin acoplar a un sidecar live.

**Failed approaches:**
- Primera version del test "5 tabs" usaba `getByRole('link').or(getByRole('button'))` — fallo por strict mode. Iteracion: limitar al `nav` parent + selector exacto por rol especifico.

**Tiempo invertido session 1:** ~50 min efectivos (setup config + 3 suites + ajustes strict mode).
