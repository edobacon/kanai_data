**Discoveries / Learns:**
- **L1**: `vite.config.ts test.environment: 'node'` por default es correcto — los specs de parsers/composables son CPU-bound y no necesitan jsdom. Activar jsdom selectivamente con `// @vitest-environment jsdom` per-spec mantiene el test runtime rapido.
- **L2**: `@vue/test-utils` con `mount(Component, { global: { plugins: [router, pinia] } })` funciona out-of-the-box para smoke tests de views — no requirio mocks del store mas alla de stub minimo. La barrera de entrada para smoke tests es muy baja en este stack.
- **L3**: para BLY-032, los 5 specs de `app.test.ts` cubren las 4 primitivas que el split debe preservar: (1) activeWorkspace setter/reader, (2) pickerForced auto-reset, (3) recordSnapshot/snapshotOf con slot por overlay, (4) capabilities computed.
