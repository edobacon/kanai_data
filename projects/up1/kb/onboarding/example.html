La filosofía central
Una tarea = una carpeta.
Todo lo relacionado, junto.
🗂️

Centralización

Inputs, outputs, notas y contexto en un lugar. Retomar el trabajo es abrir un archivo.

🧠

Continuidad

El README de cada tarea es la memoria operacional. El agente lo lee al iniciar y lo actualiza al terminar — sin intervención manual.

📈

Conocimiento acumulado

Cada sesión enriquece la base de conocimiento. Investigaciones validadas que potencian cada acción futura.

📋

Trazabilidad automática

Cada artefacto generado queda registrado con su versión, fecha y contexto. El historial se escribe solo.

💻

Todo desde el IDE — sin cambiar de ventana

El agente corre dentro de VS Code vía Claude Code — con skills, commands y MCP integrados. Tareas, queries, maquetas, Jira, Confluence, BD: todo desde el mismo lugar.

Estructura del workspace

Todo tiene su lugar predecible

⚙️
.claude/commands/ + skills/ 16 slash commands: 9 manuales + 7 skills con auto-trigger
🧠

📋

Cada tarea activa tiene su carpeta:

008-tributacion-masiva/
├── README.md ← índice + notas de sesión
├── brief.md ← contexto + fuentes usadas
├── inputs/ ← specs, PDFs, screenshots
├── requerimiento_v3.docx
├── flujo_v1.md
└── mockup_v3.html

El README es la memoria viva de la tarea. Se actualiza automáticamente cada vez que el agente genera un artefacto.

Cómo está construido

Las capacidades de Claude
que hacen posible esto

/commands
¿Qué es?
Archivos .md en .claude/commands/. Al invocar /comando, Claude lee el archivo y ejecuta el proceso completo.
Cómo lo uso
9 commands auto-contenidos: leer contexto, generar borrador en chat, iterar con feedback, guardar al confirmar.
/req-doc /mockup /support
skills
¿Qué es?
Módulos en .claude/skills/ con descripción semántica. Claude los activa automáticamente cuando detecta que la conversación entra en su dominio.
Cómo lo uso
7 skills: /task, /support, /db-context, /sql-query, /db-support, /research, /notebook. Se disparan solos por contexto.
db-context sql-query + extensible
MCP
¿Qué es?
Model Context Protocol — estándar abierto que permite a Claude conectarse con herramientas externas en tiempo real. El agente puede leer, escribir y actuar en esas herramientas directamente.
Cómo lo uso
Lee tickets Jira, publica en Confluence, consulta Gmail y Calendar — sin salir del IDE, sin copy-paste, sin cambiar de contexto.
Jira Confluence Gmail Calendar
memory + context

Cómo lo uso

juntos

3 actividades prácticas — 20 minutos

🔌
1. Conectar Jira
Instalar MCP de Atlassian y verificar que Claude puede leer un ticket.
📝
2. Tu CLAUDE.md
Crear tu primer archivo de contexto persistente. Claude te "conoce".
⚡
3. Tu primera Skill
Crear una skill que resuma tickets de Jira automáticamente. Sin código.

Prerrequisito: Claude Code instalado en VS Code. Extensión: claude-code

Actividad 1 — 5 minutos

Conectar Claude
con Jira

1️⃣
Abrir Claude Code en VS Code
Panel lateral o Ctrl+Shift+P → "Claude Code: Open"
2️⃣
Instalar MCP de Atlassian
Escribir en Claude:
Install the Atlassian MCP server
3️⃣
Autorizar en el browser
Se abrirá una ventana de Atlassian → Permitir acceso → Volver a VS Code
4️⃣
Verificar conexión
Escribir en Claude:
Lee el ticket USUITE-13429

✅ Si Claude muestra el título, estado y descripción del ticket...

¡Conexión exitosa!

Claude ahora puede leer y actuar sobre cualquier ticket de Jira, buscar issues por JQL, ver estados y transiciones — todo desde el IDE.

¿No funciona? Verifica que tienes acceso al proyecto USUITE en Jira. Si el OAuth falla, intenta cerrar y abrir VS Code.

Actividad 2 — 5 minutos

Tu primer
CLAUDE.md

Abrir demo/CLAUDE.md y completar:

# Mi contexto - **Rol:** [tu rol en uPlanner] - **Proyecto:** [en qué trabajas] - **Regla:** Responde siempre en español y sé conciso.

Guardar el archivo. Luego preguntarle a Claude:

¿Qué sabes sobre mí?

Claude usará tu contexto
para responder

Este archivo se carga automáticamente al inicio de cada sesión de Claude Code.

¿Qué puedes poner en un CLAUDE.md?

  • 👤 Tu rol y responsabilidades
  • 📐 Estándares y convenciones de tu equipo
  • 🚫 Cosas que Claude NO debe hacer
  • 📂 Estructura de tu proyecto
  • 🔗 Referencias a documentación interna
Actividad 3 — 10 minutos

Tu primera
Skill

Abrir demo/.claude/skills/ticket/SKILL.md

El archivo ya tiene el contenido. Revisemos qué hace:

--- name: ticket description: > Lee un ticket de Jira y genera un resumen estructurado. TRIGGER when: el usuario menciona un código de ticket como USUITE-1234 o PROJ-567. --- # Resumen de ticket Jira Cuando detectes un código de ticket: 1. Leer ticket con MCP (getJiraIssue) 2. Mostrar resumen estructurado: ## [CÓDIGO] — [título] - Estado, Prioridad, Reporter - Cliente, Módulo ### Descripción (3-4 líneas) ### Siguiente paso sugerido

Anatomía de una Skill:

📛

name + description

El nombre es como se invoca. La descripción le dice a Claude cuándo activarla automáticamente.

🎯

TRIGGER when

Claude lee esta sección y decide solo cuándo la skill aplica. No necesitas invocarla manualmente.

📋

Instrucciones

Lenguaje natural. Le dices qué hacer, en qué orden, y qué formato usar. Sin código.

Actividad 3 — Probar la skill

Momento de la verdad
USUITE-13429

Escribir en Claude (solo el código del ticket):

USUITE-13429

Claude debería:

  • 🔍 Detectar que es un código de ticket (auto-trigger)
  • 📖 Leer el ticket de Jira via MCP
  • 📋 Generar el resumen estructurado
  • 💡 Sugerir siguiente paso

Acabas de crear una automatización

Sin código. Sin API keys manuales.
Solo un archivo .md con instrucciones en lenguaje natural.
