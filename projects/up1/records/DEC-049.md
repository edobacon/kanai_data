# `requiresComment` y audit rico de transicion se difieren a P3/DataLog (perdida #2 confirmada)

## Context and problem statement

El workflow del mod (era anterior a P4) exigia comentario en 3 transiciones de Activity y `auditCapture.handleTransition` producia `changeLog action='StateTransition'` con nombres ES + `workflowTransitionHistoryId`. Post-migracion al enum engine de core (T103 P4), el guard cae al `Activity:update` generico -> `action='Update'` con enum crudo, sin comentario ni historyId.

## Decision drivers

- Enum engine de core NO tiene hook para `requiresComment`
- Audit rico de transicion necesita senal semantica que el generico no captura
- Ya es el comportamiento aceptado de Curriculum (workflow-less, no tenia rich audit)
- P3 (DataLog) cubre el audit polimorfico de writes genericos + cambios derivados
- Scope-discovery de T103 marco la perdida como PENDIENTE desde el inicio

## Considered options

### Option A: A) Hook custom `requiredCommentForTransitions` en `versioningConfig`
- **Pro**: Extensible
- **Con**: Nuevo engine, refactor amplio, requiere aprobacion core team

### Option B: B) Pre-transicion resolver wrapper
- **Pro**: Mod-only
- **Con**: Duplica logica de `enforceEnumTransitions`, fragil

### Option C: C) Audit via DataLog siempre
- **Pro**: Sin nuevo motor
- **Con**: Depende de P3; ya cubierto por spec


## Decision outcome

**Chosen option**: Diferir `requiresComment` + audit rico de transicion al feature de DataLog (P3 spec cubre el audit polimorfico). Aceptar el delta como perdida #2 documentada. El comentario obligatorio de esas 3 transiciones se difiere a un futuro epic (no scoped a ningun ticket actual).

## Consequences

### Positive
- Alineado con P3
- No custom engine
- Simplicidad
- Aceptado por dev durante scope-discovery

### Negative
- Perdida funcional: 3 transiciones de Activity ya no exigen comentario (cambio vs workflow engine)
- Audit temporal degrada: `action='Update'` en vez de `action='StateTransition'`
- Si el cliente pide restaurar, requiere nuevo epic + posible re-introduccion de hook
- Dead code: `auditCapture.handleTransition` queda como dead code (inocuo pero ruido)

## Confirmation

Aprueba dev durante T103 S5 scope-discovery. Marcar la perdida como PENDIENTE en docs del spec + busqueda de futuros ticket que la cubra.
