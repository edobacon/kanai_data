# Code RAG injection benchmark: Hybrid Grep+Semantic for S1.T2

> Superseded by DEC-039. Este archivo queda solo como registro historico del duplicado creado durante la iteracion.

## Context and problem statement

Simulación del phase A+ (Code RAG Injection) en task S1.T2 del SPEC-curriculum-design-fix-picker-selection-icon-curation. El phase A+ inyecta contexto relevante (archivos target, consumidores, rules) antes del phase B (developer) para evitar bugs conocidos y respetar contratos existentes.

## Decision drivers

- Aumentar accuracy del developer en tareas que modifican código existente
- Evitar bugs de hidración (RULE-019) y ARIA (RULE-002) que ya están documentados
- Inyectar consumidores cross-file para prevenir breaking changes

## Considered options

### Option A: A: Grep-only
- **Pro**: Rápido, preciso para lookups exactos
- **Con**: No captura contexto conceptual (patrones, behaviors)

### Option B: B: Semantic-only
- **Pro**: Captura contexto conceptual rico
- **Con**: Débil para lookups exactos de rule-by-ID

### Option C: C: Expand index
- **Pro**: Max coverage
- **Con**: Requiere cambio al indexador, no inmediato

### Option D: D: Hybrid (elegido)
- **Pro**: Combina lo mejor de A+B: exacto + conceptual, sin cambio de infra
- **Con**: Costo marginal de 2 queries (Grep + Semantic)


## Decision outcome

**Chosen option**: Hybrid Grep+Semantic (option D): Grep para lookups exactos (rule-by-ID, consumer search) + Semantic para contexto conceptual (patterns, behaviors)

## Consequences

### Positive
- Inyecta 2 rules relevantes (RULE-019 should + RULE-002 must) que el developer ahora lee antes de codear
- Identifica 6 consumers cross-file (tests + layouts) — el developer sabe qué romper
- Gate PRE-CODE-RAG validado: decision 'executed' registrada

### Negative
- +35s por task de overhead (aceptable para tareas T1+)
- RULE-curriculum-design-019 no es recuperable por semantic search (necesita grep como fallback)
