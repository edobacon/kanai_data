# Arquitectura multi-mod: mod packs en un solo server + prefijo de tools cd_*/eng_* (breaking)

> **ACTUALIZACION (2026-08-27)** — **Vigente**: mod packs en un solo server + prefijos breaking (as_/cd_). **Cambio el mecanismo**: el MCP nuevo descubre packs por carpeta (discoverModPacks en src/mods/index.js), NO hay "manifiesto append-only src/mods/index.ts" ni lista MODS; y es JavaScript, no .ts. Ver DEC-058 y los learns de TICKET-137 (desfase MCP viejo/nuevo).

## Context and problem statement

Abrir el MCP a un segundo mod (uengagement) con equipos separados exigía decidir el modelo de aislamiento entre equipos y cómo desambiguar las tools de distintos mods (§12.E).

## Decision drivers

- Habilitar trabajo en paralelo de 2 equipos minimizando la superficie de colisión.
- Costo de build/infra razonable.
- Buena experiencia del usuario (un solo login) y del LLM (una superficie correlacionable cross-mod).
- El MCP está en 0.1.0 / uso interno → romper nombres es barato.

## Considered options

| # | Option | Description |
|---|--------|-------------|
| A | Mod packs en un solo server | cada mod en `src/mods/<mod>/`, manifiesto append-only |
| B | Monorepo multi-paquete con CI por mod | más aislamiento formal, más costo de build |
| C | Dos servers MCP | aislamiento total, pero 2 logins OTP y peor UX del LLM |

### Desambiguación
- Prefijo directo `cd_*`/`eng_*` (breaking, sin alias) vs nombres planos con aliases deprecados.

## Decision outcome

**Chosen option**: A (mod packs en un server) + **prefijo `cd_*`/`eng_*` breaking, sin alias**. Cada mod es una carpeta autocontenida auto-registrada vía `ModPack`; el único archivo compartido es el manifiesto append-only `src/mods/index.ts` (1 línea por mod). El contrato `ModPack` se diseña para que migrar a B sea mecánico.

**Justification**: A entrega ~90% del aislamiento a una fracción del costo de B; C castiga al usuario y al LLM. El prefijo breaking evita arrastrar deuda de alias en 0.1.0 interno.

## Consequences

### Positive
- 6 archivos de colisión → 1 línea por mod; equipos trabajan en paralelo.

### Negative
- Romper nombres planos previos (search_programs → cd_search_programs).

### Mitigations
- Aceptable en 0.1.0 / uso interno; registry con guard de unicidad (S33) evita colisiones de objectType.
