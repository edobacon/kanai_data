# Alta de electivas en lotes: checker todo-o-nada (rollback completo si algun prerequisito falta)

## Context and problem statement

El alta de electivas soporta `activityIds: string[]` (lote). El checker `checkPrereqsForBatch` aplica reglas de prerequisitos al lote completo.

## Decision drivers

- Rollback B2 de `createElectivaEntries` espera atomicidad
- Consistencia con `createInstance` (transaccional)
- UX: usuario edita lote completo no item-por-item
- Simplicidad de testing vs partial-state

## Considered options

### Option A: A) Bloquear solo las actividades problematicas
- **Pro**: Mas permisivo
- **Con**: UX peor (cliente espera todas o ninguna), inconsistente con rollback B2

### Option B: B) Aplicar las validas primero
- **Pro**: Maximiza throughput
- **Con**: Race conditions, partial state, UI compleja

### Option C: C) Confirmar cada faltante individualmente
- **Pro**: Grano fino
- **Con**: UX pesima, no escalable para lotes >5


## Decision outcome

**Chosen option**: Si cualquier actividad del lote tiene faltantes de prereqs, bloquear el lote completo (cero mutations). Tx rollback completo.

## Consequences

### Positive
- Atomicidad (tx unica)
- UX consistente con rollback B2
- Simple de testear (todo-o-nada)
- Cero partial-state

### Negative
- Lotes grandes pueden ser bloqueados por 1 sola actividad
- El cliente debe corregir el lote completo antes de re-intentar
- No hay progreso parcial visible
