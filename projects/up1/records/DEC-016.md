# cd se adapta al modelo reducido de engagement; engagement es inmutable desde cd

## Context and problem statement

El merge de develop trajo la reduccion del org spine de engagement (PR#9, commits 9c6b077/42f55f3): engagement es canonico de Organization/Institution/OrgUnit y redujo su modelo (OrgUnit sin recordType academico ni institutionId inline; RTs Campus/Faculty/SupportCenter). curriculum-design (SP4, UPONE-1261) dependia de campos que ya no existen. Hay que decidir el principio que gobierna la adaptacion: quien cambia para reconciliar.

## Decision drivers

- engagement es canonico del org spine — su modelo es la verdad
- no acoplar cd al roadmap/equipo de engagement: cd no debe bloquearse esperando cambios en otro mod
- minimizar coupling cross-mod y mantener ownership claro
- cd debe poder estar funcional ('arriba') con el modelo actual de engagement sin negociar cambios externos

## Considered options

### Option A: A — pedir a engagement reinstaurar recordType academico y/o sembrar el org spine
- **Pro**: menos reescritura en cd; el modelo academico viejo se conserva
- **Con**: acopla cd al roadmap de engagement, viola 'engagement canonico', bloquea a cd esperando a otro equipo/mod

### Option B: B — cd se adapta (elegida)
- **Pro**: cd autonomo y desbloqueado; respeta engagement canonico; ownership claro
- **Con**: mas cambios en cd (seeds/resolver/objeto/tests); cd queda como seeder de facto del org spine


## Decision outcome

**Chosen option**: Vivir con los cambios de engagement tal como estan (inmutables desde cd). Todo lo que cd necesite para funcionar con el modelo reducido se implementa como CAMBIOS EN CD. No se solicitan cambios a engagement: ni reinstaurar un recordType de ejecucion academica, ni que engagement siembre el org spine. Si cd llegara a necesitar distinguir governance/execution a nivel de nodo, lo resuelve por su cuenta (rol por FK de AcademicProgram, o un marcador/extension propio de cd), no pidiendolo a engagement.

## Consequences

### Positive
- cd se desbloquea sin depender de cambios en engagement
- ownership claro: cd duena de su adaptacion
- mapeo Academic* -> Faculty + rol por FK queda confirmado como definitivo (no hay fallback a opcion A)

### Negative
- cd carga con toda la adaptacion (TICKET-076 / caso A)
- cd asume ser el seeder de facto del org spine (Organization/Institution) — caso F resuelto como 'cd crea lo que necesita', sin pedir a engagement que siembre

## Confirmation

Directiva explicita del dev (2026-06-20): 'hay que vivir con los cambios que hizo engagement, pero lo que necesita cd para estar arriba con esos cambios deben ser cambios en cd'.
