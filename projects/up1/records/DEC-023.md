# Re-anclar el MCP a model-v2 sin adaptar al drift del tenant UPU

> **SUPERSEDED (2026-08-27)** — Aplica al mod **engagement**, que NO esta portado al MCP nuevo (su about hoy solo expone academic-scheduling y curriculum-design). Relevante solo si se porta engagement. Ver DEC-058 y los learns de TICKET-137 (desfase MCP viejo/nuevo).

## Context and problem statement

model-v2 cambió el modelo de engagement (Service pasó a Activity{recordType=Service}; Offering ancla a `activityLineId`→ActivityLine; inscripción/asistencia migró de `userId`→`studentId`→Student). El tenant UPU tiene un schema **híbrido/drift** (`OfferingEnrollment`/`Attendance` con `userId` Int NOT NULL viejo + `studentId` nuevo), que bloquea la escritura de engagement.

## Decision drivers

- Mantener el código del MCP correcto respecto al modelo canónico (model-v2).
- No introducir deuda que se rompa al regenerar el baseline de UPU.

## Considered options

| # | Option | Description |
|---|--------|-------------|
| A | Re-anclar a model-v2, NO adaptar al drift del tenant | elegida |
| B | Adaptar temporalmente al schema híbrido de UPU | rompería al regenerar el baseline |

## Decision outcome

**Chosen option**: A — el código del MCP se re-ancla a model-v2 (Activity:Service, activityLineId, studentId). La validación de escritura de enroll/attendance queda **diferida** hasta regenerar el baseline de UPU a model-v2 limpio (trabajo del object-manager, no del MCP).

**Justification**: adaptar al drift introduce deuda que se rompe al limpiar el tenant; el drift es un problema de DATO del tenant, no del código del MCP.

## Consequences

### Positive
- Código del MCP correcto y a prueba de futuro.

### Negative
- Escritura de engagement (enroll/attendance) bloqueada hasta regenerar UPU.

### Mitigations
- Diferido explícito en el backlog (TICKET-080); lectura de engagement funciona.

## Confirmation

- S24/S25 — lectura validada; escritura bloqueada documentada como drift del tenant.
- Al regenerar el baseline UPU, la escritura se valida sin cambios de código.
