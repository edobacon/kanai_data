## Decision

Cuando en el proyecto up1 se hable de "el MCP" o "el mcp de up1", se refiere al servidor `@uplanner/mcp` (v0.1.0), cuyo codigo vive en el repo `git@bitbucket.org:uplanner/mcp.git`. En Kanai quedo registrado como el repo `up1-mcp` del proyecto up1 (localPath `~/Workspace/uplanner/up1/mcp/`, defaultRef `develop`), habilitado para `search_project_code`, `read_project_file` y `get_project_file_context`.

Es un workspace propio del monorepo up1, cableado como gitlink (mismo patron que object-manager, layout, suite, flow), no un mod ni una carpeta suelta.

## Que es

Superficie de agentes de UP1: permite que agentes externos que el cliente final ya usa (Claude, ChatGPT, Gemini) operen la plataforma via HTTP + OAuth (Clerk), con la identidad, el tenant y los permisos reales de la persona. No habla con Postgres/Redis directo: todo pasa por la GraphQL API de object-manager, igual que la Suite. Tools declarativas por "ficha" (un motor generico las convierte en tools MCP); los mods se sincronizan con `npm run sync` desde `mods/<mod>/ai/` del monorepo y no se versionan en el repo mcp.

## Drivers

- El MCP es nuevo y no estaba en el grafo de Kanai: su codigo (`src/`, contratos, motor declarativo, `.ai/`) no era legible ni indexable, solo existian referencias sueltas en comentarios de object-manager.
- Necesidad de que Kanai pueda advertir propagacion (DET-16): cambios en objetos/enums/FKs de un mod u object-manager obligan a resincronizar y revisar las fichas del MCP.

## Alternativas descartadas

- No registrar el repo y depender solo de las specs de KB: Kanai razonaria sobre el MCP sin poder leer su codigo real ni su historial git.
- Apuntar a otro checkout (`~/Workspace/up1`): esta desactualizado y sin el `mcp/`; el canonico es `~/Workspace/uplanner/up1`.

## Confirmation

Verificado tras el registro: `search_project_code` sobre up1-mcp encuentra `buildMcpServer` (`src/mcp-server.js:148`) y `registerDeclarativeTools` (`src/tools/register-declarative-tools.js:144`); `get_project_file_context` abre `.ai/CONTEXT.md` con historial git resuelto sobre `develop`.
