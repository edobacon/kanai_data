# La reducción del OrgUnit ES canónica (verificada contra git); cd se adapta a Faculty (S1). Supersede DEC-017, que se basó en un schema local stale

## Context and problem statement

DEC-017 (2026-06-22) revirtió la adaptación cd→Faculty (S1) y cerró TICKET-076 como wont-do, afirmando que "la reducción del OrgUnit NO está viva en core" y que `Base/orgunit.json` "sigue con el modelo viejo (institutionId + enum {Geographic, AcademicGovernance, AcademicExecution})". Esa premisa resultó **FALSA**. Tras no cargar AcademicProgram/Curriculum en UPU, se hizo una **verificación independiente** (agente en contexto limpio, adversarial, read-only sobre el git real).

## Decision drivers

- El código debe alinearse al estado **committeado/canónico** del core, verificado contra git — no a un artefacto generado local que puede estar stale.
- Una decisión previa (DEC-017) se tomó sobre evidencia incorrecta; corregir el rumbo con trazabilidad.

## Hallazgos de la verificación (git real, no artefactos locales)

1. **La reducción ES canónica desde 2026-06-09.** Commits `655cbdd` (2026-06-08) + `42f55f3` (2026-06-09) en object-manager redujeron el `OrgUnit` core: removieron `institutionId` y el enum académico `recordType [Geographic, AcademicGovernance, AcademicExecution]`. En `develop` y en la rama `UPONE-1261-academic-program`, `Base/orgunit.json` está reducido (sin institutionId; `recordType` discriminador genérico) **sin ningún revert posterior**. El OrgUnit del mod `uengagement-up1` es idéntico al Base reducido.
2. **El seed de cd rompe contra el OrgUnit reducido** (más amplio de lo pensado): `_data-aiep.js`/`_data-univalle.js` crashean en el **create** (`orgUnit.create({institutionId, recordType:'AcademicExecution'})`), `_data-academicprogram.js` en el **findFirst**, y `_data-syllabus.js` + `logic/syllabus-offering.resolver.js` en el filtro `recordType:'AcademicExecution'`. Por eso AcademicProgram/Curriculum quedan en 0.
3. **cd→Faculty es la adaptación correcta**: `rt__Faculty__OrgUnit[institutionId, acronym]` + RecordTypes Campus/Faculty/SupportCenter + AcademicProgram con FKs `governanceUnitId`/`executionUnitId` (rol por FK). Es exactamente lo que implementó S1.
4. **El error de DEC-017**: el análisis de S2 se hizo sobre un `prisma/UPU/schema.prisma` GENERADO local **stale** (con el OrgUnit viejo: institutionId + enum académico), porque los artefactos generados no se commitean y el entorno local no se había re-sincronizado tras la reducción. Evidencia: el stash `8fc927e` (rama `fix/UPONE-1261-seeds-model-v2`, 2026-06-12, "pre develop reset") conserva ese OrgUnit viejo. La "verificación empírica" citada por DEC-017 (`orgUnit.create recordType:'Faculty'` rechazado por enum) describía el schema stale, no el Base committeado.

## Decision outcome

**Chosen option**: **Revertir la decisión de DEC-017.** La reducción del OrgUnit es el estado canónico vigente; cd DEBE adaptarse a Faculty (S1). Se re-aplica S1 (commits restaurados via cherry-pick: `bb263bd` fix, `77ce01b` test, `a1231a7` docs; suite 746→748). TICKET-076 se reabre. DEC-016 (engagement canónico, cd se adapta) queda confirmado como rumbo; **DEC-017 queda superseded** por esta decisión.

La validación real (S2) sigue siendo DB-gated: tras un reset/sync canónico desde develop (que produce el schema reducido consistente), el seed cd-Faculty debe crear OrgUnit Faculty + extensión institutionId y poblar AcademicProgram/Curriculum.

## Consequences

### Positive
- cd vuelve a estar alineado con el core canónico (verificado contra git por un tercero independiente).
- Trazabilidad de la corrección: DEC-017 → DEC-018 documenta por qué el revert fue un error (schema stale) y cómo se detectó.

### Negative
- Round-trip de trabajo (S1 implementado → revertido → re-aplicado) por un análisis basado en un artefacto local desactualizado.

## Confirmation

Verificación independiente (agente opus, contexto limpio, adversarial, 2026-06-22) confirmó claims 1-4 contra el git real y marcó DEC-017 como contradictoria con la fuente. Directiva del dev (2026-06-22): "corregir DKC + re-aplicar S1".

## Lección

Antes de concluir que un cambio de modelo upstream "no está vivo", verificar contra el **git committeado del core** (no contra el schema/artefacto generado local, que puede estar stale por falta de re-sync).
