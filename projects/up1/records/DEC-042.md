# Lock-in del contrato `prepareVersionData` workflow-opcional (`needsWorkflow = !!initialStateField`)

## Context and problem statement

Tras T074 (versionado workflow-less), `prepareVersionData` (`object-manager/helpers/version-from-source.js`) generaliza a workflow-opcional: toda la logica de workflow se gatea por la presencia de `initialStateField` en `versioningConfig`. Curriculum es el primer objeto versionable workflow-less (status enum simple, sin `currentStatusId`/`workflow` FK ni relacion `currentstatus`).

## Decision drivers

- Curriculum primer objeto versionable workflow-less (status enum simple)
- prepareVersionData hardcodeado bloqueaba versionar Curriculum (TICKET-065 L6 reproducia `Unknown field currentstatus`)
- Activity (precedente) siempre tuvo workflow
- T074 cerro el hardcode + T065 L6 lo reproduce en plan sin migrar version-from-source

## Considered options

### Option A: A) Flag `workflow:boolean` en versioningConfig
- **Pro**: Explicito
- **Con**: Requiere migration + audit de todos los versionable objects existentes

### Option B: B) Dejar hardcoded a workflow + parche mod-only en createInstance.version
- **Pro**: Sin tocar core
- **Con**: Duplica logica, regresion al migrar activity

### Option C: C) Migrar todo a workflow (agregar workflow a Curriculum)
- **Pro**: Uniformidad con Activity
- **Con**: Expansion de scope, cambio de modelo de negocio


## Decision outcome

**Chosen option**: Gateo por `needsWorkflow = !!versioningConfig.initialStateField`. Sin migration, sin agregar campo nuevo, backwards-compatible. Toda la logica de workflow (include de `currentstatus`/`workflow`, checks `allowsVersioning`/`initialStatusId`, set `[initialStateField]`) se gatea por el flag.

## Consequences

### Positive
- Curriculum se puede versionar
- T074 cierra el gap genEricamente
- Contrato reusable para academicProgram (futuro)
- Zero migration
- El plan v1->v2 (T074) transfiere completo, no solo clone

### Negative
- Objetos futuros sin workflow requieren revision explicita
- Tests deben cubrir el branch `needsWorkflow=false`
- Si un objeto recibe `initialStateField` despues, no hay flag de retrofit
