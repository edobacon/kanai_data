# Schemas adicionales: Rule + Decision (extension HOR-026)

## Request

**Refundacion DKC v2 — Phase 2**. HOR-026 entrego 2 schemas core (`SpecTaskSchema`, `SessionBlockSchema`) que cubren los records con mayor frecuencia de bugs. Quedan **4 records sin schema formal**: Rule, Decision, Bug, Learn. De estos, **Rule y Decision son los mas usados** y los mas susceptibles a drift cuando crecen en cantidad.

**Por que en este sprint**:

1. **Foundation HOR-026 incompleta** sin schemas para los records que se consumen en KB-first (DET-11). Hoy `dkc_search_text` retorna rules y decisions, pero sin schema no podemos garantizar shape consistente
2. **HOR-031 indexa estos records** via embeddings. Con schemas, el indexador puede confiar en estructura (kind, module, scope) y filtrar pre-search. Sin schemas, parsing fragil
3. **HOR-028 entity tracking cross-ticket** se beneficia: entidades referenciadas (rules, decisions) tienen shape validable
4. **Local-only critico**: modelos pequeños (Qwen 30B en M5 Max) producen rules/decisions con drift si no hay schema enforced. Schemas estructurados son prerequisito para fine-tuning dataset coherente (HOR-037 LoRA)

**Posicion en la refundacion DKC v2**:
- Phase 1 (HOR-040): UX live updates HC
- Phase 2 (este ticket): Schemas Rule + Decision — foundation HOR-026 completa
- Phase 3 (HOR-042): Pipeline write→validate→commit

**Alcance acotado**: solo Rule + Decision. Bug y Learn quedan como follow-up (HOR-045 conditional) — tienen menos uso y menos drift observado.
