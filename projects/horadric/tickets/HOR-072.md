# Fix parser HC sessions.ts para shape A+B+C — multi-linea, commit, phase tactic

## Request

Smoke programmatic sobre HOR-071 revelo 3 bugs del parser HC `server/deckard/sessions.ts` que dejaban informacion fuera del modelo al leer el nuevo shape canonical tactic (A+B+C introducido en HOR-071): (1) `extractTasksFromContent` iteraba line-by-line — perdia las lineas continuation con `Cambio:` / `Validado:` y el commit hash que ahora vive en linea continuation queda null; (2) regex de commit `commit \`...\`` solo se aplicaba sobre la PRIMERA linea de la task; (3) `inferPhase` no reconocia `[phase: tactic]`. Fix targeted al parser sin tocar el shape ni romper backwards compatibility con tickets previos.

- **Bugs**: n/a (este fix CIERRA bugs descubiertos de smoke, no estaban registrados en `bugs/`)
- **Specs**: [SPEC-workflow-tactic-work-type-67](../specs/SPEC-workflow-tactic-work-type-67.md) — DEC-LOCAL-03 declara `[phase: tactic]` como header canonical; el parser debe reconocerlo

## Discoveries / decisions

- D1: el bug del parser estaba latente desde HOR-068 (primer tactic) pero solo visible despues de HOR-071 (cuando el template paso a shape multi-linea). Pre-HOR-071 el shape era 1 linea — el parser line-by-line funcionaba accidentalmente
- M1 (micro-decision): preservar backwards compat con shape single-line. El refactor de line-by-line a agrupar-multi-linea conserva el comportamiento para tickets que aun usan shape viejo (HOR-068/069/070 + todos los tickets full-path). Trade-off: codigo del parser ~30 lineas mas largo pero ambos shapes funcionan
- M2 (micro-decision): NO tocar el render HC (Vue components) — el modelo SessionTask gana mas info en `description`, los componentes existentes la renderizan tal cual
