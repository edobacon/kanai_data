# Enriquecer shape canonical de tactic — Tasks + Commits + Summary informativos

## Request

Feedback empirico tras HOR-068/069/070 (los 4 primeros tactics ejecutados): el shape canonical pierde informacion clave para consulta futura. Tres gaps concretos: (1) **Tasks completadas** registran descriptores abstractos sin "que cambio" inline — el dev tiene que abrir el commit diff para entender el cambio; (2) **tabla Commits** no expone la relacion N:M task ↔ commit, queda implicita; (3) **Summary** en prosa libre no se escanea rapido. Ataque: aplicar A+B+C (Tasks enriquecidas con Cambio/Validado/commit · columna Tasks en Commits · Summary estructurado con Que se hizo / Como se valido / Que NO se hizo) en `templates/records/ticket-tactic.md` + `prompts/steps/tactic-execute.md`. NO retroactivo sobre HOR-068/069/070.

- M1 (micro-decision): NO agregar seccion `## Changes` nueva. Razon: overlap con Tasks completadas (que ahora lleva archivo:linea + Cambio inline) y con Summary (que ahora lleva bullets por task). Agregar otra seccion seria 3x redundancia. Trade-off: gana DRY, pierde una sub-pagina "Changes" estilo PR — aceptable porque la info esta en Tasks
- M2 (micro-decision): NO retroactivo sobre HOR-068/069/070. Razon: los 3 tickets estan cerrados con SP executed registrado. Re-editar agregaria commits chore sin valor incremental (la info esta en el ticket aunque en formato viejo); el dev puede consultar el commit diff si necesita detalle. Trade-off: gana consistencia hacia futuro sin overhead de migracion; pierde uniformidad cross-ticket
- D1: el shape enriquecido suma ~10-15 lineas por tactic (HOR-070 paso de 74 a ~85-90 lineas estimadas). Aun bajo overhead full-path; tiempo creacion se mantiene <5min porque el LLM/dev escribe Cambio/Validado durante la ejecucion misma, no como paso posterior
