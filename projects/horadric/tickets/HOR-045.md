# Discoveries/learns/bug tipados con schemas (DKC v2 Phase 4 — conditional)

## Request

**Ticket exploratorio conditional**. Origen: post-refundacion DKC v2. Cubre gap G + extension de HOR-041 a 2 records mas: Bug y Learn.

**Que es**: formalizar 3 tipos de records que hoy son texto semi-libre dentro de sessions/tickets:

- **Discoveries**: texto libre en sessions. Estructura conceptual (D1, D2, ...) pero sin schema
- **Learns**: tabla en ticket (id, raw, refined, status) con shape semi-canonical. Schema lo formaliza
- **Bug**: records propios en `projects/{project}/bugs/{module}/`. Frontmatter consistente pero sin schema

**Por que conditional**:

1. **HOY no es dolor diario**. Discoveries, learns y bugs raramente generan bugs de drift observable
2. **PREREQUISITE para HOR-037 LoRA fine-tuning**: dataset coherente requiere estos records tipados. Sin schema, fine-tuning aprende variance + drift
3. **Util para local-only**: indexer con embedding semantico (HOR-031) puede filtrar mas granular si discoveries/learns tienen schema (kind, scope, severity)
4. **Foundation HOR-026/041 logicamente completa al cerrar este** — los 6 records core (SpecTask, SessionBlock, Rule, Decision, Bug, Learn) con schemas
