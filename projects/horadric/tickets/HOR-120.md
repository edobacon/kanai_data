# Pre-flight lint del scaffold de tickets — atrapa los 3 gotchas sintacticos upfront

## Request

A4 del analisis de "flujo optimo": quitar la friccion recurrente de los gotchas sintacticos del scaffold de tickets, que hoy fallan MID-FLOW con mensajes cripticos (sufridos en vivo HOR-115/116/117). Los 3: (1) listas de frontmatter (`tags`/`rules`/`execute_scope`) con items a ras de columna → el validator zod del Ticket devuelve `null` ("Expected array, received null") aunque el YAML parsee; (2) tabla `### Plan de sessions` con `#` entero pelado (`| 1 |`) en vez de `S{N}` (`| S1 |`) → `dkc-execute-task init-ticket` no la encuentra; (3) header `**Tasks completadas:**` (colon dentro del bold) en vez de `**Tasks completadas**:` → el validator SessionBlock parsea array vacio. Los chequeos existen pero disparan en distintos momentos con mensajes opacos. A4: un comando `dkc-lint-scaffold` que detecta (y con `--fix` corrige) los 3 de una, corrido como PRE-FLIGHT tras scaffoldear el ticket (gate de request-intake), antes de init-ticket. Reusa el patron de fix idempotente (dkc-fix-d1, dkc-fix-date-shape).

### Context found

- **Gotcha #1 (frontmatter lists)**: el validator zod del Ticket (`commands/lib/schemas/`) devuelve `null` para `tags` si los items estan a ras (`- x` en col 0) en vez de indentados 2 espacios. Memoria `reference_deckard_self_dev_gotchas` lo documenta (HOR-115 L).
- **Gotcha #2 (Plan de sessions S{N})**: `dkc-execute-task` `extract_plan_rows` exige `^\| S[0-9]+ \|`. Memoria `reference_dkc_session_plan_table_shape`.
- **Gotcha #3 (Tasks completadas colon)**: `SessionBlock` parsea las tasks bajo `**Tasks completadas**:` (colon fuera del bold). Misma memoria.
- **dkc-fix-date-shape / dkc-fix-d1** — patron de fix idempotente por regex sobre tickets. Modelo para `dkc-lint-scaffold`.
- **RULE-workflow-session-format-canonical-002** — formato canonico de session; el lint #2/#3 lo defiende.
- **DET-32** — reusa el patron de fix-script; el comando es net-new (build) pero minimo.

**Warnings**:
- El `--fix` toca frontmatter/markdown por regex → acotar a los patrones EXACTOS (items `^- ` directamente bajo `^(tags|rules|execute_scope):$`; fila de Plan de sessions con `| {int} |`; el header literal) para no corromper YAML. Default = detect-only; `--fix` opt-in.
- NO duplicar la validacion completa (eso es dkc-validate); el lint cubre SOLO los 3 gotchas sintacticos de scaffold. Complementa, no reemplaza.

**Gaps**:
- ¿Detect-only o auto-fix? Resuelto: detect por default (reporte con linea + fix exacto); `--fix` aplica las 3 normalizaciones (seguras, deterministas).
- ¿Que campos de frontmatter? Resuelto: `tags`, `rules`, `execute_scope` (los que el validator choca). `depends_on` flush no se flagea (el validator lo tolera).
