# Re-surfacing activo de DETs por step — cablear el `dets:` (Flujo B)

## Request

**Origen**: backlog B2 de HOR-085. HOR-085 migró 11 steps a declarar `dets:` en frontmatter y quitó `reads: deterministic-rules.md`, pero dejó el re-surfacing **pasivo**: el `dets:` es metadata declarativa y **ningún body de step instruye activamente** llamar a `dkc_get_rules(dets=...)`.

**Consecuencia (la razón de este ticket)**:

1. En Claude Code el global `~/.claude/CLAUDE.md` inyecta las 30 DETs → el floor se preserva, pero el beneficio de **saliencia point-of-use** (el objetivo real de HOR-085) NO se materializa: nadie trae el set condensado en el momento de uso.
2. En hosts que NO cargan el global (Codex, Cursor, Ollama — multi-provider DET-25/HOR-060) la remoción de `reads:` **redujo la cobertura por debajo del baseline**: esos hosts perdieron el único mecanismo que tenían para ver las DETs.

**Propuesta**: convertir el `dets:` de metadata pasiva en re-surfacing **activo**:

1. Agregar al inicio del body de cada step migrado (los 11 de HOR-085) una instrucción accionable estándar: "Al ingresar a la fase: `dkc_get_rules(dets=<frontmatter.dets>)` para traer los condensados del set que gatea este step."
2. Evaluar reforzarlo con un **a-hook** (patrón de enforcement de 5 capas, RULE-workflow-enforcement-pattern-009) que dispare/recuerde el re-surfacing — o documentar por qué la instrucción de body basta.
3. Cerrar el bucle de REQ-IMPROVE-03 de HOR-085 (que quedó "declarado pero no cableado").

**Prerrequisito habilitador de Flujo A**: sin el re-surfacing activo, A (aligerar el global) no puede ejecutarse — A reemplaza la inyección del global por este mecanismo; sin él, A quitaría el floor sin red.

**Anti-objetivo**: que el cableado agregue ruido/verbosidad a los steps sin beneficio, o que duplique lo que el global ya hace en Claude Code de forma redundante. La instrucción debe ser concisa y de valor real (especialmente para hosts sin global).

**Alcance**:

- `prompts/steps/*.md` (los 11 migrados en HOR-085) — instrucción activa de re-surfacing en el body
- Posible a-hook en steps/templates (capa 5 del patrón de enforcement)
- `prompts/_style.md` — actualizar Principio 12 si cambia la responsabilidad de invocación

**Repos tocados**: `deckard` (prompts). Sin cambios de código del server (el tool `dkc_get_rules(dets)` ya existe — HOR-085 S1).
