# Ruta B mapping pilot — delegacion real a agentes del host Claude Code

## Request

**Continuacion de HOR-025**. En HOR-025 documentamos honesto que el sistema de agentes DKC quedo **declarado pero no operacional**: la sintaxis canonica `> AGENT INVOCATION ...` esta marcada en 4 steps clave (intake/design/execute/_design-shared) pero el host Claude Code no registra los `subagent_type` de DKC (researcher/scribe/developer/reviewer/architect/tester), asi que toda invocacion cae al fallback inline.

Tras evaluacion comparativa (post-HOR-025) entre 2 rutas:

- **Ruta A** — MCP server propio que registre los subagent_types de DKC en el host (alto costo, riesgo de API inestable, 2-3 sessions de impl, beneficio max teorico)
- **Ruta B** — mapear roles DKC a agentes existentes del host (`researcher → Explore`, `architect → Plan`, `reviewer/tester → general-purpose`, etc.). Bajo costo, 1 session de impl, cobertura parcial (4/6 roles ganan aislamiento real)

**Decision del dev (2026-05-15)**: ir con **Ruta B primero como experimento empirico**. Si medicion en 2-3 tickets post-pilot muestra ahorro real de contexto, evaluar HOR-029 (Ruta A) para cerrar gap. Si no, descartar Ruta A.

**Principio guia**: coherente con HOR-025 — medir antes de invertir. La estimacion del 43% de reduccion de contexto en S4 nunca fue observada (proyeccion conceptual). Ruta B nos da medicion REAL con costo bajo.
