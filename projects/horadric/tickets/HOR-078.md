# Enforcement de evaluacion de paralelizacion en design (decision observable T2)

## Request

HOR-024 dejo la heuristica de paralelizacion como check declarativo `[ ]` en el GATE 3 de `_design-shared.md` — facil de saltar (el LLM puede ignorarlo o marcarlo sin hacerlo). El dev pidio el mecanismo mas fuerte para que el LLM no se salte la evaluacion.

**Solucion**: aplicar la convencion T2 (decision observable, HOR-058/HOR-060) — el mismo patron que ya fuerza `agent-invocation`, `teach-intake-0b`, `commit-det-27`. El architect en `design-{tipo}` DEBE registrar una entry `parallelization-assessment` (choice `declared | not-applicable`) que el gate de salida verifica. Sin entry → gate no avanza. No garantiza la decision correcta (eso es juicio del LLM), pero fuerza la consideracion explicita con evidencia auditable (`--reason`).
