# Fix bug recurrente: HC no muestra tasks de sessions cuando se escriben como tabla (causa raiz + UI warning + validator)

## Request

> *(Peticion original del dev, 2026-05-21 en chat de HOR-031)*
>
> revisa porque no se cargaron las tareas en hc, nuevamente deja sin ver datos de avance al dev, hay que corregir la vista y ver la causa, sigue suicediendo muy comunmente

**Origen del descubrimiento**: durante S1 de HOR-031 (POC embedding KB retrieval), el LLM principal escribio las tasks de Session 1 como **tabla markdown** (`| S1.T1 | descripcion | [x] | files |`) en lugar de **lista de checkboxes canonical** (`- [x] S1.T1 — descripcion`). HC viewer no parseo ninguna task — el dev supervisor se quedo "ciego" al avance.

**Causa raiz identificada** (4 puntos estructurales):

1. **Formato ambiguo** — DKC usa tabla en `TasksTable` del spec (HC la renderiza bien) pero **lista de checkboxes** en `## Sessions` del ticket. El LLM se confunde porque la tabla es visualmente atractiva y la rule canonical no es lo suficientemente explicita en el momento de escribir.
2. **No hay validator detector del drift** — `dkc-validate SessionCheckboxes` (HOR-056) valida los checkboxes que existen, no detecta su **ausencia** cuando se uso tabla con IDs `S{N}.T*`.
3. **HC viewer no avisa visualmente** — cuando el parser no encuentra tasks en una session, la session se renderiza vacia silenciosa. El dev no sabe por que.
4. **Template del ticket no incluye ejemplo inline** — el formato canonical vive solo en `RULE-workflow-session-format-canonical-002.md` y no en el template que el LLM rellena.
