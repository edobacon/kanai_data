# Roles DKC como agentes custom del host, con allowlist de tools en vez de prompt-guard

## Request

**Peticion literal del dev** (2026-08-01): "cierra 030 como superseded y crea el ticket de agentes custom".

**Origen**: revision de HOR-030 (Ruta A, MCP server custom que registrara los subagent_types de DKC nativamente). Tres de sus cuatro justificaciones quedaron resueltas por HOR-130 con otro mecanismo (delegacion a un CLI externo con enforcement por sandbox del SO), y su hipotesis H1 —"¿el host expone API publica para registrar subagent_types con capabilities?"— hoy tiene respuesta afirmativa por una via mucho mas barata: el host define tipos de agente en `.claude/agents/*.md`, y de ese frontmatter salen su modelo, su reasoning effort y **su allowlist de tools**, aplicada por el harness y no por un prompt.

**Objetivo**: cubrir el residual que quedo despues de HOR-130 usando el mecanismo nativo del host en vez de infra propia: que los roles DKC que hoy se resuelven a `general-purpose` con prompt-guard (`reviewer`, `tester`) y los que quedan inline por falta de equivalente (`developer`, `scribe`) tengan un tipo de agente propio con su allowlist exacta. Sin MCP server custom: esa parte de HOR-030 envejecio mal y su propio warning lo anticipaba.
