# Cablear StatusCoherence como gate de cierre en request-close

## Request

El validador `StatusCoherence` (HOR-066, `commands/lib/schemas/status-coherence.ts`) detecta drift
entre el status del ticket y su spec referenciado (`status_mismatch`: ticket `closed` con spec aun
`in_progress`; `spec_not_found`: referencia a spec inexistente). PERO no esta cableado como a-hook
de `request-close` — es opt-in manual. Resultado: el drift se acumula silencioso.

Quick win (#1 del analisis de integridad 2026-05-31): agregar `StatusCoherence` al catalogo de
a-hooks de `request-close/transversal.md` + un checkbox bloqueante en el GATE FINAL de
`request-close/gates.md` que obligue a resolver el drift (spec → `done`/`archived`, o reparar la
referencia rota) ANTES de marcar `status: closed`. Forward-only (preventivo); no arregla drifts
retroactivos existentes.
