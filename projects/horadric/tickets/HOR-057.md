# Extender validator SessionCheckboxes a detectar drift en bloque `**Gate decision:**`

## Request

> *(Captura del descubrimiento, 2026-05-17 — HOR-056 close)*
>
> Durante el cierre de HOR-056, el dev observo que Session 6 aparecia como "en ejecucion" en HC viewer aunque todas las tasks estuvieran marcadas `[x]`. Causa: el bloque `**Gate decision:**` de Session 6 tenia los 4 checkboxes en `[ ]` (no marcado). HC infiere el `status` de la session via este bloque — sin `[x] continue`, marca `in_progress`.
>
> El validator `dkc-validate SessionCheckboxes` (HOR-056 capa D) **NO detecto el drift** porque solo parsea checkboxes con id `S{N}.T{M}` o `S{N}.GATE` (regex en `extractTicketCheckboxes`). El bloque `**Gate decision:**` tiene checkboxes textuales (`- [ ] continue`, `- [ ] iterate`, etc.) sin id — el validator los ignora.
>
> Blindspot del validator descubierto en dogfooding de HOR-056. Capa D enforcement funciona para tasks pero queda incompleta para gate decision.

## Summary

### What was requested
Extender el validator `dkc-validate SessionCheckboxes` (HOR-056 capa D) para cubrir blindspot descubierto en dogfooding: el validator detectaba drift en checkboxes de tasks (`S{N}.T{M}`) pero no en el bloque `**Gate decision:**` de cada session ejecutada. HC infiere `SessionStatus` via este bloque — sin `[x]` en alguna option, marca `in_progress` aunque las tasks esten todas done.

### What was done
Extension del validator en `commands/lib/schemas/session-checkboxes.ts` (~110 LOC nuevas): interface `SessionGateDecision` + funcion `extractGateDecisions` (parsea cada session + cuenta marks del gate decision + task stats) + funcion `detectGateDecisionDrifts` (comparator con 3 casos: 2+ marks = error ambiguedad; 0 marks + all tasks done = error drift S6; 0 marks + tasks pending = warning legitimo). Integrado en `detectCheckboxDrift` como step 3. 4 tests sinteticos cubren los 4 casos canonicos. Regression HOR-056 sigue pass (gate decisions ya marcados post-fix).

### What was discovered
- L1 (raw): drift `**Gate decision:**` vs `**Gate decision**:` (`:` adentro vs afuera del bold). Regex tolerante `\*\*Gate decision:?\*\*:?` cubre ambas variantes.
