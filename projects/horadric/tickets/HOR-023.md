# Gates verificables programaticos (guardrails inspirados en CrewAI) — DET-27 enforcement + gates G3/G4 + teach skip body verify

## Request

Post-HOR-022 (cerrado 2026-05-15) y analisis comparativo DKC vs CrewAI, identificada brecha sistemica: los gates DKC declaran "BLOQUEANTE" pero la verificacion depende del LLM auto-validandose. Findings HOR-022 audit S1.T3 documenta 11 agujeros (G1-G11) — 4 de severidad alta (G1, G3, G4, G5) sin enforcement programatico.

CrewAI `guardrails` ofrece patron arquitectonico: funciones programaticas que validan output del agent ANTES de aceptarlo. DKC puede adoptar el patron sin perder portabilidad — guardrails como comandos bash/python invocados como pre-conditions de gate.

**Items a atacar** (absorbe backlog must re-clasificado de HOR-022):

- **G1 — DET-27 commits post-GATE no enforced**: working tree puede quedar sucio post-session sin que el gate sync lo detecte. Fix: `git status --short` como pre-condition del gate → si hay `M` o `??` no esperados, gate falla con mensaje explicito.
- **G3 — DET-25 TCs inline puede saltarse**: gate D dice "BLOQUEANTE" pero verificacion depende del LLM. Fix: si log de task menciona `vitest|tsc|npm test|jest` Y la tabla TC tiene `Actual: —` para TCs de la session → gate falla.
- **G4 — DET-23 Quality review puede omitirse**: gate sync acepta `continue` sin escribir el bloque. Fix: grep `#### Quality review (DET-23)` en session activa antes de aceptar continue.
- **G7 — teach skip silencioso**: gate `_design-shared` GATE 1 acepta `teachings.intake: skipped` sin verificar razon en `## Teaching — Intake`. Fix: grep `**Status**: skipped — .+` en seccion correspondiente → si no encuentra, gate falla.
- **G2 — quick path escalamiento mid-flow**: self-reported sin proxy automatico. Fix: si quick path lleva >3 archivos modificados o >30 min wall-clock → warning sugerido escalate a full path. NO bloqueante (es heuristica), pero documentado.

**Patron CrewAI a adoptar**:

Convertir gates declarativos en verificables — comandos shell o python invocables como pre-conditions:

```
gate.verifications:
  - command: "grep -q '#### Quality review (DET-23)' tickets/{TICKET-id}.md"
    on_fail: "DET-23 quality review ausente en session activa — agregar antes de continue"
  - command: "git status --short | grep -q '^[ MARC?]' && exit 1 || exit 0"
    on_fail: "DET-27 working tree dirty — commit antes de cerrar gate"
```

### Learns promovidos

**L1 — Patron de verifier programatico para gates declarativos**

Los gates DKC declaran "BLOQUEANTE" pero la verificacion historicamente dependia del LLM auto-validandose. Adoptar el patron CrewAI guardrails (comandos shell con exit codes claros) convierte gates declarativos en gates ejecutables. La separacion estructural/semantica (verifier para checks estructurales, LLM judgment para semanticos) evita que el verifier crezca infinitamente. **Candidata a rule**: "Cualquier gate con check de presencia/formato/sintaxis DEBE invocar dkc-verify-gate. Checks semanticos (claridad/mantenibilidad/decision quality) siguen LLM judgment". No promovido en este ticket — emerge si patron se confirma en >=3 tickets adicionales.

**L2 — Bash puro mas portable que Python para tools DKC**

El comando funciona en cualquier shell POSIX sin dependencies. Trade-off explicito: parsing markdown limitado (regex + awk) vs Python con libraries robustas. Para los 5 checks actuales bash es suficiente. Si los checks crecen (ej. G8 que requiera parse de tablas markdown complejas), considerar migracion a Python. **No promovido a regla** — depende del caso.

**L3 — Cross-validation natural durante self-development**

Durante S1.T2 detecte 2 bugs propios (G7 regex, ignore-paths BRE) probando el comando contra HOR-029 (baseline valido). Sin ese test, los bugs habrian llegado a S2 o post-close. Patron: **siempre validar contra outputs reales de casos baseline conocidos antes de declarar S1.GATE continue**. Esto es analogo al insight D11 de HOR-029 (cross-validation researcher+reviewer) pero aplicado a auto-validacion. **Candidata a antipatron documentado**: "no marcar S1.GATE continue sin haber ejecutado el comando/funcion contra >=1 input real conocido".
