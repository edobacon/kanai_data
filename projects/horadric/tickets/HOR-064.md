# Falso positivo del format drift detector: durante la primera task de cualquier session pre-llenada

## Request

Reportado por el dev tras cierre de TICKET-031 (proyecto up1, 2026-05-22): "el ticket 031 cumplio con rellenar las sesiones al iniciar las sesiones del execute, pero puso todas las sesiones en ejecucion y cada vez que comenzaba una sesion aparecia este mensaje: 'Format drift detectado en 1 session: Session 3: Session activa con 1 task in_progress + 5 pending, 0 completadas. Verificar transicion checkbox per-task (HOR-056 capa B + HOR-063): cada cierre de task debe transicionar [~]→[x] ANTES de avanzar a la siguiente'".

El warning aparecio de forma sistematica al iniciar cada session (S1, S2, S3) y desaparecio al cerrar la primera task de cada una. El LLM (Claude Opus 4.7) confirmo que SI hacia las transiciones canonicas `[~]→[x]` per-task via `dkc-execute-task done-task` — el warning es falso positivo.

## Summary

### What was requested

Reportado por el dev tras TICKET-031: el detector de format drift del HC viewer disparaba banner amber al iniciar cada session de tickets multi-session, sugiriendo que el LLM no transicionaba `[~]→[x]` per-task — pero el LLM SI lo hacia. Investigar y resolver el falso positivo.

### What was done

- **Diagnostico**: el flujo `dkc-execute-task init-ticket` exigia stubs canonical de TODAS las sessions execute upfront. Sessions futuras con `**Tasks completadas**:` quedaban marcadas `in_progress` por HC parser. El predicate `isStale` del detector se disparaba durante la primera task de cada session (0 done + 1 in_progress + 5+ pending). Falso positivo durante operacion normal del LLM.
- **Solucion (Opcion B lazy stubs)**: refactor de `cmd_init_ticket` para solo asegurar el stub de S{first_n}. Sessions futuras viven en `### Plan de sessions` subseccion hasta que `open-session N` las active.
- **Fix colateral**: parser regex `markdown.ts:286,301` actualizado para aceptar `[~]` (in_progress) y `[D]` (deferred). Bug pre-existente que TICKET-031 sufrio.
- **Docs**: DET-28 actualizada a singular ("la session actual") + nota lazy stubs post-HOR-064. Mensaje del comando consolidado con DET-29 pre-existing del dev (per OK explicito).
- **Validacion empirica**: HC tests 223/4 = baseline; init-ticket smoke OK; HC viewer post-fix muestra S1+S2 completed (post Gate decision blocks), S3 in_progress, sin banner format drift (dev approval).
