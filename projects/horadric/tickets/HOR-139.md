# Atar el super autopilot de DKC al sistema de permisos de Claude Code

## Request

Cuando un ticket corre en `autopilot: super`, hoy el modo solo cambia el comportamiento del LLM (auto-commit local, no pausar entre sessions), pero **cada acción mecánica sigue pidiendo autorización al harness de Claude Code** (leer, editar, ejecutar comandos). El dolor: durante la ejecución de un ticket hay muchas autorizaciones básicas, y un allowlist amplio (~1600 entradas exactas acumuladas) no lo resolvió porque las entradas literales no generalizan.

Objetivo: que `autopilot: super` **abra los permisos mecánicos a nivel del harness** mientras dura ese ticket (leer, editar dentro de `execute_scope`, ejecutar comandos seguros) sin prompts, manteniendo **frenos duros que SIEMPRE preguntan**. Cuando el ticket cierra o hace standby, todo vuelve a la normalidad. Debe ser **per-ticket**, no un cambio de modo global de la sesión.

Decisiones ya tomadas con el dev (fuera de alcance re-discutirlas):
- **Disparador**: `frontmatter.autopilot == "super"` (+ `execute_scope` declarado) del ticket activo.
- **Mecanismo**: marker-gated PreToolUse hook, mismo patrón que `dredd-guard.py` (inerte salvo marcador), invertido (abre en vez de restringir). NO usar `defaultMode: auto` global (es de sesión, no per-ticket).
- **Alcance de edits bajo super**: scope-bound a `execute_scope` (fuera de scope, pregunta).
- **Frenos duros SIEMPRE preguntan**: `git push`/`merge` a ramas compartidas; destructivos de BD (prisma migrate/db push, tenant:reset, DROP); escrituras externas (Jira/Confluence/PR); `rm`/`mv`/`chmod`/`kill`; y el **close del ticket** (`dkc-set-ticket-status ... closed`), que por DET-30 SIEMPRE pregunta incluso en super.

## Context found

- **DET-30 (red de seguridad autopilot)**: ya define que en autopilot {strict,true,super} hay guarda de inicio (rama + `execute_scope`), cierre reforzado, y que **el CLOSE SIEMPRE PREGUNTA en todos los modos incluido super**. Esta feature es **aditiva** a DET-30: agrega la apertura de permisos mecánicos como contraparte de esa red. Fuente: `prompts/deterministic-rules.md`, `prompts/steps/request-execute/start.md:50` (guarda 0b, ya lee `autopilot` + `execute_scope`).
- **DET-29 (transiciones canónicas)**: toda transición de execute pasa por `./commands/dkc-execute-task <project> <ticket> <op>` (init-ticket, open-session, start-task, done-task). Es el punto natural para el ciclo de vida del marcador. Fuente: `prompts/steps/request-execute/gates.md:29`.
- **`dredd-guard.py`** (`~/.claude/hooks/`): patrón de referencia probado. Hook PreToolUse INERTE salvo que exista `~/.dredd/active.json`; con TTL (3h); fail-open ante error, fail-closed en categorías reconocidas; decide por `permissionDecision` allow/deny/ask. HOR-139 es el mismo patrón invertido.
- **`auto-allow-safe.py`** (`~/.claude/hooks/`): ya implementa denylist-first + auto-allow por subcomando (dkc/git-safe/vitest/lecturas), robusto a `cd &&` y variables. La lógica Bash de HOR-139 **reusa** este enfoque (misma lista DANGER + frenos duros).
- **HOR-079 (`execute_scope`, DET-30 REQ-02/03)**: `execute_scope` es la lista de repos/paths que el ticket puede tocar; ya bloquea la primera task si está vacío en autopilot. HOR-139 lo reusa como frontera de auto-aprobación de edits.
- **Capacidades de Claude Code verificadas** (CLI 2.1.210): `permissionDecision: allow|deny|ask` en PreToolUse hooks; `permissions.ask` prompts mode-independent; modo `auto` existe pero es de sesión (por eso se descarta para per-ticket); `--permission-mode` lista `auto`. Precedencia: para no depender de ask-vs-hook, los frenos duros se enforcan DENTRO del hook (no emiten allow → caen a prompt).

**Warnings**:
- Precedencia entre múltiples PreToolUse hooks Bash (ya hay 4: cd-case, block-nvm, auto-allow-safe, dredd-guard). Un `deny` de dredd-guard debe ganar sobre un `allow` de HOR-139. Se mitiga porque los frenos duros de HOR-139 nunca emiten allow (caen a `{}`), así no compiten con un deny.
- `~/.claude/hooks/` y `~/.claude/settings.json` están FUERA de todo repo; `execute_scope` los referencia por path absoluto/`~`. La verificación de scope del hook debe resolver paths multi-repo + home.
- Un marcador colgado dejaría permisos abiertos: TTL obligatorio (~3h como dredd) + limpieza en close/standby.
