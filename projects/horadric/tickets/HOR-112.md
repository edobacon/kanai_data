# Verificar el self-report de workers antes de declarar exito

## Request

Verificar el self-report de los workers (sub-agentes delegados) antes de reportar exito al usuario o cerrar un gate. Hoy DKC confia en lo que el agente claima (archivo escrito, test verde, build PASS) y eso ha causado fallos reales documentados: un 'build PASS' del sub-agente que no reproducia en el entorno de ejecucion real; un reviewer aislado que dejo reverts staged contaminando el working tree del submodulo de codigo; y un TC cerrado por override sobre un runtime que nunca se ejecuto. gentle-ai lo codifica como REGLA DURA en el skill hermes-ephemeral-delegation: 'Treat worker output as self-report: verify file writes, test pass/fail, URLs, and IDs before reporting success to the user.' Objetivo: convertir esto en parte explicita del workflow DKC (reforzar DET-9/DET-10 o anadir un DET nuevo): todo handoff que claime archivo / test / build / URL se verifica de forma independiente (incluido `git status` del submodulo de codigo tras correr un reviewer aislado) antes de declarar exito. Fuente: gentle-ai @510751e017d308d986bd4b45c249e0b0cf00678f, internal/assets/skills/hermes-ephemeral-delegation/SKILL.md (seccion Hard Rules). Contexto y catalogo en DEC-003.
