# Enforce uso de sub-agentes via convencion T2 (extension HOR-058 al fence `dkc:agent-invocation`)

## Request

Hoy el sistema DKC tiene infraestructura completa para delegar trabajo a sub-agentes:
- **Fence canonico** `dkc:agent-invocation` en 6 lugares de 4 steps (intake-explore, request-intake, request-execute, _design-shared) con shape `role + tier + prompt + fallback`
- **MCP tool** `dkc_invoke_agent` (HOR-054) que resuelve el fence al host LLM correspondiente
- **Tier mapping** `fast | balanced | reasoning` por host LLM (HOR-029)
- **6 roles canonicos** con prompts dedicados en `prompts/agents/*.md` (architect, developer, researcher, reviewer, scribe, tester) — HOR-025

PERO esto es **solo recomendacion** — verificado: 0 validators, 0 a-hooks, 0 gates programaticos. El comentario en `prompts/agent-tiers.md:123` lo dice literal: "El enforcement de `MUST NOT use Edit` via prompt depende de que el LLM del subagente respete el prompt — sin garantia nativa del host". El LLM principal puede ejecutar todo inline (research + edit + reasoning) en su propio tier (Opus tipicamente) y nada falla. Es el mismo patron sistemico que HOR-058 ataco para DET-27 / DET-25 / DET-21-0b — gate verifica resultado pero no que el paso interno (delegacion) se ejecuto.

**Impacto observable hoy** (sin fix):
- **Costo**: tier `fast` declarado en research/scribe se ignora → research va a Opus en vez de Haiku → ~10x el costo del sub-task
- **Context window principal contaminado**: research masivo (grep/glob/read) consume tokens del principal cuando podria estar aislado en sub-agente
- **Drift cross-host**: distintos hosts LLM (Claude Code, Codex, Cursor) divergen en cuanto delegan vs no
- **Determinismo bajo**: misma session puede ejecutarse inline o delegado segun decision ad-hoc del LLM principal

**Fix propuesto**: extender la convencion T2 de HOR-058 con quinto step interactivo `agent-invocation`. Cada vez que un step encuentra un fence `dkc:agent-invocation`, el LLM principal registra entry observable con choice ∈ `{invoked-mcp, fallback-inline, inline-bypass}`. Validator StepDecisions exige cobertura: si el step tiene fence pero no hay entry, gate falla.
