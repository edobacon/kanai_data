# Explore Frente B cross-host — AGENT INVOCATION portable a multiples LLM hosts (reclasificado de improvement a explore)

## Request

**Derivado de HOR-050** (closed 2026-05-16, spec en draft). Implementa la **Solucion B** del SPEC-workflow-directive-enforcement-50.

**Problema que resuelve**:

Las 6 mentions de `> **AGENT INVOCATION (HOR-025)**: subagent_type=researcher, tier=fast, prompt="..."` (en `_design-shared.md`, `intake-explore.md`, `request-intake.md`, `request-execute.md`) son **prosa que el LLM principal lee pero no ejecuta como Agent tool call real**. Medicion HOR-046: 1/40+ invocaciones reales = ~2.5% (D11 capturado).

**Solucion B**: re-escribir las directivas como fence markdown que el harness Claude Code interpreta como `Agent({subagent_type, ...})` directo.

Propuesta tentativa:
```markdown
<!-- enforcement: b-protocol -->
```dkc:agent-invocation
subagent_type: researcher
tier: fast
prompt: "Validar hipotesis {H_id}..."
output_schema: prompts/agents/researcher.md
```
```

El wrapper del harness detecta el fence + parsea YAML + invoca `Agent({subagent_type, ...})`. Si el harness no soporta dispatch desde markdown directo, se requiere **CLI bridge** intermedio (script bash que el LLM principal ejecuta).

**Caveat exploratorio**: si `OPEN-2` del spec HOR-050 (¿harness Claude Code expone API para dispatch desde markdown?) resulta NO, el scope crece — requiere CLI bridge + manual del LLM para invocarlo. En ese caso, considerar derive a sub-ticket.

**Plan tentativo (refinable en intake)**:

1. **Verificar OPEN-2 empirico**: ¿harness permite dispatch desde markdown? POC chico
2. **Refactor 6 AGENT INVOCATION** a fence `dkc:agent-invocation`
3. **Wrapper o CLI bridge** segun OPEN-2 result
4. **Tests**: invocacion real al menos 100% (6/6) post-refactor
5. **Documentacion**: README en `prompts/agents/` actualizado

**Acceptance criteria (de NFR spec HOR-050)**:
- AGENT INVOCATION → Agent real: 17% → 100%
- Inline ratio: 97.5% → < 30% (junto con HOR-051 y HOR-053)
