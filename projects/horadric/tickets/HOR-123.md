# Visor de cambios tipo IDE read-only embebido en la vista de ticket

## Request

Quiero que HC pueda mostrarme lo que va cambiando durante un ticket sin tener que alternar entre el navegador (HC) y un IDE. Necesito una parte dedicada dentro del ticket, que pueda agrandar a pantalla completa o abrir en pestaña nueva para aprovechar el espacio. Debe ser algo similar a una vista de VSCode: una barra lateral con los archivos que se van modificando y otro panel donde se ve el archivo, resaltando el cambio que se esta realizando (antes y despues), con syntax highlighting segun el formato (no colores planos). Algo como un IDE de solo lectura.

### Refinamiento de alcance — multi-repo, navegacion y scope (dev, 2026-06-22)

El dev acota el alcance de la fuente del diff (refina DEC-005):

1. **Enumeracion de repos desde config (reuso)**: el server toma los repos via `enumerateProjectRepos(rootPath, config)` — `repo.path` + `workspaces[]` (si `monorepo`) + `additional_paths[]`. Para horadric: `horadric-cube` (principal) + `deckard` (additional). El endpoint de working-tree itera ese set, igual que el de commits.
2. **Navegacion por repo en el sidebar**: los archivos cambiados se agrupan por repo; con varios repos, una seccion navegable por repo. El `repo.path` principal es la seccion primaria; los `additional_paths`/`workspaces` son secciones adicionales.
3. **Seccion "Otros" (decision dev: scan + declarado)**: ademas de los repos declarados, un **scan acotado** detecta repos git con cambios **no declarados** en config y los agrupa en "Otros" (red de seguridad: nada queda oculto). Parametro abierto para design: el **limite del scan** (`scan_root` + `scan_depth` configurables por proyecto + ignores) — el ancestro comun de los repos de horadric es `~/Workspace`, donde un scan amplio capturaria repos de otros proyectos (ruido). Default a resolver en design-feature.
4. **Exclusion de churn de DKC (H5)**: la regla `projects/**` (+ `.active_project`, `*.db`, asset dirs) aplica SOLO al repo `deckard_root`. Asi:
   - Ticket up1/jormat: cambios en `deckard` (todo `projects/<proj>/…`) ocultos; trabajo en repos up1/jormat visible.
   - Ticket horadric: `deckard/projects/horadric/…` oculto; `deckard/server|commands|prompts` (core DKC) visible; `horadric-cube` visible.

   Importante: el filtro NO es "ocultar el repo deckard" sino "ocultar el subarbol KB del repo deckard" — porque en horadric el core de DKC (codigo real del ticket) vive en `deckard` fuera de `projects/`.

### Re-fundacion del alcance — navegador repo→ticket→sesion + blame (dev, 2026-06-22)

El dev re-funda HOR-123 (via AskUserQuestion): deja de ser primariamente un tab "live de working tree embebido en un ticket" y pasa a ser un **navegador read-only tipo IDE sobre el trabajo**: repo → ticket → archivos cambiados → diff Monaco → filtro por sesion con atribucion estilo blame. El working tree deja de ser el nucleo y pasa a representar "la sesion en curso (sin commitear)" dentro del modelo unificado.

**Request expandido (NO reemplaza el Request original — DET-3):**
1. Navegar entre repos.
2. Dentro de cada repo, ver los tickets con nombre + contexto rapido (no solo el id).
3. Navegar los archivos cambiados en ese ticket; ver antes/despues destacando el cambio (Monaco — DEC-004).
4. Filtrar por sesion del ticket: destacar los cambios de esa sesion; ocultar/deshabilitar los archivos no modificados en esa sesion pero mantenerlos en vista (pertenecen al ticket).
5. Al destacar por sesion, tener al alcance la descripcion de la sesion (contexto semantico).
6. Base conceptual: git blame por sesion.

**Consecuencia de fuente de datos (revisa DEC-005):** la atribucion por sesion y el blame exigen el **delta acumulado del ticket por sesion** (historial commiteado), que DEC-005 habia diferido (F-C). Por lo tanto F-C pasa de "futuro" a **nucleo**; F-A (working tree) se conserva como "la sesion en curso".

**De-risk clave (simplifica vs DEC-005):** el navegador NO necesita "inferir la rama base" (el riesgo que hizo diferir F-C). El delta del ticket se arma con `git log --grep=HOR-123` (convencion DET-27, ya usada por `/tickets/:id/commits`) y se agrupa por el token `-S{N}` del subject del commit. El blame = atribuir cada linea/hunk a la sesion cuyo commit la introdujo, restringido a los commits del ticket. La metadata semantica de la sesion sale de `## Sessions` del ticket markdown (HC ya las parsea).

**Pendiente para design-feature:** REQs y test cases se regeneran (TC1–TC8 actuales asumian working-tree-primario; siguen validos parcialmente pero el set se reescribe). Decisiones abiertas a resolver en design: (a) granularidad del blame (archivo vs hunk vs linea); (b) que es el "antes" del diff (parent del primer commit que toco el archivo vs base del ticket); (c) IA del shell (navegador dedicado vs reuso del shell de tabs actual); (d) fuente del listado de tickets por repo (index.db de DKC vs git) y como se atribuyen commits a tickets en repos sin convencion DET-27 (up1/jormat usan `external`).

### Decisiones de arquitectura (tomadas en exploracion previa, confirmadas por el dev)

> Registradas formalmente como decision records — ver seccion Context found.

1. **Motor de render: Monaco DiffEditor (read-only)** — el motor real de VSCode, cumple "IDE de solo lectura" literal. Alternativas descartadas: CodeMirror 6 merge (mas liviano, menos pulido), diff2html (se ve a diff de PR), custom highlight.js (cero dep pero todo el side-by-side a mano). Riesgo: dep pesada + setup de web worker en Vite 8.
2. **Fuente del diff: working tree en vivo (F-A)** — `git diff` (staged+unstaged) + untracked, multi-repo. Es literalmente "lo que va cambiando ahora". F-B (commits) ya existe para lo historico; F-C (acumulado de rama) queda como evolucion.
3. **Live: SSE + chokidar (L-1)** — extender el patron SSE/EventSource ya montado para empujar `worktree-changed`; el panel re-fetcha. Requiere ignores (`node_modules`, `.git`, `dist`) + debounce.
4. **Superficies en capas** — tab embebido "Cambios" → expand fullscreen (Teleport) → ruta standalone para pestaña nueva.

**Huecos reales a construir (lo que el gate DET-32 marca como `build`):**

1. **Monaco**: NO instalado (`grep monaco package.json` → vacio). Requiere instalar + setup de worker en Vite + `MonacoDiffPanel.vue`. (DEC-004)
2. **Endpoint de blobs por archivo**: Monaco consume original+modificado completos; `getCommitDiff` da patch. Falta `GET .../file?path=&rev=` que sirva el contenido del archivo en una rev dada (HEAD-del-primer-touch / base-del-ticket / working-tree). (DEC-004 H3)
3. **`server/git/blame.ts`**: NO existe. Viable con `runGit(repo, ['blame','--porcelain',hash,'--',path])` + mapear cada hash→S{N} portando `SESSION_REGEX` al server. Limite: solo lineas de commits del ticket son atribuibles (las de commits externos quedan sin sesion).
4. **Agrupacion tickets por repo**: hoy los tickets se listan por PROYECTO DKC, no por repo git. El mapeo proyecto↔repos sale de config. La IA repo→ticket es nueva.
5. **IA del navegador**: ruta/superficie nueva (tab `#changes` y/o ruta standalone). No existe navegador repo→ticket→archivo→sesion.

**Caso abierto (design-feature):** repos sin convencion DET-27 (up1/jormat: commits con `external` id, sin token `-S{N}`) → el grep los encuentra pero `extractSessionNumber` no los atribuye a sesion (caen en `unassignedCommits`). El navegador debe degradar con gracia (mostrar "sin sesion") en esos repos.
