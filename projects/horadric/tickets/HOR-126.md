# Fix: `dkc-mutate` falla en frontend vitest4 (stryker SIGSEGV) — fast-skip graceful

## Request

**Origen**: HOR-125 P1. Fricion F2: `dkc-mutate` (gate DET-31) falla cronicamente en proyectos frontend vitest4 (jormat JOR-055/057/059/060/061). Ejecutado en super autopilot, teach skip.

## Resumen (cierre)

La hipotesis inicial (timeout por coverage-v8) fue **refutada** por verificacion empirica (DET-33). Causa raiz real: **StrykerJS 9.6.1 (el ultimo publicado) crashea el worker de vitest 4.x con SIGSEGV en el dry-run** — no hay fix upstream disponible. Decision del dev (Opcion A): en vez de intentar hacer correr la mutacion, **cortar rapido y honesto** en vitest≥4. Implementado y verificado: el gate ahora retorna `infrastructure_issue` en 0.17s en vez de colgar 5-15 min.

## Triage — causa raiz (VERIFICADA)

| # | Hipotesis | Status | Evidencia |
|---|-----------|--------|-----------|
| H1 (inicial) | Timeout por coverage-v8 heredado + perTest | **REFUTADA** | El fix (coverage off + timeout) no resolvio; ademas `dryRunTimeoutMs` que agregue es opcion invalida en stryker ("Unknown stryker config option") |
| H2 (real) | vitest-runner 9.6.1 crashea el worker de vitest 4.1.x con **SIGSEGV** en el dry-run | **CONFIRMED** | Log full: `Child process exited unexpectedly (SIGSEGV)` x2 → "Test runner crashed". `test.poolOptions removed in Vitest 4` + horadric-cube usa `better-sqlite3` (nativo) |
| H3 | No hay stryker mas nuevo que soporte vitest 4 | CONFIRMED | `npm view @stryker-mutator/vitest-runner@latest` = 9.6.1 (== cache) |

**Causa raiz**: StrykerJS 9.6.1 no soporta vitest 4.x de forma estable — worker SIGSEGV. Sintoma variable (crash ~16s o hang hasta timeout ~300s) → jormat lo veia como "timeout", horadric como "went wrong". Afecta a todo proyecto vitest4.

## Solucion implementada (Opcion A)

En `commands/dkc-mutate`, guard temprano (tras detectar `RUNNER=vitest` + `VMAJOR>=4`, antes de resolver el cache/worktree):
- Corta con salida `infrastructure_issue` (warn-first DET-31, NO bloquea como gap; el consumidor `mutation_tester` ya mapea ese valor a "el dev arregla setup").
- Mensaje claro a stderr + JSON `{recommendation: infrastructure_issue, reason: unsupported_runner_vitest4, ...}`.
- Escape hatch `DKC_FORCE_VITEST4=1` para forzar el intento cuando upstream publique soporte real.
- Documentado en el header del script (LIMITACION vitest >=4) + routing.

**Cambio aditivo y acotado**: solo afecta `vitest major>=4`. Los paths vitest3, jest, mutmut y el fallback embebido quedan intactos (self-test verde). Tooling DKC-owned: cero footprint en repos target; beneficia el gate DET-31 de todos los proyectos vitest4 (deja de colgar).

Alternativas descartadas: B (spike pool:forks — payoff incierto, diferido a backlog); C (downgrade vitest — inviable); el fix de coverage/timeout inicial (revertido, causa equivocada).
