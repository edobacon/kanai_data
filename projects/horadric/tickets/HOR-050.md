# Directive enforcement — sistematizar la diferencia entre lo declarado y lo ejecutado por el LLM

## Request

**Origen**: 3 discoveries in-vivo durante HOR-046 (closed 2026-05-16) con causa raiz comun. Ver tabla abajo.

**Problema sistemico**: el sistema declara directivas en los prompts/steps/templates pero el LLM principal no las ejecuta consistentemente. Las directivas viven en **prosa** (no en codigo ejecutable). El LLM las interpreta como sugerencia textual, no como protocolo enforced. Manifestaciones:

| # | Discovery | Directiva declarada | Comportamiento LLM observado |
|---|-----------|---------------------|------------------------------|
| D2 | cat 10 (HOR-046) | `_design-shared.md:339-348`: *"Inmediatamente despues de producir el spec, ejecutar `dkc-reindex` sincrono"* | LLM trata como sugerencia, ejecuta solo cuando el dev se queja |
| D9 | cat 18 (HOR-046) | `sessions.ts:46`: `StepStatus = 'pending' \| 'in_progress' \| 'executed'` con marker `[~]` (HOR-015 H10) | LLM va de `[ ]` directo a `[x]`, nunca usa `[~]`. Sessions parecen "muertas" hasta cierre |
| D11 | cat 19 (HOR-046) | Steps tienen `> **AGENT INVOCATION (HOR-025)**: subagent_type=researcher, tier=fast, prompt="..."` | LLM lee como instruccion textual, no como `Agent({subagent_type: ...})` real. **~97.5% inline** en HOR-046 (1/40+ invocaciones reales medidas) |

**Por que es critico para LLM-local**:

- Sin enforcement de invocaciones de Agent, proyeccion HOR-029 H4 (25-30% ahorro context via subagents aislados) **NO se cumple**. LLM-local con context 32K depende criticamente de aislamiento via subagents
- Sin auto-reindex enforced, markdown ↔ SQLite drift acumula — LLM-local que consulte SQLite proyectado tendra info stale
- Sin patron `[~]` real-time, sessions interrumpidas pierden estado — LLM-local con interrupciones frecuentes (context limit) sufre mas

**Frentes a explorar (3 caras de la misma moneda)**:

- **Frente E — Enforcement de directivas auto** (D2 base): hooks post-step que ejecutan acciones declaradas como "auto"
- **Frente F — Real-time persistence patterns** (D9): LLM usa `[~]` y persiste DURANTE tasks no al cierre
- **Frente G — Agent invocation enforcement** (D11): protocolos ejecutables vs prosa

**Soluciones tecnicas tentativas** (a refinar en intake-explore):

| Solucion | Pro | Contra |
|----------|-----|--------|
| **A. Hooks Claude Code** (`.claude/settings.json` PreToolUse/PostToolUse) | Funciona HOY con harness existente | Requiere disciplina al instalar; no portable a otros LLM hosts |
| **B. Wrapper de prompts** (steps re-escritos como protocolos ejecutables, no prosa) | Portable, declarativo | Refactor masivo de todos los steps |
| **C. Post-step validator** (check programatico tras cada step) | Reusable con cualquier LLM | Detecta drift post-hoc, no lo previene |
| **D. Schema de step output** (cada step JSON con post-conditions) | Validable + portable + composable | Mas trabajo de modelado por step |

**Sospecha tentativa**: la solucion correcta es **B + C combinados** — protocolos ejecutables + validator post-step. Pero esto se valida en intake-explore.

**Alcance del intake (decision del dev)**:

Grep exhaustivo de directivas tipo `auto`, `obligatorio`, `siempre`, `inmediatamente`, `debe`, `MUST` en `prompts/steps/*.md`. Probable encontrar 10-20 directivas adicionales que el LLM tambien ignora silenciosamente. Output: inventario completo de directivas declarativas + clasificacion (ejecutable hoy vs no-ejecutable hoy).

**Prioridad estrategica (decision del dev 2026-05-16)**:

HOR-050 ANTES que HOR-031 (embeddings). Argumento: "sin enforcement, ningun fix arquitectural se cumple consistentemente, incluido HOR-031 mismo". Coherente — si HOR-031 introduce nuevos commands/hooks pero el LLM no los invoca, no sirve.

**Por que `explore` (no improvement)**:

Produce **modelo conceptual primero** (¿la solucion correcta es A/B/C/D o combinacion?) + spec draft + POC chico (1 directiva implementada con la solucion elegida → measurement empirico). La implementacion completa entra en tickets derivados post-explore.

**No es alcance**:

- Implementar la solucion completa (eso son tickets post-explore)
- Modificar HOR-031 (embeddings sigue separado, retomar despues)
- Refactorear las 25 DETs (HOR-047 lo cubre)
- Resolver Ruta A (HOR-030)
