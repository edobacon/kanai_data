# DKC local-only readiness — bloqueantes de contexto (#1) y superficie de tools (#2)

## Request

Explorar como preparar DKC para correr sobre un host LLM **local-only**, consolidando
los dos bloqueantes identificados en el analisis previo (2026-05-31):

1. **Presupuesto de contexto** — el baseline por turno (~83.7K tokens, medido HOR-059
   2026-05-24) es alto para ventanas locales (128K → 47-78% consumido; 32K inviable).
2. **Superficie de tools** — 78 MCP tools `dkc_*` afectan tanto la precision del
   tool-calling local (mas debil/inconsistente) como el peso de contexto (schemas
   cargados al init en hosts sin carga diferida tipo Ollama).

**Restriccion clave**: AUN NO hay host local disponible. El alcance debe enfocarse en lo
que se puede avanzar **host-agnostico** ("en el medio") y dejar **preparado el terreno**
para cuando llegue el host local. Lo que dependa de un host local real se documenta como
backlog explicito, no se ejecuta a ciegas.

**Subtipo de explore**: `improvement` (optimizar lo que ya existe y funciona — la
maquinaria de reduccion de contexto ya esta construida). El spec resultante queda en
`status: draft` sin pasar a execute (DET: explore no ejecuta).

**Alcance acordado** (AskUserQuestion 2026-05-31): "Mapear + host-agnostico ejecutable" —
spec draft de ambos bloqueantes + identificar y dejar listos para ejecutar los avances que
NO necesitan host local. Lo bloqueado por host local queda como backlog.
