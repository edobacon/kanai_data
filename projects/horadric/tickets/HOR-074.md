# Fix extractSessionNumber: commits tactic (-tactic) → Session 1

## Request

Smoke post-HOR-073 revelo que el chip clickable del task commit (introducido en HOR-073) NO mostraba diff al clickear. Diagnostico: `useSessionCommits.ts:14-22` agrupa commits del ticket por session number matcheando `S{N}` en el subject del commit. Pero los commits tactic usan formato `HOR-XXX-tactic ...` (sin `S{N}`) porque tactic tiene Session 1 implicita (DEC-LOCAL-03 SPEC-67). Resultado: `extractSessionNumber('HOR-072-tactic fix...')` retornaba null → commits tactic caian en `unassignedCommits`, NO en `commitsBySession.get(1)` → `SessionDetailModal` recibia `commits=[]` para Session 1 → `selectCommitByHash` en `filteredCommits` (vacio) no encontraba nada → no diff. Fix: agregar fallback que reconoce `-tactic` como Session 1.

## KB consulted

- **Rules**: n/a (no rules de viewer/parser normativas sobre session grouping)
- **Bugs**: n/a (no estaba registrado; emerge ahora que tactics empiezan a usarse y HOR-073 expuso el flow)
- **Specs**: [SPEC-workflow-tactic-work-type-67](../specs/SPEC-workflow-tactic-work-type-67.md) — DEC-LOCAL-03 (Session 1 implicita) es la fuente conceptual del fix: tactic == Session 1, entonces commits tactic agrupan a 1

## Discoveries / decisions

- D1: este bug estaba latente desde HOR-068 (primer tactic) pero solo emergio ahora porque HOR-073 introdujo el chip clickable que DEPENDE de que el modal reciba los commits correctos. Pre-HOR-073 el dev veia los commits en la tab Commits del ticket completo (sin filtrado por session), entonces el bug era invisible
- M1 (micro-decision): el fix detecta `-tactic\b` (boundary palabra) para no matchear "tactical" / "tactics" como falso positivo. Patron consistente con SESSION_REGEX que tambien usa boundaries (`[\s-]` antes, `[\s.]|$` despues)
- M2 (micro-decision): SESSION_REGEX tiene PRIORIDAD sobre TACTIC_REGEX. Si un subject tuviera ambos (improbable pero defensivo), el `S{N}` gana. Test verifica esto explicitamente
- M3 (micro-decision): aplica solo a Session 1 (== single-session de tactic). Si en el futuro tactic pasa a multi-session (improbable, contradiria DEC-LOCAL-03), habria que extender el fallback. No es escenario actual
