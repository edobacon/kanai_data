# Mutation testing gate para el flujo de DKC

## Request

Agregar mutation testing al flujo de DKC como técnica de aseguramiento de calidad de código,
ubicado de forma que **no enlentezca el flujo**. Origen: revisión del repo de referencia
`github.com/betta-tech/harness-sdd` branch `uncle-bob-harness` (clonado en `/tmp/harness-sdd-review`),
que implementa el proceso de Robert C. Martin con un `mutation_tester` como gate de cierre. La
técnica es valiosa pero su implementación de referencia (`tools/mutate.py`) es naïve: reejecuta la
suite completa por cada mutante — inviable en codebases reales (up1, horadric).

**Objetivo**: usar mutation testing como respaldo **empírico** de la dimensión #4 (testing) de DET-23.
Hoy esa dimensión se juzga subjetivamente por el reviewer; la mutación la vuelve medible. Refuerza
DET-7 (regresión obligatoria) y DET-13 (cierre por evidencia) con medición real, no declarativa.

**Decisiones de diseño ya tomadas con el dev** (en conversación previa, no re-abrir salvo que el diseño lo exija):
- **Ubicación**: ASYNC en `S{N}.GATE`. Al cerrar la session se dispara `dkc-mutate` en un git worktree aislado en background (patrón del reviewer aislado). NO bloquea `S{N+1}`.
- **Alcance**: TODO work_type que toca código testeable (implement, fix, improvement, refactor). quick/explore/query exentos.
- **Reconciliación HÍBRIDA por severidad**: un mutante sobreviviente = test-gap (NO bug de producción → aditivo, seguro de diferir). Crítico (score muy bajo o path crítico) → hardening task al inicio de `S{N+1}` vía G-open. Leve → backlog `must` (DET-17) que bloquea `request-close`.
- **Gating**: WARN-FIRST. Entra como dimensión informativa (warn, no bloquea) mientras se calibra el threshold por stack con datos reales; graduar a bloqueante en T3/exhaustive después.

**Palancas de velocidad (no negociables — el dev fue explícito)**:
1. Mutar solo el diff de la session (`git diff` contra base de session), no archivos enteros.
2. Test selection por cobertura: por mutante correr solo los tests que cubren esa línea, no la suite completa. La palanca grande (10-100x).
3. Aislamiento + async: worktree separado en background.
4. Incremental: cachear, re-mutar solo líneas cambiadas. Mutación corre contra el commit de cierre de `S{N}` (DET-27 da ref estable).
