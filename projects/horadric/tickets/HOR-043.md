# Cross-record relations validation (DKC v2 Phase 4 — conditional)

## Request

**Ticket exploratorio conditional**. Origen: post-refundacion DKC v2 (HOR-040/041/042). Cubre gap B identificado en el analisis 2026-05-16: validacion de relaciones entre records.

**Que es**: hoy spec.tasks referencian REQs, ticket.sessions referencian tasks del spec, decisions referencian rules. Si uno cambia y el otro queda stale, drift silencioso. **Cross-record relations validation** detecta:

- `spec.tasks[S2.T1]` referenciada en `ticket.sessions[2]` pero `S2.T1` no existe en el spec → broken reference
- `ticket.rules: [DET-22]` referenciada pero `DET-22` deprecada/movida → stale reference
- `decision.alternatives: [DEC-005]` pero DEC-005 archived → reference rota
- `spec.requirements: [REQ-IMPROVE-01]` no cubierta por ninguna task → coverage gap

**Por que conditional**: dolor diario NO observable HOY. Drift cross-record es ocasional, no recurrente. Refundacion DKC v2 (HOR-040..042) cubre el 80% del dolor. Este es el 20% restante con costo no trivial (5 SP).

## Conditions for activation (BLOQUEANTE)

Activar SI o SI ocurren UNA o MAS de estas condiciones:

| # | Condicion | Como se detecta |
|---|-----------|-----------------|
| **C1** | >= 3 incidentes de broken references entre records en proximos 3-5 tickets (post-HOR-042) | Documentado en learns con tag `cross-record-drift` |

**Si NINGUNA condicion activa**: HOR-043 queda `open` indefinido. Si HOR-042 cubre suficiente: cerrar como `won't_do` con razon.
