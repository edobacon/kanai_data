# Visibilidad de assets del ticket en horadric-cube — reflejar el flujo de deckard

## Request

Horadric-cube es un **read-only viewer** del flujo deckard. Hoy muestra el `.md` del ticket, las sessions, learns, tasks, flow, commits — pero NO muestra los **artefactos que el flujo deckard ya produce por ticket**:

- **Screenshots**: PNGs junto al `.md` (convencion global `~/.claude/CLAUDE.md:39`). Hoy el viewer los renderiza solo cuando el markdown los linkea inline — pero sin mejora de UX (click abre en pestaña nueva via browser default, no hay lightbox ni caption visible).
- **`tickets/{TICKET-id}.draft/intent.md`**: producido siempre que `design-draft` se invoca. Contiene proposito, inventario, mapping, open questions. **Hoy invisible en horadric-cube**.
- **`tickets/{TICKET-id}.draft/preview.html`**: producido si `creates_visual: true` (ver `prompts/steps/design-draft.md:140`). **Hoy invisible**.
- **`tickets/{TICKET-id}.draft/data-model.{ext}`**: producido si `creates_data: true` (ver `design-draft.md:96`). **Hoy invisible**.

Decision acordada con el dev (sesion #1, iterada):

- **Screenshots — Opcion A (inline + lightbox con contexto)**: NO hay tab separada. El viewer mejora el render inline del markdown: cada `<img>` que apunta a un PNG loose del ticket se envuelve en un hook de markdown-it que muestra thumbnail compacto + click abre lightbox modal con la imagen full-size y el **texto circundante del markdown** (row del TC, bullet de session, caption narrativa). **Principio**: el screenshot nunca se muestra sin el contexto que lo produjo. No hay galeria aislada.
- **Preview.html — Opcion B3**: tab **Draft visual** con iframe embebido + boton "Abrir en pestaña".
- **Data model — Opcion C1**: tab **Data model** — markdown-it + highlight.js + plugin mermaid (dep nueva).
- **Intent.md — Opcion D**: tab **Draft intent** — render markdown-it (reusa pipe existente).

**Principios rectores**:
1. HOR-005 NO modifica el flujo deckard. Solo **refleja** lo que deckard ya produce en horadric-cube. Deckard es la fuente de verdad.
2. Los artefactos **requieren su contexto** para tener valor. Screenshots: contexto en el markdown del ticket (inline). Drafts (intent/preview/data-model): contexto autocontenido en la carpeta `.draft/` — intent.md explica el proposito, preview+data-model son los artefactos que valida. Por eso screenshots NO tienen tab, drafts SI.

|---|----------|---------------|---------|

| 2 | Tab **Screenshots** como galeria agrupada (v1 del draft) | Lista aislada por nombre de archivo descontextualiza el screenshot. Feedback del dev: "los screenshots por si solo no sirven, deben estar incluidos en el contexto que fueron producidos para entender que responden". | Los assets binarios (screenshots) necesitan el contexto textual del markdown para tener valor. | 3 | `VALID_TICKET_ID` regex inicial `^[A-Z]{2,8}-[A-Za-z0-9-]+$` — rechazaba `UP1-012` | Los prefijos de tickets en deckard permiten dígitos (`UP1`, `up1`). El pattern debe aceptar letras + digitos en el prefijo, solo exigiendo letra inicial. | Corregido a `^[A-Z][A-Z0-9]{1,7}-[A-Za-z0-9-]+$`. Test explicito cubre HOR-001, BLY-020, TICKET-005, UP1-012. |
| 4 | `markdownImageHook` v1 solo interceptaba tokens `image` (sintaxis `![](url.png)`) | Tickets legacy (HOR-001, HOR-002) usan sintaxis de link `[text](url.png)` para screenshots — el hook no los transformaba. Detectado en validacion manual de REQ-IMPROVE-02 con HOR-002 Testing tab. | Extendido el hook a detectar links cuyo `href` tenga extension de imagen y reescribirlos como tokens `image`. Cubre ambas sintaxis. Tests nuevos en `markdownImageHook.test.ts`. |
| 5 | `wireInternalLinks` original rompia anchors existentes cuyo texto matchea `RECORD_ID` regex — bug preexistente en HOR-001/HOR-002 que se hizo visible con la feature | El replace sobre HTML no distinguia texto plano de contenido dentro de anchors. Un `<a href="HOR-002-f1.png">HOR-002-f1.png</a>` se convertia en `<a href="HOR-002-f1-loader-amber-tones"><a class="...">HOR-002-...</a>.png</a>` (anchor anidado, HTML invalido, URL rota). | 6 | `markdownImageHook` necesitaba reescribir URLs relativas al endpoint raw del server — sin esto el lightbox 404 porque el browser resolvia contra `/p/:project/tickets/:ticketId-*.png` | Hook no tenia contexto del ticket actual. Solucion: singleton `rewriteContext` en `useMarkdown.ts` que el plugin consulta en render time. `MarkdownBody` y `TicketDetail` propagan `ticketId`. | `resolveAssetUrl()` en hook reescribe relativas a `/api/projects/:project/tickets/:ticketId/assets/screenshot/:filename`. Absolutas/root-relative se dejan intactas. Validado en browser: fetch al chip href → 200 image/png. |

## Summary

### What was requested
Visibilizar en horadric-cube los artefactos que el flujo deckard ya produce por ticket — screenshots loose, `intent.md`, `preview.html` y `data-model.{ext}` — sin inventar convenciones paralelas y preservando el contexto narrativo de cada asset.

### What was done
Un dev que abre un ticket en el viewer ahora puede:
- **Ver screenshots inline con contexto**: cada imagen linkeada en el markdown del ticket (tanto sintaxis `![](url)` como `[text](url.png)` legacy) aparece como chip compacto `[thumbnail · filename · ⤢]` dentro del row del TC, bullet de session, o parrafo que la referencia. Click abre lightbox modal full-size con el texto circundante como caption (ej: `TC-02 Gradient amber shimmer sin translateX F1 manual loader forzado visible... pass`). Cierre con Esc o click backdrop.
- **Revisar el draft sin salir del viewer**: 3 tabs nuevas condicionales en TicketDetail — `Draft intent` (render del `.draft/intent.md`), `Draft visual` (iframe con sandbox del `.draft/preview.html`), `Data model` (render del `.draft/data-model.{ext}` con syntax highlight + mermaid renderizado como SVG inline).
- **Abrir cada asset en pestaña nueva** si necesita fullscreen — todos los tabs de draft tienen boton external que sirve el archivo raw con content-type correcto.
- **Navegar entre tickets sin confusion**: tickets legacy (BLY-001) sin draft no ven las 3 tabs nuevas — se muestran solo si el asset correspondiente existe.

Internamente: nuevo tipo de dominio `TicketAsset` (discriminated union por `kind`), 2 endpoints REST (`GET /assets` list + `GET /assets/{kind}/{filename}` raw con path traversal guard), composable `useTicketAssets` con invalidation + race guard, hook de `markdown-it` que transforma imagenes y links-a-imagen en chips con caption del AST.

### What was discovered
- **Rules creadas**:
  - [RULE-viewer-assets-context-001](../rules/viewer/RULE-viewer-assets-context-001.md) (must) — promovida desde L2. Assets binarios siempre inline con contexto narrativo; galeria aislada = antipattern. Aplica a cualquier feature futura del viewer que exponga screenshots, videos o PDFs.
- **Decisions tomadas** (locales, registradas en Session #1 y #2):
  - DEC-LOCAL-01..07: screenshots por pattern discovery (no subdir), iframe B3 (embed + external), markdown-it + mermaid lazy para data-model, `intent.md` via `MarkdownBody` existente, HOR-005 no modifica deckard-core, screenshots sin tab dedicada, 6 OQs resueltas con recomendacion.
- **Bugs encontrados**: 1 preexistente documentado como failed approach #5 (`wireInternalLinks` rompia anchors con RECORD_ID matches — corregido con placeholder guard). No se promovio a BUG formal porque el fix vive en el mismo commit y no tiene status `detected` pendiente.
