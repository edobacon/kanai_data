# HC viewer: parsear las 10 dims DET-23 + filtrar tickets por dimension en warn/fail

## Request

**Origen**: spin-off de HOR-082 (explore cerrado `wont_do` el 2026-06-13). HOR-082 evaluo agregar `dim_results` JSON al output del reviewer y lo refuto: **no existe consumidor** que lea las 10 dims del quality review (DET-23). Este ticket crea ese consumidor — que es el entregable de valor real, y el prerequisito que desbloquearia (si se decide) el `dim_results` de HOR-082.

**El gap concreto**: DET-23 (`prompts/deterministic-rules.md:650`) declara el caso de uso:

> *"HC viewer renderiza el bloque y permite filtrar tickets por dimensiones en `warn` o `fail` para construir backlog de deuda de calidad."*

Pero ese filtrado **no esta implementado**. Evidencia recopilada en HOR-082 S1:

- El parser del HC viewer (`commands/lib/parsers/markdown.ts:354-366`) extrae solo `{reviewer, tier, globalResult}` del bloque `#### Quality review (DET-23)`.
- `horadric-cube/server/deckard/sessions.ts:90-143` (`SessionSummary`) **no tiene campo de dimensiones** — las 10 filas de la tabla markdown no se parsean.
- No hay UI de filtrado por dimension en `warn`/`fail`.

## Que se pide (alcance preliminar — refinar en intake)

1. **Parsing**: extender el parser del HC viewer para leer las 10 dims (`code_quality, lint, typing, testing, scalability, maintainability, clarity, a11y, storybook, error_handling`) + su resultado (`pass | warn | fail | n/a`) desde la tabla del bloque `#### Quality review (DET-23)`. Hoy es markdown (fuente de verdad DKC) — el parser lo lee, NO se introduce un JSON nuevo (ver decision pendiente abajo).
2. **Modelo**: agregar las dims al `SessionSummary` (o estructura equivalente) que consume el frontend.
3. **UI/filtrado**: vista o filtro que liste tickets/sessions con dimensiones en `warn`/`fail` → "backlog de deuda de calidad" (el caso de uso de DET-23). Respeta [feedback_decisions_deliver_value]: estructurar las dims solo aporta si la UI las muestra.

## Decisiones resueltas (S0 intake — super autopilot, decide+documenta)

- **DEC-01 — Parsear la tabla markdown directo (NO JSON).** El HC viewer implementa su propio extractor de las 10 dims desde el bloque markdown. Racional: (a) HOR-082 confirmo que el JSON sin consumidor es deuda; (b) el parser del HC viewer es **independiente** del de deckard core (no hay import cruzado — ver Context found), asi que el cambio queda 100% en horadric-cube, cero cambio al reviewer ni a deckard; (c) markdown sigue siendo la unica fuente de verdad (principio DKC + [feedback_viewer_reflects_flow]). HOR-082 NO se reactiva — el JSON no aporta.
- **DEC-02 — Soportar AMBOS formatos del bloque.** Tickets reales usan `**Quality review (DET-23)**:` (bold-label, mas comun) y `#### Quality review (DET-23)` (heading, canonico DET-23). El extractor tolera ambos + variaciones (reviewer/resultado al inicio o al final, nombres de dim con/sin "de", tablas que omiten filas n/a). Se parsea por **numero de fila** (`| N | ... |`, 1-10), no por nombre de dim, para robustez ante el naming drift ("Calidad de codigo" vs "Calidad codigo").
- **DEC-03 — Endpoint de agregacion dedicado (`/:project/quality-debt`), NO N+1 en el browser.** El board solo tiene `TicketSummary` (sin sessions). Filtrar por dims warn/fail desde el frontend exigiria N requests de detalle. En su lugar, el server escanea las sessions de los tickets una vez por request y devuelve una lista plana de hallazgos warn/fail. Evita N+1 y no contamina `TicketSummary`. Reversibilidad: endpoint nuevo aislado, no toca el contrato de listado existente.
- **DEC-04 — Vista dedicada (`QualityDebtView`) con filtro, NO solo un filtro del board.** DET-23:650 enmarca el caso de uso como "backlog de deuda de calidad" — una lista con proposito, no un modo del kanban. Entrega valor visible ([feedback_decisions_deliver_value]). Reusa el patron de filtrado de `TicketFilters.vue` + `computed filtered`. Ademas: render del bloque qualityReview en `SessionDetailModal` (hoy cae a extras sin formato), para que el detalle por session tambien muestre las dims.

### Arquitectura mapeada (S0 — Agent Explore sonnet, 2026-06-13)

- **Dos parsers independientes, sin import cruzado**: el HC viewer NO importa `deckard/commands/lib/parsers/`. `grep -rn "commands/lib" horadric-cube/server/` → 0. El parser de deckard (`markdown.ts:354-366`, extrae reviewer/tier/globalResult) es solo para tooling DKC. **El HC viewer tiene su propio parser** en `server/deckard/sessions.ts` → todo el cambio queda en horadric-cube.
- **Las 10 dims NO se parsean hoy**: `parseBoldBlocks()` (`sessions.ts:863`) divide el body en bloques `**label**: content`; los no-canonical (incluido Quality review) caen a `extras[]` (`sessions.ts:484-487`). `CANONICAL_LABELS` (`sessions.ts:145-168`) no incluye "quality review". El formato heading `####` se serializa dentro de `rawMarkdown` sin extractor. `SessionSummary` (`sessions.ts:95-143`) **sin campo qualityReview**.
- **Helper reusable**: `server/deckard/tables.ts` (`parseTables()`) parsea tablas markdown (columnas + rows) → reusar para la tabla de 10 dims.
- **Flujo de datos**: `.md` → `readFileSync` (`tickets.ts:91`) → `parseFile` → `extractSections` (`body.ts`) → `parseSessionsSection` (`sessions.ts:188`) → `SessionSummary[]` → `c.json()` en `TicketDetailPayload.sections.sessionsParsed`. **index.db (SQLite) solo para listing/ids**, el contenido de sessions se parsea del .md en cada request.
- **Cache ETag**: cambiar el shape de `SessionSummary` exige bump de `TICKET_DETAIL_SCHEMA_VERSION` (`server/routes/tickets.ts:23`, hoy `'ticket-detail-v6'`).
- **Frontend**: filtrado actual = `filters ref({module,workType,tag}) + computed filtered` (`TicketsBoard.vue:66-81`) + sidebar `TicketFilters.vue` (reusa opciones dinamicas). Tipo `SessionSummary` duplicado client-side en `src/api/client.ts:311-345` (extender ambos lados). `SessionDetailModal` hoy NO renderiza el quality review (cae a extras sin formato). No existe vista de "deuda de calidad".
- **Tests**: `server/deckard/sessions.test.ts` usa inline markdown como fixture → `extractSections` → `parseSessionsSection` → asserts. Sin tests de quality review hoy. Patron a seguir.
