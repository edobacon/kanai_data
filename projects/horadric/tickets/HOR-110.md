# Enumerador de repos respeta additional_paths sin importar el flag monorepo

## Request

Arreglar `enumerateProjectRepos` (HC `server/deckard/monorepo.ts`) para que el bloque de `additional_paths` se respete aunque el proyecto NO sea monorepo — hoy un early-return en `if (!config.repo?.monorepo) return repos` lo descarta. Luego declarar deckard como repo adicional del proyecto horadric en su `config.yaml`, para que HC muestre las ramas (y commits HOR-*) que viven en deckard, no solo las de horadric-cube.

## Discoveries / decisions

- M1 (micro-decision): el bloque `additional_paths` se mueve FUERA del guard `if (!monorepo) return`, no se duplica. Semanticamente additional_paths = "repos vecinos extra", ortogonal al layout monorepo del root. El acoplamiento previo era un defecto latente (codigo divergia de la propia descripcion de SPEC-108).
- D1 (propagacion DET-16): `enumerateProjectRepos` alimenta tanto `/:project/branches` como `/:project/commits` (commits.ts:71). El fix recupera en HC la visibilidad de los commits HOR-* que viven en deckard (HOR-048 repo layer, HOR-079 hooks, HOR-051/052 fix, etc.), no solo las ramas.
