# Aislamiento e2e + validar full-3-viewport en CI

## Request

Derivado de [PEH-011](PEH-011.md) S3 (2026-07-20). En esa sesion se saneo la deuda de tests e2e (selectores stale, races de hidratacion mobile, relocacion de reportes) y se dejo un gate CI bloqueante corriendo el project **desktop en serie** (`test:e2e:ci`, verde: 0 failed / 2 flaky-retry-OK / 277 passed).

Lo que **quedo sin validar**: la suite completa en los 3 viewports (mobile + tablet + desktop) bajo paralelismo real. La causa es arquitectonica y NO son bugs de producto: la suite comparte una sola base `pehuen-test` entre todos los workers y projects, asi que al correr los mismos tests 3 veces en paralelo (uno por viewport) los tests de mutacion (crear/eliminar guia/ruma) pisan filas que otros leen. Evidencia: el run full-3-viewport dio 38 hard fails; los mismos specs pasan en aislamiento (22 fallos de `receptor-flows` caen a 1). Incluso el project desktop en paralelo flakea con "element not found: table/boton"; por eso el gate actual corre `--workers=1`.

Este ticket habilita el aislamiento para reactivar el paralelismo y promover el gate CI a full-3-viewport.

## Scope

### Dentro de alcance
1. **Aislamiento de base por worker/project.** Sembrar una base por `TEST_WORKER_INDEX` (ej. `pehuen-test-{n}`) y que cada worker/project use su propio `NUXT_MONGODB_URI`, o reseed por-archivo, de modo que las mutaciones no contaminen lecturas concurrentes. Adaptar `global-setup.ts` + `playwright.config.ts` (webServer por project o URI por worker).
2. **admin-login mobile (F1-F6).** Hoy apunta al staging `:4400` (443k guias) y el `waitForFunction($nuxt.isHydrating)` de 10s no alcanza en webkit. Decidir: migrar al webServer `:4401` (como los `*-flows`, que se repuntaron en PEH-019 B9) o subir el timeout y condicionar la ejecucion a que el clone `:4400` este arriba. Hoy esta tagueado `@staging` y excluido del gate.
3. **Estabilizar flaky remanentes** del gate serial (timing, pasan en retry): `admin-flows` Ajustes F5 (Carga Masiva) y `supervisor-flows` Usuarios (page load).
4. **Reactivar paralelismo + promover el gate CI a full-3-viewport.** Quitar `--workers=1` de `test:e2e:ci` (o subir el worker count) y sumar los projects `mobile` + `tablet` al job `e2e` de `ci.yml` (instalar tambien webkit en `playwright install`, hoy solo chromium).

### Fuera de alcance
- Paridad numerica de reportes Excel vs legacy (PEH-011 backlog B3, otra naturaleza: parity, no e2e infra).
- Validacion ops del cutover (paridad E2E `@paridad`, canary, smoke en vivo): sigue en PEH-011, no autopiloteable.
- Cualquier cambio de producto (el triage de PEH-011 S3 confirmo 0 bugs de producto en el set).

## Acceptance checkpoints

- [ ] La suite e2e completa corre en paralelo en los 3 viewports (mobile/tablet/desktop) sin carreras de mutacion, **verde y reproducible** en varias corridas seguidas (no solo un run afortunado).
- [ ] `admin-login` mobile: verde, o excluido conscientemente con razon documentada y su dependencia de infra resuelta.

- [ ] `ci.yml` job `e2e`: gate bloqueante en full-3-viewport, con tiempo de corrida aceptable (documentar el tradeoff paralelismo vs aislamiento).
- [ ] `playwright install` en CI cubre chromium + webkit (mobile usa webkit).
- [ ] Confirmado 0 bugs de producto (todo lo que aparezca es deuda de tests / infra).
