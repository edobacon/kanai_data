## Alcance — 7 items (mix fix + decision)

> DET-1: los items marcados **[DECISION]** estan `blocked` hasta que el dev/stakeholder confirme; no
> pasan a tasks sin decision. Los **[FIX]** tienen causa clara y source_ref al codigo.

### 1. [DECISION + FIX] TTL de tokens no coincide con el acceptance ni entre si

- **Evidencia**: el path activo que setea cookies (`server/utils/auth.ts:38,114,118`) usa
  access = 15min (default, configurable por `NUXT_ACCESS_TOKEN_MAX_AGE`) y refresh = 7 dias.
  Existe un path paralelo `server/models/user.model.ts:66-67` con 3h/90d que **no alimenta las cookies**
  (codigo muerto/duplicado). El `acceptance-checklist.md` §3 pide 3h/90d.
- **Accion**: verificar el TTL real del legacy (fuente de verdad), decidir el valor, unificar en un solo
  lugar y eliminar el path muerto. Actualizar el acceptance si el valor efectivo difiere por decision.

### 2. [FIX] `audit()` solo en 12 de 35 endpoints de escritura

- **Evidencia**: `grep audit( server/api/**/*.{post,patch,delete}.ts` = 12; total escrituras = 35. Faltan
  crear/editar guia y ruma, status/reset-geo, todo canchas y productos, logout, refresh, cancha,
  mii/upload, reports.
- **Accion**: invocar `audit()` en todas las escrituras criticas + test que verifique la invocacion
  por-endpoint (no solo la funcion aislada).

### 3. [FIX] `/api/health` no consulta la DB

- **Evidencia**: `server/api/health.get.ts` retorna solo `{ status:'ok', timestamp }`. El item 2.4 pide
  `db: 'connected'` y el caso DB-caida -> 503.
- **Accion**: agregar ping a Mongo + estado; 503 si no conecta. Ajustar el test de health.

### 4. [FIX] `User.rut` sin indice / unique

- **Evidencia**: `server/models/user.model.ts:40` (`rut: { type: String }`), indices en :102-103 solo
  cubren `email` (unique) y `role+active`. El login consulta por rut sin indice.
- **Accion**: auditar duplicados de rut en la data legacy ANTES (un unique podria fallar si hay duplicados),
  luego agregar indice (unique si la data lo permite; si no, non-unique + decidir politica).

### 5. [DECISION + FIX] defaults numericos de Guia ausentes en el schema

- **Evidencia**: `server/models/guia.model.ts:85-99` declara `pesoBruto*`, `pesoNeto*`, `volumen*`,
  `foto*`, `cantidadRollizo*` como `{ type: Number }` sin `default: 0` (el acceptance §1 los pide en 0).
- **Accion**: confirmar si Zod aplica el default en el request (podria no ser gap). Si no, agregar
  `default: 0` para paridad con el legacy.

### 6. [FIX] regla `origen !== destino` ausente

- **Evidencia**: no hay validacion que compare `origen` vs `destino` en `server/schemas/guia.schema.ts`
  ni en los handlers de `server/api/guias/`. El acceptance §4 la exige (comportamiento legacy).
- **Accion**: implementar la validacion (test primero desde el legacy) + mensaje literal.

### 7. [DECISION] refresh token sin rotacion one-time-use

- **Evidencia**: `server/api/auth/refresh.post.ts` reemite tokens pero no invalida el refresh anterior
  (solo `tokenVersion` lo invalidaria, y no cambia en cada refresh). La mejora "1.2" del checklist queda
  sin la semantica anti-replay.
- **Accion**: decidir si se implementa rotacion anti-replay o se acepta como DELTA documentado.
