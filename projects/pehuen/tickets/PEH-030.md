# Corregir ortografia de copy en la UI (tildes/acentos)

## Request

Derivado de [PEH-011](PEH-011.md) S3 / backlog B7 (2026-07-20). La UI de nuxt tiene copy sin tildes/acentos. El caso disparador y prioritario: el label `Ano Plantacion` ([`GuideAnexosSection.vue:51`](../../../q/pehuen/pehuen_nuxt/app/components/guides/GuideAnexosSection.vue)) debe ser **`Año Plantación`** (falta la tilde en "Año" — sin ella "Ano" cambia el significado — y el acento en "Plantación").

Escaneo (2026-07-20) muestra que la omision de acentos es **sistematica** en el codebase (Descripcion ~124, Codigo ~92, Recepcion ~43, Numero ~30, Plantacion ~26, Intervencion ~26, Contrasena ~21, Estadisticas, Cerrar sesion, etc.). Los tildes renderizan bien (`/importer` ya usa "Año" con tilde), asi que es inconsistencia de copy, no limitacion tecnica.

El objetivo: corregir la ortografia del copy visible al usuario **sin romper los tests** (varios e2e/unit asertan el texto actual sin tilde) y decidiendo conscientemente la amplitud del barrido.

### Scope: C — completo (decidido por dev, 2026-07-20)
Barrido de **toda la ortografia**: copy visible al usuario (labels, headings, botones, placeholders, mensajes/toasts, empty-states) **y** strings internos (logs, mensajes de error). Motivo del dev: dejar todo correcto, cubrir solo una parte deja deuda tecnica. El `must` de arriba ("Año Plantación") es el primer lote/prioridad dentro de C.

#### Evaluacion de C (2026-07-20) — viable, pero el trabajo es CLASIFICAR, no reemplazar
1. **No hay capa i18n**: el copy esta **hardcodeado** en los templates Vue y en strings `.ts` (toasts/errores). No existe un archivo de locale central que corregir; se arregla string por string, in-place. Mayor esfuerzo manual, pero cambios localizados.
2. **Copy ≪ codigo (riesgo central):** la mayoria de las apariciones de una palabra son **identificadores de codigo**, no texto. Ejemplo medido: `Descripcion` → ~3 son copy visible vs **~174** son keys/campos/accessorKey (`descripcion:`, `.descripcion`, `accessorKey`). **Un find/replace global es catastrofico** (rompe DB, contratos API, Zod/Mongoose, tests). C obliga a clasificar cada ocurrencia.
3. **Conclusion:** C es un **pase curado y clasificado, multi-sesion** (no un quick fix). El volumen real de strings a corregir es una fraccion chica de los conteos crudos del grep, pero disperso en muchos archivos.

#### Reglas de clasificacion (que SI se corrige / que NO se toca)
- **SI (corregir a ortografia correcta):** texto entre `>...<` en templates, valores de `label=` / `placeholder=` / `title=` / `heading` props, labels de botones, `empty-message`, `toast.add({ title/description })`, mensajes de error mostrados al usuario (`createError({ statusMessage })` visible), textos de columnas (`header:` que se muestra).
- **NO (dejar intacto — romperia contratos/DB/tests):** keys de objeto y nombres de campo (`descripcion:`, `anioPlantacion`), `accessorKey` (liga a la data), valores de enum, IDs, nombres de variable/prop/composable, rutas, clases CSS, keys de storage, y cualquier string que la API/DB/test use estructuralmente. Ante la duda: si el string es un identificador o liga a data → NO se toca.

#### Fases sugeridas (sessions DET-20)
1. **Inventario clasificado:** recorrer app/ (+ server/ para errores visibles) y armar la lista de ocurrencias `copy` (con archivo:linea + texto actual → corregido), separada de las `code` (descartadas). Entregable revisable antes de editar.
2. **Correccion por modulo/pagina** en lotes (guias, rumas, ajustes, productos, stats, auth, mii, mantenedores, reportes, layout/nav), un commit por lote.
3. **Actualizar tests en lockstep:** cada string corregido que un test (e2e/unit) asierte se actualiza en el mismo lote; correr el gate e2e desktop + unit del modulo y confirmar verde.
4. **Cierre:** barrido de logs/errores internos (la parte C-especifica), verificacion runtime de una muestra por pagina, y registro del delta vs legacy.

### Fuera de alcance
- Identificadores de codigo, keys de objeto, nombres de campo Mongoose/Zod, valores de enum, IDs. Cambiarlos rompe contratos/DB. Solo se corrige **texto mostrado al usuario**.
- Traduccion o cambios de wording (esto es solo ortografia: agregar tildes/acentos correctos).

### Consideracion de paridad (RULE-MIGRATION-004)
El legacy tambien tiene el copy sin tildes. Corregir nuxt es un **delta deliberado** vs legacy (mejora de copy, patron de excepcion sancionada tipo DEC-009/DEC-022). Registrarlo como tal en la decision del ticket. No es regresion: es mejora de calidad de UI, no cambio de comportamiento.
