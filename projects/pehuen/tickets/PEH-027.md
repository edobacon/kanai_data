**Discoveries / Learns nuevos**:
- L1: El modelo `User` declara `_id: { type: Schema.Types.ObjectId }` explicito (para tolerar `_id` legacy string). Efecto colateral de Mongoose: declarar el path `_id` **desactiva la autogeneracion** del ObjectId, asi que `User.create()` requiere `_id` explicito. No es bug de `anonymizeUser`; solo afecta el seeding de tests.
- L2: La capa `tests/integration/` del proyecto es HTTP-paridad (jsdom + MSW contra staging), no accede a Mongo directo. Un test de codigo de datos real-DB debe correr en env `node` sin MSW; se resolvio con `// @vitest-environment node` en `tests/unit/` (corre bajo `pnpm test:run`, no necesita config aparte). MSW no interfiere (intercepta HTTP, no el socket TCP de mongod).
- L3: `anonymizeUser` es correcta a nivel runtime: el mock y la DB real coinciden. La prueba real confirma persistencia (no solo el llamado).

**Bug classification (T3)**: 0 bugs de runtime en `anonymizeUser`.
