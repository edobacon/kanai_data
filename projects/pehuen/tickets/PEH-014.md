# Desbloquear roundtrip HTTP de paridad — seed de usuario con password conocida

## Request

El test de integración `tests/integration/migration-roundtrip.test.ts` tiene sus bloques HTTP en `describe.skip` / `it.todo` porque el seed de datos NO incluye un usuario con password conocida para autenticarse contra legacy y nuxt. Solo corre la capa DB-level (counts por colección). Hay que **agregar un usuario de seed con password conocida y desbloquear (unskip) los bloques HTTP**, de modo que el roundtrip valide paridad legacy↔nuxt sobre endpoints autenticados (no solo counts en Mongo).

Este es el remanente operativo del **Sprint 0** (PEH-002 quedó `closed` con esta task pendiente). Es la precondición para comparar **mutaciones** (POST/PATCH/DELETE) entre legacy y nuxt — hoy `validate-migration.mjs` solo compara GETs.
