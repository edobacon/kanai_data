# Nuevo modelo `AuditLog` para auditoría de escrituras críticas (no existe en legacy)

## Context and problem statement

El legacy no tiene ningún mecanismo de auditoría de escrituras. Preguntas como "¿quién anuló esta guía?" o "¿quién creó este usuario?" no se pueden responder. El nuxt define `server/models/audit-log.model.ts` con campos `{ userId, action, entity, entityId, ip, changes, timestamp }`. Se debe confirmar este modelo y su alcance.

## Decision drivers

- Compliance y trazabilidad regulatoria (auditoría forestal).
- Capacidad de investigar incidentes operativos ("¿quién hizo X?").
- Costo de storage: estimado ~10MB/año para el volumen actual de operaciones.
- Alcance: qué entidades requieren auditoría.

## Considered options

| # | Option | Description |
|---|--------|-------------|
| A | Sin auditoría (paridad legacy) | No implementar AuditLog |
| B | AuditLog en modelo dedicado | Modelo `AuditLog` con write en cada operación crítica |
| C | Auditoría via logs de aplicación | Usar Winston para loguear operaciones, sin modelo dedicado |

### Option A: Sin auditoría
- **Pro**: Cero implementación adicional.
- **Con**: Sin trazabilidad. Incidentes operativos sin respuesta. Riesgo regulatorio.

### Option B: AuditLog modelo dedicado
- **Pro**: Queryable directamente desde MongoDB. Permite UI de auditoría futura.
- **Pro**: Registro permanente con estructura definida.
- **Con**: Costo de storage (mínimo según estimación).
- **Con**: Requires `audit()` en cada handler de escritura.

### Option C: Logs de aplicación (Winston)
- **Pro**: Sin modelo adicional.
- **Con**: Logs de aplicación son efímeros y difíciles de consultar. No sirven para auditoría formal.

## Decision outcome

**Chosen option**: B — modelo `AuditLog` dedicado.

**Justification**: La trazabilidad de escrituras es un requisito de negocio implícito en operaciones forestales reguladas. El costo de storage es despreciable. La función `audit()` como utilidad auto-importada minimiza el overhead de implementación.

## Consequences

### Positive
- Capacidad de responder "¿quién hizo qué y cuándo?" en cualquier entidad.
- Base para una UI de auditoría futura si se necesita.

### Negative
- Todas las operaciones de escritura deben invocar `audit()` (ver RULE-GEN-003).
- Storage adicional en MongoDB (mínimo).

### Mitigations
- Implementar TTL index en `AuditLog` (sugerido: 1 año) para evitar crecimiento indefinido.
- `audit()` como util auto-importado en Nitro reduce el boilerplate.

## Confirmation

- `grep -rn "audit(" server/api/" → debe aparecer en cada handler de escritura.
- Test: crear guía → existe documento en colección `audit_logs` con `entity: 'Guia'`.
- `db.audit_logs.getIndexes()` → debe existir TTL index en `timestamp`.
