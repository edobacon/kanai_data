# Corregir 5 bugs legacy en nuxt: isRut, ingresoRomana, rango movimiento, RumaDto:31, Producto.role

## Context and problem statement

El legacy tiene 5 bugs documentados que el nuxt debe decidir si replicar (paridad exacta) o corregir. Replicar bugs puede ser válido si el comportamiento incorrecto ya fue asumido por el sistema o los datos. Corregirlos puede introducir inconsistencias con datos legacy o comportamientos que los usuarios conocen como "normal". Cada bug requiere evaluación individual.

## Decision drivers

- Corrección técnica: el comportamiento correcto es mejor a largo plazo.
- Impacto en datos legacy: algunos bugs generaron datos inconsistentes que complican la corrección.
- Comunicación al equipo: cambios de comportamiento deben comunicarse.
- Riesgo: bugs críticos (catastrófico si se corrige mal) vs cosmético (seguro de corregir).

## Considered options

Para cada bug:

| Bug | Descripción | Riesgo de corregir |
|-----|-------------|-------------------|
| `isRut` semántica invertida | Retorna `true` cuando es inválido | ALTO: si se corrige semántica pero no el `if` → rechaza RUTs válidos |
| `ingresoRomana` sobreescrito | Se almacena `ingresoPlanta` en `ingresoRomana` | MEDIO: datos legacy tienen ambos iguales; reportes que asumen igualdad |
| Rango movimiento (1..5) | `&&` en lugar de `\|\|` → nunca valida | BAJO: datos con `movimiento` inválido son improbables |
| RumaDto:31 `estadoMadera` vs `estadoRuma` | Error en mensaje de validación | BAJO: cosmético, sin impacto en datos |
| `Producto.role` fantasma | Campo duplicado coexiste con `estado` | BAJO: `$unset` en migración, sin impacto funcional |

## Decision outcome

**Chosen option**: Corregir los 5 bugs, con precauciones específicas por bug.

**Justification**: El nuxt es la oportunidad de sanear el comportamiento. El riesgo de cada corrección está documentado y es manejable con los controles adecuados.

## Consequences

### Positive
- Comportamiento correcto y predecible post-migración.
- Menos bugs latentes que reportar.

### Negative
- `isRut`: riesgo de bug catastrófico si se corrige semántica sin actualizar todos los `if`.
- `ingresoRomana`: datos legacy tienen el campo con valor incorrecto (igual a `ingresoPlanta`).

### Mitigations
- `isRut`: test explícito con RUTs válidos e inválidos en todos los endpoints que lo usan.
- `ingresoRomana`: auditar si algún reporte/stat usa `ingresoRomana` antes del corte.
- `Producto.role`: ejecutar `db.productos.updateMany({}, { $unset: { role: 1 } })` en migración.
- Comunicar cambios de comportamiento al equipo operativo.

## Confirmation

- Test `isRut`: RUT válido `12345678-9` → función retorna `true`. RUT inválido → `false`.
- Test `ingresoRomana`: `{ ingresoPlanta: 'A', ingresoRomana: 'B' }` → ambos campos distintos.
- Test rango movimiento: `movimiento: 0` → 400. `movimiento: 6` → 400. `movimiento: 3` → 201.
- Test RumaDto: `estadoRuma` inválido → mensaje apunta a `estadoRuma`, no `estadoMadera`.
- `grep -n "role" server/models/producto.model.ts` → 0 matches para campo `role`.
