# Vistas dedicadas de ASESOR se eliminan: usa `/rumas` y `/stats` con feature subset por rol

## Context and problem statement

El legacy tiene dos vistas dedicadas para el rol ASESOR: `/asesor-ruma-list` y `/asesor-stats`. Estas vistas son versiones simplificadas de las vistas principales, con menos columnas y sin opciones de edición. El nuxt unifica las vistas: ASESOR accede a `/rumas` y `/stats` directamente, pero la UI renderiza condicionalmente solo el subset de features correspondiente al rol.

## Decision drivers

- DRY: mantener dos versiones paralelas de la misma vista aumenta la deuda de mantenimiento.
- UX: la URL del usuario ASESOR cambia → comunicación necesaria.
- Implementación condicional por rol: ya existe el patrón en Nuxt (feature flags por `user.role`).

## Considered options

| # | Option | Description |
|---|--------|-------------|
| A | Mantener vistas dedicadas | Preservar `/asesor-ruma-list` y `/asesor-stats` |
| B | Vistas unificadas con conditional rendering | ASESOR usa `/rumas` y `/stats` con UI adaptada |
| C | Redirect transparente | `/asesor-*` redirige a vistas compartidas (DEC-012) |

### Option A: Mantener vistas dedicadas
- **Pro**: Sin cambio de URL para ASESOR. Sin riesgo de mostrar features no autorizados.
- **Con**: Doble mantenimiento de código de UI. Duplicación de lógica de fetch.

### Option B: Vistas unificadas
- **Pro**: Una sola vista a mantener. Cambios de UI aplican a todos los roles.
- **Con**: La lógica condicional por rol puede volverse compleja si los subsets son muy diferentes.

### Option C: Redirect + vistas compartidas
- **Pro**: Combina DEC-012 (redirect de URLs legacy) con la unificación.
- **Con**: No es una opción aislada; es complemento de B.

## Decision outcome

**Chosen option**: B — vistas unificadas con renderizado condicional por rol.

**Justification**: Es el comportamiento ya implementado en nuxt. La deuda de mantenimiento de dos vistas paralelas supera el costo de implementar renderizado condicional. Se complementa con DEC-012 (redirect de `/asesor-*`).

## Consequences

### Positive
- Una sola vista de rumas y stats para mantener.
- Feature flags por rol son extensibles si se agregan nuevos roles.

### Negative
- URL cambia para ASESOR. Si tienen bookmarks a `/asesor-ruma-list`, se rompen (mitigado por DEC-012).
- La lógica condicional debe ser correcta: ASESOR no debe ver botones de edición.

### Mitigations
- DEC-012: `/asesor-ruma-list` → redirect 301 a `/rumas`.
- Test: ASESOR accede a `/rumas` → no ve botones de crear/editar ruma.

## Confirmation

- `grep -rn "asesor-ruma-list\|asesor-stats" app/pages/` → 0 matches (rutas eliminadas).
- Test: ASESOR navega a `/rumas` → ve lista de rumas sin opciones de edición.
- Test: ASESOR navega a `/stats` → ve stats sin opciones de administración.
