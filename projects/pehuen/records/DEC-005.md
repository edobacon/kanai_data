# Storage de imágenes de ruma: filesystem local (legacy) vs S3/Cloudflare R2 (nuxt)

## Context and problem statement

El legacy almacena imágenes de rumas en el filesystem local del servidor en `uploads/rumaimages/`. El campo `Ruma.img` contiene el nombre de archivo relativo. El nuxt usa `@aws-sdk/client-s3` configurado para AWS S3 o Cloudflare R2. Se debe decidir el provider y confirmar si `Ruma.img` pasa a ser una URL completa o mantiene el nombre de archivo. La migración de imágenes existentes es una consideración adicional.

## Decision drivers

- Fiabilidad: filesystem local se pierde si el servidor cae o se reemplaza.
- Escalabilidad horizontal: múltiples instancias de nuxt no pueden compartir filesystem local.
- Costo: R2 (Cloudflare) tiene 0 egress fees; S3 cobra por transferencia.
- Migración de imágenes existentes: cuántas imágenes hay en producción y costo de migrar.
- Cambio en `Ruma.img`: URL completa vs nombre de archivo impacta el cliente y los endpoints.

## Considered options

| # | Option | Description |
|---|--------|-------------|
| A | Filesystem local (paridad legacy) | `uploads/rumaimages/` en servidor nuxt |
| B | AWS S3 | Storage S3 con URLs firmadas o públicas |
| C | Cloudflare R2 | Storage R2 (S3-compatible, sin egress fees) |

### Option A: Filesystem local
- **Pro**: Sin cambio en `Ruma.img` format. Sin migración de imágenes existentes.
- **Pro**: Sin dependencia externa de storage.
- **Con**: No funciona con múltiples instancias. Datos perdidos si el servidor cae.

### Option B: AWS S3
- **Pro**: Estándar de la industria. Reliability 99.999999999%.
- **Pro**: Nuxt ya tiene `@aws-sdk/client-s3` instalado.
- **Con**: Egress fees si el tráfico es alto. Configuración de CORS/URLs firmadas.

### Option C: Cloudflare R2
- **Pro**: API S3-compatible (mismo SDK). Sin egress fees.
- **Pro**: Latencia menor para clientes en Chile si se usa CDN de Cloudflare.
- **Con**: Menos documentación y ecosistema que S3.

## Decision outcome

**Chosen option**: **A — Filesystem local (paridad legacy)**.

**Justification**: El sistema se despliega en un **VPS dedicado**, instancia única. Los pros de S3/R2 (escalabilidad horizontal, reliability cross-AZ) no aplican al modelo de despliegue elegido. Filesystem local elimina:

- Dependencia externa con costo recurrente (S3 egress fees, R2 cuotas).
- Migración de imágenes existentes (`Ruma.img` mantiene nombre de archivo relativo).
- Cambios en cliente, endpoints, schema de `Ruma.img`.

El backup se cubre con la estrategia de backup del VPS (filesystem-level snapshot). Si en el futuro se migra a multi-instancia, esta decisión deberá revisarse y `RUMA_IMAGE_BASE_URL` permite el switch a cloud sin cambiar el código del modelo.

## Consequences

### Positive
- Cero costo recurrente de storage cloud.
- Sin migración de imágenes existentes (paridad de paths).
- Sin cambio en `Ruma.img` schema, endpoints, ni cliente.

### Negative
- Backup atado a la estrategia de backup del VPS.
- Si se requiere multi-instancia futura, reabrir la decisión.

### Mitigations
- `RUMA_IMAGE_BASE_URL` configurable vía env: permite cambio futuro a cloud sin tocar código del modelo.
- Backup periódico del directorio `uploads/rumaimages/` documentado en runbook del VPS.
- Endpoint `GET /uploads/rumaimages/:filename` con auth para servir imágenes (no expuesto público).

## Reconciliación con el código (PEH-028, 2026-07-19)

El código nuxt había implementado un adapter `CloudflareR2Storage` (Option C) como opción configurable, pese a que esta decisión ratificó **Option A (filesystem local)**. Ese adapter nunca se activó en ningún deploy (el Dockerfile de prod apunta storage a un volumen local; ningún env setea `NUXT_STORAGE_PROVIDER=r2`) y el dev confirmó (2026-07-19) filesystem-only sin terceros. **PEH-028 eliminó el adapter R2, su wiring y la dependencia `@aws-sdk/client-s3`**, alineando el código con esta decisión. R2 queda como **no implementado / diferido**: si en el futuro se requiere multi-instancia (ver *Negative* arriba), se reabre esta decisión y se reintroduce el adapter con cobertura de test. El factory conserva `local` (default) y `railway`.

## Confirmation

- Decisión de provider documentada y aprobada por stakeholders.
- `Ruma.img` format definido y consistente (nombre de archivo o URL completa).
- Test: subir imagen → leer imagen → URL accesible.
- Script de migración de imágenes legacy ejecutado y verificado antes del corte.
