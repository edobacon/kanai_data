# ORM: upgrade Mongoose 5 → 9 con migración de APIs deprecadas

## Context and problem statement

El legacy usa Mongoose 5 (Express). El nuxt usa Mongoose 9. Entre versiones 5 y 9 hay breaking changes significativos: `execPopulate()` fue eliminado, `Types.ObjectId(string)` se reemplaza por `new Types.ObjectId(string)`, el comportamiento de `strictQuery` cambió, y la validación de ObjectId es más estricta. Se debe confirmar que la migración es completa.

## Decision drivers

- Mongoose 5 es EOL y no recibe parches de seguridad.
- Mongoose 9 tiene mejor performance (TypeScript nativo, mejor tipado, query caching).
- Los schemas legacy son compatibles en estructura pero requieren actualizar las APIs usadas.
- La BD MongoDB es la misma — no hay cambios en los documentos almacenados.

## Considered options

| # | Option | Description |
|---|--------|-------------|
| A | Mantener Mongoose 5 | Usar Mongoose 5 en nuxt para minimizar cambios |
| B | Upgrade a Mongoose 9 | Actualizar APIs y eliminar calls deprecadas |
| C | Upgrade gradual (Mongoose 7 → 9) | Migrar en pasos para reducir riesgo |

### Option A: Mantener Mongoose 5
- **Pro**: Sin cambios de API.
- **Con**: EOL. Sin soporte. Incompatible con Node 22.

### Option B: Upgrade a Mongoose 9
- **Pro**: Soporte activo. Tipos TypeScript nativos. Compatibilidad con Node 22.
- **Con**: Requiere migrar `execPopulate()`, `Types.ObjectId()` (sin `new`), y revisar `strictQuery`.

### Option C: Upgrade gradual
- **Pro**: Menor delta de cambio por paso.
- **Con**: Overhead de gestión. Nuxt ya arrancó con Mongoose 9.

## Decision outcome

**Chosen option**: B — Mongoose 9, implementado directamente en nuxt.

**Justification**: Nuxt ya usa Mongoose 9. No es viable retroceder. Los breaking changes están documentados y son manejables. Node 22 requiere Mongoose ≥ 7.

## Consequences

### Positive
- Soporte activo y parches de seguridad.
- TypeScript types nativos (sin `@types/mongoose`).
- Mejor performance en queries.

### Negative
- Todos los usos de `execPopulate()` deben reemplazarse por `await populate()`.
- `Types.ObjectId(string)` debe ser `new Types.ObjectId(string)`.

### Mitigations
- Grep para detectar APIs obsoletas: `grep -rn "execPopulate\|Types\.ObjectId(" server/`.
- Tests de paridad confirman que los documentos se crean y populan igual que en legacy.

## Confirmation

- `grep -rn "execPopulate" server/` → 0 matches.
- `grep -rn "Types\.ObjectId(" server/` → solo con `new` (verificar).
- `pnpm test:run` → todos los tests de modelos PASS.
- `cat package.json | grep mongoose` → versión ≥ 9.
