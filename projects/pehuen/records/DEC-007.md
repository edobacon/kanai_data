# State management: Harlem (legacy) → Pinia (nuxt)

## Context and problem statement

El legacy usa Harlem como library de state management en el cliente Vue 3. Harlem es una librería de nicho con menor adopción que Pinia. El nuxt usa Pinia, que es la solución oficial recomendada por Vue/Nuxt. Los stores de Harlem deben reescribirse como stores de Pinia. No hay compatibilidad de APIs entre ambas librerías.

## Decision drivers

- Pinia es el estándar oficial de Vue 3 y Nuxt 4. Soporte de primera clase.
- Harlem tiene documentación limitada y menor comunidad.
- Pinia tiene integración nativa con Nuxt (auto-importado, SSR hydration).
- DevTools de Vue incluyen soporte nativo para Pinia (timeline, time-travel debugging).

## Considered options

| # | Option | Description |
|---|--------|-------------|
| A | Mantener Harlem | Usar Harlem en nuxt para preservar los stores legacy |
| B | Migrar a Pinia | Reescribir todos los stores usando la API de Pinia |
| C | Sin store global | Usar solo composables y `useState` de Nuxt |

### Option A: Mantener Harlem
- **Pro**: Sin reescritura de stores.
- **Con**: Harlem no tiene integración nativa con Nuxt 4. SSR hydration problemática.

### Option B: Migrar a Pinia
- **Pro**: Integración oficial Nuxt. SSR hydration automática. DevTools nativo.
- **Pro**: API más simple que Harlem para composables complejos.
- **Con**: Reescritura de todos los stores legacy.

### Option C: Sin store global
- **Pro**: Más simple, solo composables.
- **Con**: Para estado global compartido (usuario actual, mantenedores cargados al login) los stores son más apropiados.

## Decision outcome

**Chosen option**: B — Pinia.

**Justification**: Pinia es el único viable para Nuxt 4 con SSR. Harlem no tiene soporte oficial para SSR hydration. La reescritura es inevitable y está ya implementada en nuxt.

## Consequences

### Positive
- State management con soporte oficial en Nuxt 4.
- SSR hydration automática.
- DevTools nativo.

### Negative
- Reescritura completa de stores legacy.

### Mitigations
- Convencion de naming: `use{Name}Store` para todos los stores Pinia.
- Tests de stores con Vitest + `createPinia()` test helper.

## Confirmation

- `grep -rn "harlem\|@harlem" package.json app/` → 0 matches.
- `grep -rn "defineStore\|useStore" app/stores/` → debe aparecer patrón Pinia.
- Test: store de auth retiene usuario al navegar entre páginas (SSR hydration).
